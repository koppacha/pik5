# 期間限定ランキング・トリックテイキング制 ルールブック

本ドキュメントは「期間限定ランキング・トリックテイキング制」に基づく大会ルールを定義する。
Codex（GPT）および実装者が仕様を誤解なく把握できることを目的とする。

---

## 1. 基本概念・用語定義

### 1.1 画面（UI）
- Phaserをフルスクリーンで表示するユーザーインターフェース
- 大会名、参加人数、プレイヤーの各情報（ダッシュボード）、カウントダウン、場札、手札（各プレイヤーの情報のみ確認可）、山札（枚数のみ確認可）、捨て札（枚数のみ確認可）、ログが表示される

### 1.2 大会
- 開催期間：**48時間**
- 参加・離脱：自由（途中参加・途中退室・再参加可）

### 1.3 カード
- 各カードは **1つのミニゲーム** を定義するデータ
- ID・専用ステージ番号（`stage_id`）・ステージ名・ルール名・ルール概要・レア度（1-5）・難易度（1-5）・作成者・テイク者・フラグが記録されている
- 同じ内容のカードであっても、カードごとに異なる専用の`stage_id`を付与する
- DBで管理される

### 1.4 ゲーム
- カード1枚ごとに対応するミニゲーム（＝期間限定チャレンジ）
- ミニゲーム自体は本プロジェクトで制作せず、各プレイヤーが共通で所有するオフラインゲームを使用する
- プレイヤーは場に出ている各期間限定チャレンジに対してゲーム内スコアを投稿できる
- スコア情報はDBで管理される

### 1.5 山札
- 未使用カードの集合
- 非公開情報（枚数のみ表示）

### 1.6 手札
- プレイヤーが所持するカード
- 所持者は確認できるが、他プレイヤーからは見えない
- 場に出す際に消費される

### 1.7 場札
- 各プレイヤーが手札から場に出したカード（すべてのプレイヤーが見れる）
- フィールド上に**16枚**まで出せる

### 1.8 捨て札
- 使用済みカード
- 非公開情報（枚数のみ表示）

### 1.9 ダッシュボード
- すべての参加者のユーザー名、ドローポイント、手札の数、合計ランクポイントを記載した一覧表
- 誰でも常時確認できる

### 1.10 ログ
- 各プレイヤーのドロー以外の行動（テイク、ゲームへのスコア投稿）と回収をアナウンスする表示領域

## 2. 大会参加と初期処理

### 2.1 参加時処理
- プレイヤーが大会に参加（参加ボタンを押下）すると：
    - 山札から **3枚ドロー**
    - これらは自動的に手札となる

### 2.2 ドロー処理
- 各プレイヤーはいつでもドローポイントを１点消費して山札から１枚カードをドローできる
- ドロー処理前に山札が枯渇している場合、捨て札をシャッフルして新たな山札を作成する（＝捨て札フラグをリセットする）

### 2.3 テイク
- 手札から１枚選び、場に出す（場札にする）ことをテイクという
- テイクするとそのユーザーの**他の手札はすべてスタック状態**になる（手札からは失われる）
- テイクされた場札はその瞬間から公開情報としてすべてのユーザーが確認できるようになる
- テイク条件（すべて満たされている必要がある）
    - 手札が **3枚以上**
    - 大会終了 **1時間前より前**
    - 場札の数が（参加者数＋５）未満
    - 場札の数が15枚以下

### 2.4 重ね枚数（スタック＝S）
- テイクしたとき、場に出したカードと捨てたカードの総枚数（テイクする前の手札の数）をスタックという
- スタック数は公開情報であり、場札の詳細情報欄に表示される（どのカードがスタックしているかどうかは表示されない）
- 例：手札3枚でテイク → S=3（場札１枚＋捨て札２枚）
- スタックされたカードは、紐づいている場札が捨て札になったときに同時に捨て札になる

### 2.5 大会の終了
- 大会時間が残り０になると、場札はすべて強制的に回収される
- 回収されたすべての場札は回収済みカード（ゲームを投稿できない）として場札に出る

## 4. ゲーム進行（各場札のライフサイクル）

### 4.1 カウントダウン
- １回目のスコア投稿完了時に **90分カウントダウン** 開始
- DB上は現在時刻の90分後をリミットオーバー時間として記録する
- テイクされた時点ではカウントダウンは開始しない。場札として公開され、最初の投稿を待つ状態になる

### 4.2 スコア投稿
- ゲーム参加者は場札をクリックするとミニゲームルールを確認でき、そのコンポーネントからスコアを投稿可能
- スコアの投稿ロジックおよびUIは`next/components/modal/RecordForm.js`を使用する
- 投稿が正常に処理されるたび：
    - カウントダウンを **15分延長**
      - 直近15分以内で５回目以降の投稿は延長処理を行わない。
      - 同一プレイヤーによる連続投稿は２回目以降のすべての投稿について延長処理を行わない。
      - 大会終了１時間前以降は常に延長処理を行わない
    - 投稿したスコアが最下位でなく前回投稿スコアよりも順位が高い場合、そのプレイヤーにm点のドローポイントを与える（各プレイヤーn回まで）
      - nの値はレア度に依存する。n = {C1:1, U2:2, R3:3, E4:4, L5:5}
      - mの値はS（スタック数）３点ごとに１点増加する。M = floor(S / 3)
      - 各場札の最初の投稿（１位であり最下位でもある）にはドローポイントは発生しない

### 4.3 ランクポイント
- 各ゲームの参加者のうち上位S人は（S - ゲームの順位 + 1）のランクポイント（R）を得る
- ゲームの参加者 < Sの場合、１位は（S - ゲームの参加者）のボーナスランクポイントを得る

### 4.4 回収
- カウントダウンが０になった場札は回収処理を実行し、大会終了まで非表示になる
- 大会自体のカウントダウンが０になった場合、場札のカウントダウンにかかわらず回収処理を実行する
- 回収された時点で上位S人は（d - ゲームの順位 + 1）の追加ドローポイントを得る（０以下の場合は発生しない）
  - dの値は難易度に依存する。{Lv1:1, Lv2:2, Lv3:3, Lv4:4, Lv5:5}

---


## 5. 大会終了後の表示

- 大会終了後は、大会中に回収処理が行われたすべてのカードを場札として表示する
- 手札・山札は表示しない
- 場札をクリックするとランキングを閲覧できるが、スコア投稿ボタンは非活性にする

## 6. デバッグモード

### 6.1 デバッグモード時の特殊処理
- デバッグモードが有効な場合、各カードに回収ボタンを設置し、即時回収できるようにする

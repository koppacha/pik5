# 期間限定ランキング・トリックテイキング制 ルール仕様書

> 第19回終了後（2026-10-11 20:00 JST以降）のルール変更・検討は、継続更新する[第20回大会案](tricks-tournament-20-plan.md)を参照。採用案と本番反映状況は区別して管理する。

本書は、大会参加、カード操作、スコア投稿、ドローポイント給付・還元、勝敗判定の現行ルールを定義する。
2026年10月7日時点の実装と指示履歴を照合して整理した。
画面構成・演出・API・DBの詳細は[システム設計書](tricks-system.md)、プレイヤーの行動仮定と比較実験は[シミュレーション仕様書](tricks-simulation.md)を参照する。

## 1. 大会の基本ルールと用語

### 1.1 開催と勝利条件

- 標準の開催期間は**48時間**。各大会の開始・終了時刻は大会データで定める。
- 既存大会 `251227` の終了時刻は**2026年10月11日20:00（JST）**とする。
- 開催中の大会へログイン済みユーザーが参加できる。一度参加すると退出できず、ログアウト・ページ離脱後も参加状態、成績、ドローポイントを保持する。
- 「累計参加者数」は、その大会に一度でも参加したユーザー数を指す。
- 大会終了時の**合計ランクポイント**が最大のプレイヤーを勝者とし、イベントランキングもその大きい順に並べる。
- ドローポイント残高や手札の保有量は勝敗に算入しない。
- カード経済は、期間限定チャレンジの成績を競う中で、ルール選択、練習、多数のゲームへの参加、トリック作成などの駆け引きを生む仕組みとする。

### 1.2 用語・記号

| 用語・記号 | 意味 |
|---|---|
| ドローポイント（P。画面のDPも同じリソース） | ドロー、手札返却、スコア投稿、任意延長に使う残高 |
| ランクポイント（R） | 期間限定チャレンジの順位から得る成績。合計値で大会の勝敗を決める |
| カード | 1つの期間限定チャレンジのルールを定義するデータ |
| クリエイター | カードのルールを考案・投稿した参加者 |
| テイク／テイカー | 手札から1枚を場へ出す操作／その操作をしたプレイヤー |
| トリック数 `S` | テイク直前の手札総数。切り札本体1枚と、それに紐づく残りのカードを含む |
| レア度ボーナス `B` | 選択したカードのレア度とトリック数から決まる還元原資 |
| 成功テイク総数 `T`／レベル `L` | 大会ごと・プレイヤーごとのテイク成功回数／`L = floor(sqrt(T))` |
| 投稿者数 `N`／順位 `r` | 対象切り札に現在有効な記録を持つプレイヤー数／標準競技順位 |
| 支払ドローポイント総数 `C` | 対象切り札への投稿費・任意延長費の実支払い総額 |
| ポット | 定期徴収と手札返却費を大会単位で一時保管する残高 |
| 総還元ドローポイント `Q` | 回収時に投稿者へ分配するドローポイントの総額 |
| ホルダー | 回収時に1位の記録を持ち、カードの所有権を得たプレイヤー |

### 1.3 カードと期間限定チャレンジ

- 期間限定チャレンジは各プレイヤーが共通で所有するオフラインゲームで行い、切り札のルールに従ってスコアを投稿する。
- カード本体にはカード固有ID（`card_id`）、元ステージ番号（`origin_stage_id`）、投稿用ステージ番号（`stage_id`）、ステージ名、ルール名・本文、クリエイターなどを保持する。
- 大会内の難易度（1〜5）、レア度（1〜5）、テイカー、カード状態、開封・返却履歴は大会ごとのカード情報として管理する。レア度はカード本体とは独立してドロー時に確定する。
- 投稿用 `stage_id` が未設定の場合、最初のテイク時に**1001〜1999の未使用番号の最小値**を付与し、イベント用ステージ情報を登録する。
- 付与済みの `stage_id` は回収・大会終了後もカード固有の投稿先として保持し、次回以降のテイクでも同じ番号を使用する。
- 投稿先の番号を再利用しても、スコア、参加順、支払い、ランクポイント、還元結果は大会ごとに分離して集計する。

### 1.4 カードの状態と公開範囲

| 状態 | 内容 | 公開範囲 |
|---|---|---|
| デッキ | ドロー可能なカード | 枚数と難易度1〜5の枚数内訳 |
| 手札 | プレイヤーが所持するカード | 内容は本人のみ。他者には所持枚数を公開 |
| 切り札 | テイクされ、投稿対象になっているカード | 内容、テイカー、トリック数、期限、ランキングなどを公開 |
| トリック | 切り札に紐づいた残りの手札 | 合計枚数を公開。個々のカード内容は非公開 |
| 捨て札 | 切り札回収に伴いトリックから移された再利用可能なカード | 枚数のみ |
| 回収カード | 回収処理を完了した切り札本体 | ホルダーの有無にかかわらず結果一覧で公開 |

- 回収カードは、ホルダーの有無にかかわらず**その大会中はカード循環へ戻らない**。
- 捨て札はデッキ補充に使うため、同じ大会中に再登場することがある。
- ホルダーがいるカードはそのプレイヤーの所有物となる。大会間の扱いは5.2に従う。

## 2. 参加・手札操作・テイク

### 2.1 大会参加

- 初めて参加すると**5P**を得て、手札0枚から開始する。
- 新規参加者が増えるたび、既存参加者全員へ**1P**を付与する。新規参加者本人はこの加算の対象外とする。
- 同じユーザーの参加処理を再送しても、初期5P・既存参加者への1Pを重複して付与しない。

### 2.2 ドロー

- 大会開始時のデッキは**160枚**。大会間の投入対象は5.2に従う。
- 開催中、**1P**を消費してデッキから1枚を引ける。実行には残高1P以上が必要。
- デッキ内の各カードは同じ確率で選ばれる。
- 大会261009の枯渇対策では、開催中に元160枚をCSV順に複製し、公開カードID `261009-161`〜`261009-320` の未開封カードとして追加する。元カードの手札・切り札・捨て札・回収・成績は維持する。複製は別の投稿先・期限・ランキングを持つ。
- 手札上限は**`(L + 2) × 3`枚**。現在の手札が上限以上の場合はドローできない。
- レア度未確定のカードは、ドロー時の大会残り時間に応じて次の確率でレア度を決める。

| レア度 | 終了3時間前より前 | 終了3時間前以降 |
|---|---:|---:|
| 1（C1） | 87% | 0% |
| 2（U2） | 8% | 87% |
| 3（R3） | 4% | 8% |
| 4（E4） | 0.9% | 4% |
| 5（L5） | 0.1% | 1% |

#### 2.2.1 デッキの補充と開封履歴

- 最後のデッキをドローすると、**同じトランザクション内ですべての捨て札をデッキへ戻す**。次のドロー前に補充を完了する。
- 処理開始時点でデッキが空の場合も、捨て札を補充してからドローする。デッキ・捨て札ともに空ならドローできない。
- 捨て札から補充したカードのレア度は未確定へ戻し、次のドローで再抽選する。
- 捨て札へ移る時点で開封回数とレア度をリセットする。再抽選した本人のドローは初回（開封済みなし）となり、レア度を保持した手札返却後の再ドローのみ「開封済み」を表示する。

#### 2.2.2 手札のデッキへの返却

- 手札から1枚を選び、**1P**を消費してデッキへ戻せる。実行には残高1P以上が必要。
- 戻したカードは他のデッキカードと同じ確率で再ドローされる。カード固有ID、元・投稿用ステージ番号、難易度、レア度、開封履歴を保持する。
- 返却後に別のカードを引くには、ドロー費を別途1P支払うため、返却とドローの合計は**2P**となる。
- 返却費はポットへ加算する。
- 再ドロー時には「過去に手札から返却されたカード」であることを示す履歴アイコンを表示する。
- 返却操作は非公開の監査履歴へ記録する。

### 2.3 テイク

- 手札から選んだ1枚を切り札とし、**残りの手札をすべてその切り札のトリックへ移す**。成功後の手札は0枚となる。
- テイクは、選んだ期間限定チャレンジで他の参加者へ競争を提案する操作であり、切り札の内容は全員に公開される。
- テイク条件は次のすべてを満たすこととする。

| 条件 | 必要な状態 |
|---|---|
| 手札 | **`L + 2`枚以上** |
| 大会時間 | **大会終了1時間前より前** |
| 切り札数 | テイク後に**`min(max(1, 累計参加者数 - 1), 16)`枚以下** |
| クールダウン | 初回テイク、直前の成功から**60分以上**経過、または**終了150分前以降** |

- 成功時に `T` を1増やし、次回のレベル・必要手札枚数・手札上限を更新する。
- クールダウンは成功時刻から60分で固定し、切り札の順位、投稿、延長、回収時刻に左右されない。
- 終了150分前以降は進行中のクールダウンも免除する。終了1時間前以降はテイク禁止となる。
- テイク時の即時給付は3.2に従い、消費前の手札枚数で資格を判定する。

### 2.4 トリックとレア度ボーナス

- 物理的なトリック数 `S` はテイク前の手札枚数。例：手札3枚なら切り札1枚＋トリック2枚で `S = 3`。
- 選択カードのレア度に応じて、`g = floor(S / 3)` として次の `B` を還元原資へ加える。

| レア度 | ボーナス `B` |
|---|---|
| 1 | `0` |
| 2 | `g + 1` |
| 3 | `g + 4` |
| 4 | `2g + 7` |
| 5 | `3g + 15` |

- テイク前の「トリック数」表示は**`S + B`**とし、レア度ボーナス `B` を併記する。レア度2以上のテイク確認にもボーナス値を表示する。
- 切り札の物理トリック数は `S` のままとする。紐づくトリックカードは切り札回収時に捨て札へ移る。

### 2.5 手札の練習

- 手札の期間限定チャレンジは、テイクまで回数・期間の制限なくオフラインで練習できる。
- 練習時間・回数をWebシステムへ記録する専用操作は設けない。練習自体には費用、期限変更、給付を伴わない。
- 練習成果は、テイク後のスコア投稿に利用できる。

## 3. ドローポイント給付・徴収・ポット

### 3.1 継続給付

- 日本時間（Asia/Tokyo）の**毎時00分と30分**に、**手札枚数＋所持ドローポイントが3未満**の参加者へ**1P**を付与する。
- 切り札枚数・参加者数・直前の行動にかかわらず、処理時点の合計で判定し、負の残高も計算へ含める。
- 給付後も合計が3未満なら次回も対象となる。
- 同じ給付スロットでは二重配布しない。スロット時刻より後に参加したプレイヤーは、次のスロットから対象となる。

### 3.2 テイク・無料初投稿時の即時給付

- **行動直前の手札枚数＋所持ドローポイントが5未満**で、テイクまたは無料初投稿が成功した場合、同じトランザクション内で**1P**を付与する。
- テイクでは、切り札・トリックへ移す前の手札を含めて判定する。
- 無料初投稿は、非テイカーによる各切り札への最初の有効な投稿を指す。各プレイヤー・各切り札につき1回限りとする。
- 投稿の再送、更新、削除後の再投稿、練習、有料投稿は即時給付の対象外とする。

### 3.3 表示用の給付フラグ

- 開催中かつ**現在の手札枚数＋所持ドローポイントが3未満**の場合に有効とする。
- 行動、即時給付、還元、継続給付後の現在値で再判定する。合計が3以上ならフラグを外す。

### 3.4 空場時の緊急補充

- 切り札が0枚で、参加済みの**全プレイヤーがそれぞれ所持ドローポイント＋手札枚数3未満**の場合、各プレイヤーへ合計が3になる不足分を即時配布する。
- 状態変更と同じトランザクション内で条件を再確認し、同一状態への二重配布を防ぐ。
- 監査履歴にはプレイヤー別配布量と合計を保存し、公開ログには合計配布量を表示する。

### 3.5 高残高プレイヤーからの定期徴収

- 毎時00分・30分の給付処理後、残高が**`(L + 2) × 5`Pを超える**各プレイヤーから**1P**を徴収する。
- 閾値と同額なら徴収しない。条件を満たし続ける間、スロットごとに徴収する。
- 表示上の「税金徴収ボーダー」は、最小対象残高である**`(L + 2) × 5 + 1`DP以上**。例：Lv.0は11DP以上。

### 3.6 ポットの蓄積と使用

- 定期徴収と手札返却費を大会単位のポットへ加算する。
- 有効な投稿者がいる切り札を次に回収するとき、ポット全額をその切り札の総還元ドローポイントへ移し、4.4の配分で還元してポットを0にする。
- 投稿者0人の切り札回収ではポットを保持し、次の還元可能な回収へ持ち越す。

## 4. 切り札の進行・投稿・成績・回収

### 4.1 初期カウントダウン

- テイク時刻から次の時間を加えた時刻を、切り札の初期期限とする。

| 難易度 | 初期時間 |
|---|---:|
| 1・2 | 60分 |
| 3 | 80分 |
| 4 | 100分 |
| 5 | 120分 |

- 初投稿がない切り札も、期限到達時に回収する。

### 4.2 スコア投稿

- 大会参加者は切り札の詳細からルールを確認してスコアを投稿する。投稿はその期間限定チャレンジへの参加とルールへの支持の意思表示とする。
- 受け付ける大会記録はルール番号 `1`、スコア**1〜999999の整数**。対象大会の切り札へ紐づける。
- 同じステージでまったく同じルールのカードが複数テイクされた場合、１回のプレイで出した記録はどれか１枚にしか投稿できない。同じ記録・動画を複数カードへ使い回してはならない。別プレイで出した記録は、同スコアでも別々に投稿できる。
- 投稿費は次のとおりとする。

| 投稿 | 費用 |
|---|---:|
| 非テイカーの初投稿 | **無料** |
| テイカーの初投稿 | **難易度と同じP** |
| 同じプレイヤーの2回目以降 | **難易度と同じP** |

- 投稿費だけは残高不足でも支払える。残高は負数になり得て、給付条件にもその値を使用する。
- 初投稿の判定単位は**プレイヤー×切り札**。参加順は各プレイヤーの最初の有効な投稿が完了した順とする。
- 記録を削除して有効記録が0件になっても、初投稿履歴、参加順、支払い履歴、発生済みの初投稿延長を保持する。再投稿は有料の2回目以降として扱う。
- 同一保存処理の再送で投稿費、初投稿延長、即時給付を重複して適用しない。
- 回収済みのカードと大会開催時間外への投稿・更新は受け付けない。

#### 4.2.1 初投稿による自動延長

| 初投稿の参加順 | 延長時間 |
|---|---:|
| 1人目・投稿直前の残り時間15分未満 | **30分** |
| 1人目・残り時間15分以上 | **15分** |
| 2人目以降 | **10分** |

- 投稿費の有無にかかわらず、各プレイヤーの初投稿時に適用する。スコア更新では延長しない。
- この延長で期限が大会終了時刻を超えても保持するが、大会終了時には全切り札を回収する。

#### 4.2.2 プレイヤーによる任意延長

- ログイン済み大会参加者は、テイカー・投稿者であるかを問わず、**1P**を支払って期限を**15分**延長できる。
- 条件は、残高1P以上、終了1時間前より前、未回収かつ切り札期限前、現在の期限が大会終了時刻より前とする。
- 延長後の期限は大会終了時刻を上限とする。残りの延長可能時間が15分未満でも費用は1P。
- 延長費は当該切り札の `C` へ加算する。
- ドローポイント減算、期限更新、支払い履歴、ログは同じトランザクションで反映し、失敗時は全体をロールバックする。
- 同じリクエストの再送で二重延長しない。改めて確認した別操作は、条件を満たす間、回数制限なく実行できる。

### 4.3 順位とランクポイント

- 各プレイヤーの有効な最良スコア1件で順位を決める。スコアの大小の優劣は対象ステージの順位設定に従う。
- `N` は現在有効な記録を持つプレイヤー数とする。同スコアは同順位で、標準競技順位を使用する。例：3人中2人が同率1位なら1位・1位・3位。
- ランクポイントは**`N - r + 1`R**。さらに**1位へ1R**を加える。
- 例：1人なら1位2R、3人で同点がなければ1位4R・2位2R・3位1R。
- 切り札の暫定ランクポイントは、有効記録の投稿・更新・削除に応じて現在の `N` と順位から再計算する。
- ダッシュボードの合計は、**回収済みカードの確定分＋切り札の暫定分**。回収時には最終順位分を確定し、暫定集計から外して二重加算を防ぐ。

### 4.4 回収とドローポイント還元

- 切り札期限到達、大会終了、即時回収、管理者操作時に、同じ回収・還元処理を行う。
- 切り札本体を回収済みにし、紐づくトリックカードを捨て札へ移す。
- 有効な投稿者がいれば最終順位でランクポイントと還元を確定し、1位のプレイヤーをホルダーとする。
- 同率1位では、**1位となる記録の投稿IDが最小のプレイヤー1人**をホルダーとする。記録の日時欄は先着判定に使わない。
- 投稿者0人の場合は、ホルダー、ドローポイント還元、ランクポイントを作成しない。
- 回収時のランキングと還元結果を保存し、後の記録削除でも確定結果を変更しない。
- 回収処理は冪等とし、再実行でドローポイント、ランクポイント、ホルダー、ログを二重反映しない。

#### 4.4.1 総還元ドローポイント

- `C` は実際に支払われた投稿費・任意延長費の総額とし、記録削除後も保持する。
- 今回の回収へ移すポットを `P` としたとき、投稿者1人以上なら**`Q = S + B + C + P`**、投稿者0人なら**`Q = 0`**とする。
- 原資を全額配分する。投稿者1人の場合はそのプレイヤーへ `Q` 全額を還元し、2人以上は以下の順位配分を行う。

#### 4.4.2 基底配分

同点がないと仮定した順位枠へ、基準額 `Q = N + 3` において次のドローポイントを配分する。

| 投稿者数 `N` | 1位から順の配分 |
|---|---|
| 2 | `(3, 2)` |
| 3 | `(4, 2, 0)` |
| 4 | `(4, 2, 1, 0)` |
| 5以上 | `(3, 2, 2, 1, ..., 1, 0)`。1Pの枠は `N - 4`個 |

- 実際の `Q` が `N + 3` 未満なら、最下位に近い正の成分から1Pずつ減らし、毎回下位から探し直して合計を `Q` へ合わせる。
- 3人以上では最下位の順位枠は0P。2人では最下位も減額対象に含める。

#### 4.4.3 超過ドローポイントの循環配分

- `Q > N + 3` の差分を1Pずつ配分する。
- 2位から最下位の1つ上までを上位から走査し、直上とのドローポイント差が「必要差」を超える最初の順位へ1Pを加える。
- 必要差は1位と2位の間が2P、その他は1P。ただし5人以上の基底配分で同額の隣接枠は必要差0Pとする。
- 加算対象がなければ1位へ1Pを加える。1P配るたび同じ走査を繰り返す。
- 4人の例：`(4,2,1,0) → (5,2,1,0) → (5,3,1,0) → (5,3,2,0) → (6,3,2,0) → (6,4,2,0) → (6,4,3,0)`。

#### 4.4.4 同順位と整数端数

- まず厳密順位の各枠への配分を計算し、同順位者が占める枠のドローポイントを合算して人数で均等配分する。
- 均等配分で整数にできない余剰は合算し、順位配分とは別枠でテイカーへ全額還元する（テイカーが未投稿でも対象）。
- 端数は各同順位グループで割り切れなかった分だけであり、厳密順位配分は総額を全て割り当てる。4人以下では最大3P。同点人数が多ければ3Pを超えることがあるが、同順位の均等配分を維持し、余り全額をテイカーへ渡す。
- この余剰還元は「同順位なら同じ順位配分」の判定に含めない。

## 5. 大会終了と次回大会へのカード投入

### 5.1 大会終了処理

- 大会終了時刻に残っている切り札はすべて強制回収し、4.4に従って最終成績・還元・ホルダーを確定する。
- 大会終了後はカード操作・投稿を終了し、その大会のデッキ・手札・捨て札を進行に使用しない。
- ドローポイント残高・未使用手札をランクポイントへ変換しない。

### 5.2 次回大会のデッキ

- ホルダーを得たカードは所有物として保存し、以後の大会のデッキ候補から除外する。
- ホルダーを得なかったカードは大会終了時に投入可能状態へ戻す。
- 新大会の初期化では、**直前大会のホルダーなし回収カードをすべて優先して含め**、残りを他の投入可能カードから補って160枚を選ぶ。
- 投入可能カードが160枚未満、または必須の再投入カードが160枚を超える場合は初期化を成立させない。
- 再投入するカードは新大会のデッキとして開始し、大会内のレア度・開封回数・参加状態・成績は新たに管理する。カード本体の投稿用 `stage_id` は1.3に従って保持する。

## 6. 公開表示と観戦

### 6.1 プレイヤー情報・切り札・ログ

- ダッシュボードは全参加者のユーザー名、ドローポイント、手札枚数、レベル・テイクコスト、合計ランクポイントを公開する。
- 切り札のカード右下に表示する「総還元P」は、基本額は**`S + B + C`**。有効投稿者がいる切り札のうち期限が最も早いカードへポットを加算する。延長等で順序が変われば対象を再計算する。投稿者0人の原資は回収時に消滅し、ポットへ移らない。
- テイカーが未投稿の場合の端数見込みはランキング内へ別枠表示する。順位配分とテイカー別枠の合計は、投稿者がいるカードの総還元Pと一致する。
- ランキングの各記録には**`[暫定R / 暫定P]`**を表示する。右側は現在の順位で回収された場合の還元見込み。
- 暫定Pには、投稿者がいる切り札のうち**期限が最も早い1枚**へ現在のポットを加える。同一期限なら大会内カードIDが小さいものを対象とする。回収前の投稿・延長・徴収・他札回収により見込みは変わり得る。
- 公開ログには参加、テイク、投稿・更新、任意延長、継続・即時給付、緊急補充、回収を表示し、日時を日本時間の `m/d hh:mm` で示す。
- ドロー、手札返却、定期徴収の個別履歴は公開ログに表示しない。公開取得対象は最新100件を基本とし、継続給付は同じスロットをまとめて表示する。

### 6.2 回収結果とコレクション

- 大会終了後は、回収カードをすべて結果一覧に表示する。総還元Pの降順、同額ならステージIDの昇順に並べ、ポットを含む実際の総還元Pを表示する。無料・投稿済みマークと投稿操作は表示しない。
- 手札・デッキ・捨て札は表示しない。
- カードにはクリエイター、テイカー、ホルダー、トリック数、アクティブ時間を表示する。
- 詳細では、その大会の確定ランキング、実際の総還元ドローポイント、テイクから回収までのアクティブ時間（`h:mm`）を閲覧できる。
- 各プレイヤーの取得カードはコレクタールームでも閲覧できる。回収カードは閲覧対象とし、投稿操作を表示しない。

### 6.3 観戦モード

- 未ログイン・未参加のユーザーも公開情報を観戦できる。参加者も通常表示と観戦表示を切り替えられる。
- 観戦中は手札・デッキ・ゲーム操作コマンドを隠し、切り札、ランキング、プレイヤー情報、公開ログを表示する。
- 投稿・延長・即時回収・デバッグ変更を無効にする。観戦画面から参加操作を行う場合は通常参加へ移行する。
- 観戦は表示モードであり、参加済みプレイヤーの参加状態やサーバー上の成績・給付資格は維持する。
- 投稿の順次表示・点滅時間などの演出詳細はシステム設計書に従う。

## 7. 管理・テスト用操作

- デバッグモードでは即時回収を行える。還元、ランクポイント、ホルダー、ログは通常回収と同じ処理とする。
- 即時回収とデバッグ時刻変更は、管理者または許可されたテスト用署名を持つ要求に限る。
- デバッグ・テスト用大会では時刻停止、指定時刻への変更、任意時間の経過、実時刻への復帰を行える。通常大会は実時刻で進行する。

## 管理者裁定によるルール変更・ランキングリセット

- 開催中の切り札のランキングフッターに管理者だけ「ルール変更」「リセット」を表示する。ルール変更ではステージ名、ルール名、本文、難易度を編集できる。大会状態や支払い額などは編集しない。
- リセットは「ランキングをリセットしますか？」の確認後に実行する。有効記録（flg < 2）すべてをflg = 2にし、records.post_memoへ「管理者権限による削除（YYYY-MM-DD HH:mm:ss）」を日本時間で追記する。
- 支払い履歴、初投稿履歴、発生済みポイント、支払い総額、トリックを保持する。次の投稿は2回目以降の有料投稿となる。
- リセット直前の有効記録の投稿者を参加者として、各人へ5DPを即時配布する。既に削除済みの記録だけを持つ人や未投稿者は対象外。同じ要求の再送は二重配布しない。
- 対象者のranking_reset_tax_exemptを有効にする。次に処理する給付・徴収スロットの徴収を免除し、残高が徴収対象以下でもそのスロットで消費する。複数のリセットによる未消費免除は累積しない。
- 回収済みカードと終了大会では操作不可。ルール変更、リセット、補償はイベントログで参加者へ共有する。

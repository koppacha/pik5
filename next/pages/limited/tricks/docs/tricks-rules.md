# 期間限定ランキング・トリックテイキング制 ルールブック

本ドキュメントは「期間限定ランキング・トリックテイキング制」に基づく大会ルールを定義する。
Codex（GPT）および実装者が仕様を誤解なく把握できることを目的とする。

---

## 1. 基本概念・用語定義

### 1.1 画面（UI）
- Phaserをフルスクリーンで表示するユーザーインターフェース
- 大会名、参加人数、プレイヤーの各情報（ダッシュボード）、カウントダウン、場札、手札、山札枚数、捨て札枚数、ログが表示される
- 手札は各プレイヤー本人のみ確認できる
- 山札と捨て札は枚数のみ確認できる

### 1.2 大会
- 開催期間：**48時間**
- 既存イベントID `251227` は例外として開催期間を延長し、終了を **2026年10月11日20:00（JST）** とする
- 勝利条件は、大会終了時に合計ランクポイントがもっとも大きいことである
- イベントランキングは合計ランクポイントの大きい順に並べる
- ポイントや手札の保有量は勝敗を決めず、大会終了時に残っていても本人の利益にはならない
- 本質的な競争対象はミニゲームの成績であり、カード経済は勝敗以外の遊び方や参加者同士の駆け引きを生むための仕組みとする
- ミニゲームの腕前には参加者間の格差があり、上位を取りにくい参加者にも、多数のゲームへの参加、練習、巨大スタック作成など別角度の楽しみ方を認める
- 参加者は一度参加すると大会から退出できない
- ログアウトやページ離脱をしても参加状態・成績・ポイントは保持される
- 参加者数は、その大会に一度でも参加した累計参加者数を指す

### 1.3 ポイント（P）
- プレイヤーがドロー、手札の山札への返却、スコア投稿、または場札の任意延長時に消費するリソース
- プレイヤーのポイントはマイナス値を保持しうる。投稿費だけは残高不足でも支払え、任意延長、ドロー、手札返却には必要残高を要求する
- ただし、ポイントが0P以下の場合はドローできない

### 1.4 カード
- 各カードは **1つのミニゲーム** を定義するデータ
- カード本体は参加者が考案・投稿したルールであり、レア度はドロー時に付与されるカード本体とは独立した情報である
- ミニゲームのルールを考案・投稿した参加者を**クリエイター**という
- ルール作成者にとって、カードがドローされテイクされることは「自分のルールが採用された」ことを意味する
- カード固有ID（`card_id`）・元ステージ番号（`origin_stage_id`）・投稿用ステージ番号（`stage_id`）・ステージ名・ルール名・ルール概要・レア度（1-5）・難易度（1-5）・作成者・テイカー・フラグが記録されている
- 投稿用`stage_id`はテイク時に初めて付与され、1001以上2000未満の未使用番号のうち最小値を使用し、同時に`stages`へイベント用ステージ情報を登録する
- 一度付与された`stage_id`はカード固有の投稿先として永続的に保持し、回収、イベント終了、次回イベントへの再投入時にも破棄・再発行しない
- 同一カードが次回以降のイベントで再びテイクされた場合は、既存の`stage_id`を使い回す
- DBで管理される

### 1.5 ゲーム
- カード1枚ごとに対応するミニゲーム（＝期間限定チャレンジ）
- ミニゲーム自体は本プロジェクトで制作せず、各プレイヤーが共通で所有するオフラインゲームを使用する
- プレイヤーは場に出ている各期間限定チャレンジに対してゲーム内スコアを投稿できる
- スコア情報はDBで管理される
- 1回のスコア投稿に必要なプレイ時間は、ミニゲームの難易度とプレイヤーの意欲を含め、原則 **10〜60分** を想定する
- 同じゲームを繰り返し更新する場合は更新回数に応じて次の更新へ必要な時間が増え、腕前が上の参加者を上回ろうとする場合も同格同士より多くの時間を要する想定とする

### 1.6 山札
- 未使用カードの集合
- 非公開情報（枚数のみ表示）

### 1.7 手札
- プレイヤーが所持するカード
- 所持者は確認できるが、他プレイヤーからは見えない
- 場に出す際に消費される
- プレイヤーは手札のミニゲームを、テイクするまで回数・期間の制限なく**練習**できる
- 練習はスコア投稿ではなく、ポイント消費、場札のカウントダウン開始・延長、給付金フラグの有効化を発生させない
- 練習成果は、そのカードをテイクした後のスコア投稿で上位を狙うために利用できる
- 練習はカード内容を確認してオフラインで行う概念であり、専用ボタン、練習時間、練習回数をWebシステムへ記録しない

### 1.8 場札
- 各プレイヤーが手札から場に出したカード
- すべてのプレイヤーが確認できる
- 場札として出せる枚数は2.3の動的上限に従い、絶対上限は**16枚**とする

### 1.9 ホルダー
- 回収時にその場札のランキングで1位となり、カードの回収権を得たプレイヤー
- 参加者数の多いカードほど、参加者から多くの支持を得たカードとしてホールドする価値が高いものと位置づける
- 同率1位が複数人いる場合は、1位となる記録を最初に登録したプレイヤーだけをホルダーとする
- ホルダーが存在する回収カードはホルダーの所有物となり、以後のイベントの山札には含めない

### 1.10 回収カード
- 場札の制限時間到達、大会終了、即時回収、管理者権限発動によって回収されたカード
- 回収後はそのイベントの山札・手札・場札・捨て札へ戻らず、そのイベント中は二度と登場しない
- 投稿者が1人以上いる回収カードにはホルダーが存在する
- 投稿者が0人の場札本体は回収済みとしてそのイベントの循環から除外する。スタックだけを捨て札へ移す
- ホルダーの有無にかかわらず、付与済みの`stage_id`は保持する

### 1.11 捨て札
- テイク時に場札へ選ばれなかったスタックカードなど、そのイベント内で再利用可能な使用済みカード
- 非公開情報（枚数のみ表示）
- 山札が枯渇した場合はシャッフルして山札へ戻るため、同じイベント中に再登場する可能性がある
- 回収カードとは異なり、イベント内のカード循環から除外されない

### 1.12 ダッシュボード
- すべての参加者のユーザー名、ポイント、手札の数、合計ランクポイントを記載した一覧表
- 誰でも常時確認できる

### 1.13 ログ
- 各プレイヤーのドロー以外の行動（テイク、ゲームへのスコア投稿）と回収をアナウンスする表示領域

## 2. 大会参加と初期処理

### 2.1 参加時処理
- プレイヤーが大会に参加（参加ボタンを押下）すると、ポイントを **5P** 得る
- 参加時の自動ドローは行わない
- 新規参加者本人には、後発参加ボーナスは付与しない
- 既存参加者は、自分より後に新規参加者が増えるたびに **1P** 得る
- 同一ユーザーが複数回参加処理を行っても、参加時5Pや後発参加ボーナスは重複して発生しない

### 2.2 ドロー処理
- 大会開始時の山札は **160枚** とする
- 各プレイヤーはいつでもポイントを **1P** 消費して山札から1枚カードをドローできる
- ポイントが0P以下の場合はドローできない
- 成功テイク総数を`T`、プレイヤーレベルを`L = floor(sqrt(T))`とし、手札上限を`(L + 2) × 3`枚とする。現在の手札が上限以上ならドローできない
- ドローによって山札が0枚になった場合、そのドローと同じトランザクション内ですべての捨て札を山札へ戻し、新たな山札を作成する（＝捨て札フラグをリセットする）
- 山札が0枚の間はドローを受け付けず、補充後のstateで山札が1枚以上になり次第ドローを再度受け付ける
- 既存データなどでドロー処理前から山札が枯渇している場合も、同じロック下で捨て札を山札へ戻してからドローする
- 回収カードは、山札が枯渇してもそのイベントの山札へ戻さない
- レア度未確定のカードを引くたびに、レア度1〜5を順に **87%、8%、4%、0.9%、0.1%** で抽選する（レア度2以上の合計は常に13%）
- 大会終了3時間前以降、レア度未確定のカードに対する排出率を **0%、87%、8%、4%、1%** に切り替える。C1は排出せず、L5は通常時の10倍とする
- 終了3時間前より前は、経過時間による排出率補正を行わない
- レア度は各カードの最初のドロー時に確定し、山札への返却や捨て札再利用後も再抽選しない

### 2.2.1 手札の山札への返却
- 手札から1枚を選び、**1P**を消費して山札へ戻せる
- 実行時に1P以上を所持している必要がある。0P以下では返却ボタンを表示するが非活性にする
- 戻したカードは山札内へランダムに混ぜ、通常の山札カードと同じ確率で再度ドローされる
- 返却後の自動ドローは行わない。別のカードをドローする場合は通常どおり1Pを消費するため、引き直しには合計2Pを要する
- 返却コストはPotへ移し、次に投稿者がいる場札が回収されたときの総還元ポイントへ加算する
- カード固有ID、元ステージ番号、投稿用ステージ番号、難易度、レア度は返却前の値を保持する
- 返却コスト支払い後の所持ポイントが4P以下なら、次回給付金タイミングに対する給付金フラグを有効にする
- 返却操作は公開ログへ表示しない。ただし運用監査用の非公開履歴には記録する
- 一度返却されたカードが再び誰かにドローされた場合、手札に「過去に誰かの手札から返却されたカード」であることを示す履歴アイコンを表示する

### 2.3 テイク
- 手札から1枚選び、場に出す（場札にする）ことをテイクという
- テイクしたプレイヤーをテイカーという
- テイクすると、そのユーザーの**他の手札はすべてスタック状態**になる（手札からは失われる）
- テイクされた場札は、その瞬間から公開情報としてすべてのユーザーが確認できるようになる
- テイクは、テイカーがカード内容を選別し、他の参加者へ「このミニゲームで競い合おう」と提案する意思表示として位置づける
- テイク条件（すべて満たされている必要がある）
    - そのプレイヤーの成功テイク総数を`T`、レベルを`L = floor(sqrt(T))`としたとき、手札が **L + 2** 枚以上
    - 大会終了 **1時間前より前**
    - テイク後の場札数が **min(max(1, 累計参加者数 - 1), 16)** 枚以下
    - 初回テイク、直前のテイク成功から **60分以上** 経過、大会終了150分前以降のいずれかを満たす
- テイクが成功した瞬間から、そのプレイヤーには60分のクールダウンを設定する。大会終了150分前以降は進行中のクールダウンも免除する。ただし大会終了1時間前以降のテイク禁止は維持する
- すべての場札で1位になってもクールダウンは解除しない
- 場札の投稿数、制限時間の延長、回収時刻によってクールダウンを短縮・延長しない
- 自分がテイクした場札が60分より早く回収された場合もクールダウンは継続する。場札が延長されて60分を超えて残っている場合もクールダウン終了後は次のテイクを行える
- 大会終了1時間前以降はテイクできないため、参加者はそれより前に必要手札枚数を満たしている場合、可能な範囲で締切直前までにテイクすることが合理的な行動となる
- 成功テイク総数はプレイヤーごと・大会ごとに保持し、テイク成功と同一トランザクションで1加算する
- レベルと次回テイクコストは公開情報とし、各プレイヤー欄に`Lv.{L} / テイクコスト {L + 2}`形式で表示する

### 2.4 重ね枚数（スタック＝S）
- テイクしたとき、場に出したカード1枚と、それに紐づくスタックカードの総枚数（テイクする前の手札の数）をスタックという
- スタック数は公開情報であり、場札の詳細情報欄に表示される（どのカードがスタックしているかどうかは表示されない）
- 例：手札3枚でテイク → S=3（場札1枚＋スタック2枚）
- 選んだカードのレア度に応じて還元原資へスタックボーナス`B`を加える。`g = floor(S / 3)`とし、レア度1は`B=0`、レア度2は`B=g+1`、レア度3は`B=g+4`、レア度4は`B=2g+7`、レア度5は`B=3g+15`とする。物理的なスタック枚数`S`は変わらない
- レア度2以上のカードを選んでテイクするときは、確認ポップアップにボーナス値を表示する
- テイク前に選択カードの横へ表示する「スタック数」は、手札枚数`S`にそのカードのレア度ボーナス`B`を加えた`S+B`とする。その直下へ`（レア度ボーナス B）`を表示する。場札の物理スタック枚数は引き続き`S`とする
- スタックされたカードは、紐づいている場札が回収されたときに捨て札となる。場札本体は投稿者0人の場合も回収済みとしてイベント内の循環から除外する

### 2.5 大会の終了
- 大会時間が残り0になると、場札はすべて強制的に回収される
- 大会終了後は、ホルダーを持つその大会の回収カードだけを投稿不能な回収カード一覧として表示する。投稿者0人の場札本体も回収済みだが、一覧には表示しない
- 大会終了時点の山札・手札・捨て札はその大会の進行には使用しない

## 3. ポイント給付

### 3.1 給付金タイミング
- 日本時間（Asia/Tokyo）の毎時00分と30分を給付金タイミングとする
- 給付金タイミングでは、給付金フラグが有効になっているすべてのプレイヤーに **1P** を即時付与する

### 3.2 給付金フラグ
- 以下のいずれかの条件を満たすとき、給付金フラグが有効になり次の給付金タイミングでポイントが付与される。
- 条件を満たし続けるかぎり、給付金タイミングが来るたびにポイントは付与される。
- 給付後も場札0枚かつ手札枚数 + 所持ポイント < 8なら、次回の継続給付対象とする
- 給付金タイミングちょうどの行動によって立ったフラグは、その次の給付金タイミングで消費する
  - 例：09:00の給付は、08:30〜08:59の行動によって立ったフラグに基づいて行う
  - 09:00ちょうどの行動によって立ったフラグは、09:30の給付対象になる

#### 給付金フラグ有効条件
- 所持ポイントが参加者数未満（マイナスを含む。例：参加者数が5人なら4ポイント以下）であるとき、以下のいずれかの条件に当てはまっている
  - テイクした（次回の給付のみ有効。１回給付されたらフラグは無効になる）
  - 自分が１位のカードが自動回収された（次回の給付のみ有効。１回給付されたらフラグは無効になる）
- 上記とは独立して、手札を山札へ返却する1Pを支払った直後の所持ポイントが4P以下なら、次回の給付のみフラグを有効にする
- 上記の一回給付とは独立して、場札0枚かつ **手札枚数 + 所持ポイント < 8** の場合だけ継続給付する。参加者数は条件に含めず、給付時点でも再判定する
- ドローまたは手札返却の応答では継続給付の現在の対象状態を表示する。継続給付を一回給付へ変換して上限を迂回しない

### 3.3 空場時の緊急補充
- 場札が0枚で、参加済みの全プレイヤーがそれぞれ`所持ポイント + 手札枚数 < 3`を満たす場合、各プレイヤーへ合計が3になる不足分のポイントを即時配布する
- 1人でも3以上のプレイヤーがいる場合は配布しない
- 状態変更と同じトランザクション内で条件を再確認し、同一状態に対する二重配布を防止する
- 監査ログへプレイヤー別配布量と合計配布ポイントを記録し、公開ログには合計配布ポイントだけを表示する

### 3.4 高残高プレイヤーからの定期徴収とPot
- 各給付金タイミングの給付処理後、プレイヤーレベルを`L = floor(sqrt(成功テイク総数))`として、所持ポイントが`(L + 2) × 5`を**超える**各プレイヤーから1Pを徴収する。閾値と同値なら徴収しない
- 条件を満たし続けるかぎり、給付金タイミングごとに1Pを徴収する
- 徴収ポイントと手札返却コストは大会単位のPotへ一時保管する
- Potが1P以上ある状態で投稿者がいる場札を回収するとき、回収直前にPot全額をその場札の総還元ポイントへ加算し、通常の順位配分ルールで分配する
- 投稿者がいない場札の回収ではPotを消費せず、次の還元可能な回収へ持ち越す

## 4. ゲーム進行（各場札のライフサイクル）

### 4.1 カウントダウン
- テイク時のカウントダウンは難易度1・2を60分とし、難易度3以上ではさらに`(難易度 - 2) × 20`分を追加する
- 従って難易度1・2は60分、難易度3は80分、難易度4は100分、難易度5は120分となる
- DB上はテイク時刻へ上記時間を加えた時刻をリミットオーバー時間として記録する
- 誰からも支持されず初投稿がない場札は延長されず、難易度別の初期期限で回収される

### 4.2 スコア投稿
- ゲーム参加者は場札をクリックするとミニゲームルールを確認でき、そのコンポーネントからスコアを投稿可能
- 場札への初投稿は、そのミニゲームへの参加およびルールへの支持の意思表示として位置づける
- スコアの投稿ロジックおよびUIは`next/components/modal/RecordForm.js`を使用する
- テイカー以外のプレイヤーによる、その場札への最初のスコア投稿は常に無料とする
- テイカーによる最初のスコア投稿は、その場札の難易度と同じポイントを消費する
- 同じプレイヤーによる2回目以降のスコア投稿は、投稿のたびにその場札の難易度と同じポイントを消費する
- 参加順は、その場札に対する各プレイヤーの最初の有効な投稿が完了した順で判定する
- 初投稿の判定単位は「プレイヤー × 場札」とする
- 投稿を削除して有効な記録が0件になった場合も、そのプレイヤーの初投稿済み履歴、参加順、支払い履歴、発生済みの初投稿延長は保持する。再投稿は2回目以降として難易度分を支払う
- 投稿費にかぎり残高不足でも支払える。残高0Pからの支払いを含めて負数になり得て、負数も給付条件の判定対象とする
- 1人目の初投稿時点で残り時間が15分未満なら30分、15分以上なら15分延長する。残り15分ちょうどは15分延長とする
- 2人目以降の初投稿では一律10分延長する
- 初投稿延長は投稿費の有無にかかわらず発生する
- 同じプレイヤーによるスコア更新では延長は発生しない
- 初投稿による期限は大会終了時刻を越えて保持してよいが、大会終了時には全場札を強制回収する
- スタック数による制限時間ボーナスは設けない
- スコア投稿によってポイントが即時還元される制度は存在しない

### 4.2.1 プレイヤーによる任意延長
- ログイン済み大会参加者は、当該場札のテイカー・投稿者であるかにかかわらず、残高が1P以上なら1Pを支払って期限を15分延長できる
- 大会終了1時間前以降、回収済み、期限到達済み、大会終了済みの場札は延長できない
- 延長後の期限は大会終了時刻を上限とする
- 延長費は当該場札の支払ポイント総数へ加算し、回収時の総還元ポイント計算へ含める
- ポイント減算、期限更新、支払い履歴、ログ作成は同一トランザクションで行う。処理に失敗した場合は全体をロールバックし、ポイントを失わせない
- 同じリクエストの再送で二重延長しない。一方、利用者が改めて確認した別の延長操作は回数制限なく実行できる

### 4.3 ランクポイント
- 合計ランクポイントがイベントランキングと最終勝者を決める唯一の成績指標である
- そのミニゲームの参加者数を`N`、順位を`r`としたとき、各参加者のランクポイントは `N - r + 1` とする
- 1位は、上記計算に加えて常に1ランクポイントを得る
- 同スコアは同順位とし、順位`r`には標準競技順位を使用する。例として3人中2人が同率1位の場合、順位は1位・1位・3位となる
- ランクポイント計算にスタック数は使用しない
- 例：参加者1人では1位2R、参加者3人では1位4R・2位2R・3位1Rとなる
- 場札のランクポイントは回収時だけでなく、有効なスコア投稿・更新のたびに現在の参加者数と順位からリアルタイムに再計算する
- ダッシュボードの合計ランクポイントは、回収済みカードで確定したランクポイントと、現在場に出ているカードの暫定ランクポイントの合計とする
- 場札の順位が変わった場合、暫定ランクポイントも即時に増減する。回収時は最終順位の暫定分を確定分へ移し、二重加算しない
- 各スコアには暫定ランクポイントと暫定還元ポイントを`[0r/0p]`形式で表示する。左側が暫定ランクポイント、右側がその順位のまま回収された場合の暫定還元ポイントである

### 4.4 回収
- カウントダウンが0になった場札は回収処理を実行し、大会終了まで非表示になる
- 大会終了時、即時回収時、管理者権限発動時も、リミットオーバーを迎えたときと同じ回収処理を行う
- 回収時は、対象場札を回収済みにし、紐づくスタックカードを捨て札へ移動する
- 回収時のランキングで1位となったプレイヤーがホルダーになる。同率1位なら、1位となる記録を最初に登録したプレイヤーを投稿IDの順で選ぶ。記録の日時欄は先着判定に使用しない
- 投稿者がいない場札はホルダー、ポイント還元、ランクポイントを作成せず、場札本体を回収済みとしてそのイベント中は除外し、スタックだけを捨て札へ移す
- ホルダーが存在するカードは恒久的にイベント循環から除外し、ホルダーの所有物として保存する
- 回収前に付与された`stage_id`はホルダーの有無にかかわらず保持し、ホルダーなしカードが次回イベントで再テイクされた場合も同じ`stage_id`を使用する
- 同じ`stage_id`を再利用しても、過去イベントのスコア、参加順、支払ポイント、ランクポイント、還元結果は次回イベントへ持ち越さず、イベントごとに分離して集計する
- 回収処理は冪等にする。すでに回収済みの場札に対して再度回収処理が呼ばれても、ポイント・ランクポイント・ログを二重反映してはならない

#### 4.4.1 総還元ポイント
- その場札に対して支払われたポイントの総数を「支払ポイント総数」とする
- 支払ポイント総数は、その場札へのスコア投稿費と任意延長費として実際に支払われたポイントの合計である
- 支払ポイント総数は、投稿削除や再投稿によって失われてはならない
- 投稿者数を`N`、スタック数を`S`、選んだカードのレア度別スタックボーナスを`B`、投稿費・任意延長費の実支払い総数を`C`、今回の回収へ移すPotを`P`とする
- 総還元ポイントは、投稿者が1人以上なら`Q = S + B + C + P`、投稿者が0人なら`Q = 0`とする
- 場札カード右下には、投稿者の有無によらず現在の`S+B+C`を「総還元P」として表示する。将来の回収へ移るPotはこの表示に含めない
- 控除と難易度ボーナスは使用せず、Potを含む原資を全額配分する
- レア度はスタックボーナスを通じて総還元ポイントに影響する。投稿費には影響しない
- 投稿者が1人だけの場合は通常の順位配分を行わず、総還元ポイント全額をその1人へ還元する

#### 4.4.2 基底配分
- 厳密な順位だけがある場合、理論下限`Q = N + 3`における順位別の基底配分を次のとおりとする
    - `N=1: (4)`
    - `N=2: (3,2)`
    - `N=3: (4,2,0)`
    - `N=4: (4,2,1,0)`
    - `N>=5: (3,2,2,1,...,1,0)`。1Pは`N-4`個
- `N>2`では最下位の順位配分を0Pとする。5人以上では異なる隣接順位が同じ配分になることを許容する
- 実際の`Q`が`N+3`未満なら、基底配分のうち最下位に近い正の成分から1Pずつ減らし、合計を`Q`へ合わせる。2人の場合だけ最下位も減額対象にできる

#### 4.4.3 超過ポイントの循環配分
- `Q>N+3`の差分は1Pずつ配分する
- 2位から最下位の1つ上までを上位から調べ、直上との差が必要差を超えている最初の順位へ1Pを加える
- 必要差は1位と2位の間を2P、その他の隣接順位間を1Pとする。ただし5人以上の基底配分で最初から同配分となる順位間は基底を優先する
- 上記の加算対象がなければ1位へ1Pを加え、再び同じ走査を繰り返す
- 4人では`(4,2,1,0)→(5,2,1,0)→(5,3,1,0)→(5,3,2,0)→(6,3,2,0)→(6,4,2,0)→(6,4,3,0)`となる

#### 4.4.4 同順位と整数端数
- 回収時点のランキングは、各プレイヤーの有効な最高スコアで判定する
- 同スコアのプレイヤーは同順位とする
- まず厳密順位を仮定した各順位枠の配分を計算し、同順位者が占める順位枠のポイントを合算して人数で均等配分する
- 同順位者へ均等配分できない1P未満の整数端数は、順位配分とは別枠で最下位投稿者へ還元する
- 最下位が同点の場合は余剰を均等配分し、割り切れない1P単位はユーザーID昇順で配る
- 最下位への余剰還元は順位配分ではないため、同順位同配分の判定には含めない

## 5. 大会終了後の表示

- 大会終了後は、大会中に回収処理が行われたホルダーありカードを回収カード一覧として表示する
- 手札・山札・捨て札は表示しない
- 回収カードは場札と同じカードコンポーネントで、重ね合わせを使わずスタック数とホルダー名を表示する。下部は作成者・テイカー、ホルダー、アクティブ時間・スタック数の3段とし、プレイヤー名は改行せず末尾を`…`で省略する
- 回収カードをクリックすると、開催中の場札と同じ詳細パネルでその大会のランキング、回収時の総還元ポイント、テイクから回収までのアクティブ時間（`h:mm`）を閲覧できる。投稿コスト・投稿ボタンは表示しない

## 6. デバッグモード

### 6.1 デバッグモード時の特殊処理
- デバッグモードが有効な場合、各カードに回収ボタンを設置し、即時回収できるようにする
- 即時回収でも、通常のリミットオーバー回収と同じポイント配分・ランクポイント反映・ログ記録を行う
- 即時回収とデバッグ時刻の操作は、管理者またはテスト用署名を持つ要求だけに許可する
- デバッグ・テスト用大会では大会時刻を停止し、指定時刻への変更、任意時間の経過、実時刻への復帰を行える。通常大会では常に実時刻を使用する

## 2026-10-06 アニメーション縁・切り札スクロール修正

- レア度3以上はカードfaceの静的border色を透明にし、10pxの幅はレイアウト維持のため残す。アニメーション縁のみを表示する。背後の配置枠はカードと同じ18pxの角丸とし、レア度3以上の占有枠では枠線を透明にして角から露出させない。
- 切り札のtransform transitionは通常無効。スクロール時は配置枠と同じfieldScrollYを即座に適用する。テイク準備時だけ240msの並び替えを行い、その間はホイールで切り札領域を操作しない。
- 縁アニメーションの可視判定・停止・監視解除は従来の仕組みを維持し、常時JS描画は追加しない。

## 2026-10-06 投稿状態・税金徴収ボーダー表示

- 切り札フッターの期限と総還元Pの間に共通の投稿状態領域を設ける。「無料！」とチェックアイコン＋「投稿済み」は同じ領域に表示し、投稿済みを優先する。「無料！」だけ領域内で右寄せにする。アイコンは装飾扱いとし、文字を二重に読み上げない。
- ユーザー情報のクリックツールチップに「税金徴収ボーダー NDP以上」を常時表示する。APIのbalance_tax_thresholdは課税対象外の上限であり、徴収条件はDP > thresholdのため、表示する最小対象DPはthreshold + 1。未取得時はテイクコスト×5 + 1を使用する。
- 徴収判定は従来どおり毎時00分・30分。対象者の表示には既存のbalance_tax_eligibleを使用し、今回課税ロジックは変更しない。

## 2026-10-06 トップページの本大会告知期間

- トップの「期間限定ランキング開催中」は本大会251227に限定し、日本時間2026/10/9 20:00:00以上・2026/10/11 20:00:00未満に表示する。テスト大会の開催状況では表示しない。
- 大会情報はevent_id=251227を指定して取得する。告知期間は固定の実日時で判定し、大会デバッグ時計やAPIのavailableには依存しない。
- 開催中ブロックと「次のイベント」「期間限定チャレンジルール応募」は排他的に描画する。期間外は後者を通常の各表示条件で表示する。
- ページを開いたままでも開始・終了境界で切り替える。開始前は開始時刻まで1本のタイマー、開催中は毎秒と終了境界を更新し、終了後・アンマウント後は時計タイマーを残さない。

## 2026-10-06 切り札の表示順・テイク演出

- 切り札はテイク日時の新しい順で左上から配置する。新規に届いた切り札を先頭に加え、同時刻のカード間はその表示順を維持する。残り時間では並び替えない。
- 成功したテイクでは既存切り札を約240msで1枠ずつ後ろへ動かし、1番目の枠を空ける。描画の余裕32msを置いてから、選択中の手札ポップアップ位置を始点、1番目の枠を終点に約620msで移動する。
- 移動は二次曲線の放物線に沿い、perspective・奥行き・傾きを加えて立体感を出す。内部スクロールにも対応するため、ポップアップとそのoffsetParentの実座標差を使用する。
- 演出開始はAPI成功後・state再取得前とする。移動中の実切り札は隠し、着地時に演出カードを実切り札へ切り替える。失敗・確認キャンセル時には配置を変えない。演出中は操作と定期ポーリングを一時停止し、終了時に再開する。
- CSSで有限時間の移動を実行し、終了・アンマウント時にタイマーを破棄する。常時RAF、追加パーティクル、重いフィルターは使用しない。

## 2026-10-04 細部操作調整

- 「手札非表示」「手札を表示」は手札とデッキ本体を同時に切り替える。コマンドは残す。
- ユーザー情報をクリックすると、直下に同じ背景・順位色の枠のボックスを表示する。幅280px・画面幅内に制限し、高さは内容に応じる。テイクコスト、次のレベルまでの必要テイク回数、累計所持カード数、手札上限を１行ずつ表示する。必要テイク数は `max(0, (take_level + 1)^2 - take_count)`。ボックス内のクリックでは閉じず、外側クリック、元のユーザー情報の再クリック、スクロール・リサイズで閉じる。追加の常時描画は行わない。
- ユーザー情報のミニホルダーカードは `#{stage_id} {title}（{rule_name}）` のツールチップを表示し、クリックで既存の `/api/tricks/cards/{deck_id}/scores` を読み込むランキングポップアップをミニカードの直下（下端＋4px）に開く。横方向は画面外へ出ないよう補正する。投稿・延長などの操作は設けず、閉じるボタンだけを表示する。state DTOにカードID・タイトル・ルール名を加える。
- ログのステージ名にはルール名を全角括弧で併記し、ホルダー回収のユーザー名に「さん」を付ける。ログDTOにrule_nameを加え、既存ログにも現行デッキ情報を反映する。

## 1. 前提条件

- 勝者は大会終了時の合計ランクポイント最大者とし、イベントランキングは合計ランクポイント降順で表示する
- ドローポイント・手札の終了時保有量は勝敗や報酬に使用せず、期間限定チャレンジの成績をイベントの主目的とする
- 腕前差によって上位を取りにくい参加者にも、多数投稿、長時間練習、巨大トリックなど別の遊び方を提供する
- 「トリックテイキング」はメインプロジェクト配下に単一ページで表示する子プロジェクト（特設ページ）である
- この子プロジェクトは`/next/pages/limited/tricks/`に単一ページとして表示する
- ルールの正本は`next/pages/limited/tricks/docs/tricks-rules.md`とし、本ドキュメントはUI・DB・APIへの落とし込みを担当する
- シミュレーション固有の仮定・行動モデル・未採用候補は`next/pages/limited/tricks/docs/tricks-simulation.md`を正本とする
- 既存の投稿UIは`next/components/modal/RecordForm.js`を利用し、ランキング表示は`next/components/record/Record.js`をmini表示で利用する
- イベント専用のドメイン処理は共通サービスへ集約し、`TrickController.php`と汎用記録処理の双方から同じサービスを利用する
- 即時反映は短周期ポーリングを前提とする。ポーリングで大会運営上の遅延・負荷が問題になる場合にのみ、WebSocketまたはSSEを追加検討する

## 2. 画面構成

- canvasは画面いっぱいに表示する（既存のレイアウト制限は無視し、イベント専用の2段固定ヘッダーを表示する）
- ヘッダーの参加者欄には最下部4列の「ランク／DP／手札／回収」と、その大会でホールドした枚数と同数の極小カードを表示する。極小カードは`tricks-player-info`の直下で同じ横幅を使って折り返し、レア度に対応する縁色と中央揃えの半角数字の難易度を表示する。難易度が未定義ならハイフンを表示する。累計はツールチップだけに「累計所持カード：X 枚」と表示し、第2〜18回期間限定ランキングのホルダーも含める
- 第2〜18回の各ステージは、有効な最高記録の投稿者をホルダーとし、同点ならその最高記録を先に投稿したプレイヤーを優先する。期間限定ランキング以外のイベントは対象外とする
- ユーザー別ページのイベントスタンプ数の右に、ホルダーカードがある場合だけコレクタールームの枚数と開閉ボタンを表示する。展開領域はダッシュボードの直前に配置し、ランクポイント降順、ステージID降順の順で既存のDOMカードを並べる。カード詳細には投稿不能のミニランキングを表示する。進行中大会のカードは並べない
- 歴代ステージ名の「ステージ名（ルール名）」はカードのタイトルとルール名に分割する。括弧の全角・半角が混在し、括弧後にチーム戦の役割表示がある場合は役割表示をステージ名へ残す

### 2.1 サイト名等

- 1段目は左上に密着した黒背景・白文字の1行ナビゲーション。下角を丸め、内容幅で表示する。ホーム、第19回期間限定ランキング、トリックテイキング制×スタンダード、実時刻（日本時間）、Discord、テーマ変更、ナレッジの順に配置する。
- ナビゲーションの時計は独立したタイマーで更新し、Phaserを再描画しない。大会残り時間はダッシュボード内の大会情報ブロックへ表示する
- ログは新しい順に最大10行まで表示し、100行までスクロールできる。101行目以降は取得しない。新規ログは先頭へ挿入する。各行は日本時間の`hh:mm:ss - ログ本文`で表示し、参加・テイク・投稿・給付・回収をスクリーンネームとカード名を用いた利用者向け文面へ整形する
- 参加者0人で回収されたカードのログは「{cardTitle}が除外されました。」と表示する。内部状態は`_collected`であり、再利用可能なトリック由来の`_trash`とは区別する
- ログ表示領域は幅400pxとし、ログラッパーを画面右側へ固定する。上端はヘッダー直下とし、初期状態は右へ収納する。収納時は本文を不可視にして、44px幅のログタブだけを残す
- タイトルはログ表示領域の左側に置く。タイトルクリック時はログ表示領域を右へスライドして画面外へ隠し、タイトルだけを残す。再クリック時は左へスライドして元の位置へ戻す
- 手札のデッキへの返却は公開ログへ表示せず、監査用の非公開ログだけに記録する
- ログはバックエンドを短周期ポーリングで監視して反映する
- サイト名をクリックでサイトトップページ`/next/pages/index.js`に遷移する

### 2.2 ダッシュボード

- 2段目として左から大会情報・参加者情報を固定表示する。親背景は透明、大会情報・参加者情報は視認性を優先してテーマ標準背景色の不透明度97%とする。管理者は大会情報のDEBUGからデバッグパネルを開閉する。
- 全参加者のプレイヤー名、ドローポイント、手札枚数、回収カード数、合計ランクポイントが合計ランクポイント降順に一覧表示
- 合計ランクポイントは「回収済みカードの確定分 + 現在の切り札の暫定分」とし、投稿・更新による順位変動を短周期ポーリングまたは投稿直後の再取得で反映する
- プレイヤーカードでは確定・暫定ランクポイントの内訳を表示せず、合計ランクポイントだけを表示する
- 一度に表示できるのは10人までとし、11位以下はスクロールして表示する
- ダッシュボードの内容はバックエンドを短周期ポーリングで監視して反映する
- ユーザー名には内部ユーザーIDではなく、ユーザー一覧から取得したスクリーンネームを表示する
- ダッシュボードの先頭へ同じカードスタイルの大会情報ブロックを置き、現在の切り札上限、回収カード総数、大会残り時間、ドロー総数、テイク総数、ポイント総数を表示する。ドロー総数は大会内の成功ドロー履歴、テイク総数は参加者の成功テイク数の合計。ポイント総数は全参加者の所持P＋ポット＋各切り札の還元予定P（ポット重複分を除く）とし、消滅済みPや回収済みカードの過去還元は加算しない。次回ドローポイント給付までの`mm:ss`カウントダウンは給付対象者が1人以上いる場合だけ表示し、ドローポイント消費後のstate再取得でも即時に再判定する。テイク必要手札数は全体共通情報に表示しない
- 大会終了3時間前以降は残り時間を黄色にし、直下に「レジェンダリー排出率10倍！」と表示する。終了70分前以降は橙色で「まもなくテイクできなくなります！」、終了60分前以降は赤色で「まもなく大会終了します。\nテイク・延長はできません」に切り替える。表示判定にはサーバー時刻で補正した既存カウントダウンを使う
- 各プレイヤー欄へ、成功テイク総数から算出した`Lv.{take_level} / テイクコスト {take_cost}`を公開表示する
- 通常モードでは大会情報と全プレイヤーカードを含むヘッダー列が横幅を超える場合に領域内だけ横スクロール可能にする。観戦モードでは複数行へ折り返し、切り札をヘッダー最下段の下へ配置する
- 給付金フラグが有効なプレイヤーの残ドローポイントは、`P`だけに下線を付けた`P 数値`とし、従来どおり赤紫色で表示する。フラグ状態は操作完了後のstate再取得および短周期ポーリングに追従する
- 大会残り時間は1時間以上なら`00時間00分`、1時間未満なら`00分00秒`で表示し、1時間未満ではクライアントの補正済み時計により1秒ずつ更新する

### 2.3 切り札

- 中央表示（**スクロール可能領域。**ヘッダー・フッター以外のすべての表示領域を占有）
- 切り札のカードコンポーネントを新しくテイクされた順に左上から右下へ表示し、新規テイクは1番目の枠へ挿入する
- 空場メッセージは表示しない。切り札上限分のカードと同寸の枠線をグリッド配置し、右上に配置順の番号を表示する。枠と切り札は同じ座標・スクロール計算を使う。
- テイク時点でリミットオーバー時間を必ず設定する。未設定の切り札は不整合として操作せず再取得する

### 2.4 デッキ

- 左下固定表示
- デッキは裏面のカードトリックとして手札の高さへ揃え、デッキという見出しを表示しない。裏面は外側18px／内側8pxの角丸、藍色を土台とした静的な斜め格子とグラデーションを使う。
- デッキクリックで右側にツールチップを表示し、★1〜★5の残り枚数を「★1：X枚」形式で各1行に示す。デッキ・ツールチップの領域外クリック、Escape、手札非表示で閉じる。内訳はstate APIの`deck_difficulty_counts`を用い、ドロー・返却・再シャッフル後のstate取得で更新する。
- 手札直上の左端に、初期状態が開いている収納式コマンドウィンドウを置く。ドロー、手札非表示、遊び方、残り枚数・捨て札数・操作不可理由を表示する。新設ブロックには固有のCSSクラスを付ける。
- ドローボタンはユーザーのドローポイントが0P以下、またはデッキが0枚のとき非活性にし、APIを発火できないようにする。state更新でデッキが1枚以上になったらすぐに活性状態を再判定する

### 2.5 手札

- 中央下・右固定表示（デッキと手札でフッターを構成）。領域背景は透明にする。
- 手札のカードコンポーネントをドローした順に左から表示する
- 人間が手に持っているように扇状に配置し、各カードコンポーネントは常に全域表示する必要はない
- 大量の手札でも左右端が過度に沈まないよう、中央から端までの縦位置差は最大約54pxの緩い曲線とし、カード角度も最大約12度に抑える
- ドロー成功後はデッキ上でカードを約0.32秒かけて裏面から表面へ反転し、表面を約0.2秒静止表示してから、角度を手札位置へ合わせながら約0.62秒の放物線状軌道で手札の右端へ移動する
- ドローAPI成功後は状態再取得より先に演出カードを表示し、追加済みの実カードを一時的に隠す。手札0枚からのドローを含め、演出前の実カード表示や演出カードとの二重表示を発生させない。デッキから手札への移動中は演出カードを常に完全不透明とし、演出終了時に実カードへ即座に切り替える。演出完了後はタイマーとゴースト要素を必ず破棄する
- 可能ならドラッグで並び替えできるようにする
- 手札詳細ではルールを確認してオフライン練習できるが、練習専用ボタン、練習時間、練習回数はWebシステムへ保存しない
- 手札フッターの「手札」とレア度表示は置かない。同じ大会で2回目以降にドローしたカードだけ、Font Awesomeの`square-check`アイコンと「開封済み」を灰色で表示する。レア度を保持する手札返却後の再ドローが対象。捨て札へ回った時点で開封回数・レア度をリセットし、再抽選するドローは空欄とする
- コマンドウィンドウのドローボタン直下に「手札非表示」ボタンを置く。押下時は手札を下方向へスライドして領域外に隠し、「手札を表示」へ切り替える。再押下時は領域外から上方向へスライドして戻す
- 「手札非表示」ボタン直下に「遊び方」ボタンを置き、イベント説明モーダルを再表示する

### 2.6 捨て札

- 左下のコマンドウィンドウへ捨て札枚数だけを表示し、カード内容は表示しない
- 大会終了後はデッキ・手札とともに非表示にする

## 3. 各コンポーネントの動作処理

### 3.1 手札クリック時の動作

- 選んだ手札を全体像が確認できる位置へ移動し、「場に出す」「デッキに戻す」「キャンセル」ボタンをこの順で表示する
- 「場に出す」ボタンの上に、テイカー初投稿コスト（選択カードの難易度と同値）と、テイク前の表示用トリック数`手札総数S + 選択カードのレア度ボーナスB`を太字で表示する。`B>0`ならトリック数の直下に`（レア度ボーナス B）`を表示する。例：手札6枚・レア度2はトリック数9、直下は`（レア度ボーナス 3）`
- テイク条件を満たさない場合はテイクボタンを非活性にし、理由を表示する
    - クールダウン中は、次にテイクできる時刻と残り時間を理由として表示する
- キャンセルボタンかモーダル外領域をクリックすると手札は元の位置に戻る
- 手札選択中は、選択カードと手札メニュー以外のPhaser・DOMオブジェクトを共通の遮光レイヤーで一律に暗くし、操作を遮断する
- デッキに戻すボタンは所持ドローポイントが0P以下でも表示するが非活性にする。1P以上なら確認後に1Pを消費し、選択カードをランダムなデッキへ戻す。返却後に自動ドローはしない
- デッキへの返却成功後は選択カードを手札位置からデッキ位置へ移動させる。移動中はカードを常に完全不透明とし、到着時に演出カードを破棄する

### 3.2 テイクボタンクリック時の動作

- 「手札をすべて消費してこのカードを場に出しますか？」という確認モーダルを表示（はい/キャンセル）。レア度2以上ではレア度別トリックボーナス値も表示する
- 確認モーダルで「はい」を押下すると確認モーダルと手札モーダルを閉じ、テイクAPIを呼ぶ
- テイク成功後、選んだカードを切り札として表示する
    - 手札から切り札の領域へシームレスに移動する
    - 切り札を公開し、難易度1・2は60分、3は80分、4は100分、5は120分後をリミットオーバー時間としてセットする
- 残りの手札はすべてトリックになり、手札からは消滅する
- テイク直前の手札枚数 + 所持ドローポイントが5未満なら成功時に1P即時支給し、処理後の合計が3未満の場合だけ継続給付フラグを表示する

### 3.3 切り札クリック時の動作

- 選んだ切り札のカードコンポーネントと、そのゲームに投稿されたスコアがモーダル表示される（切り札モーダル）
- 切り札モーダルの各スコアは汎用記録コンポーネント（`next/components/record/Record`）をminiフラグをONにして表示する
    - RPS表示領域には暫定ランクポイントと暫定還元ドローポイントを`[0r/0p]`形式で表示する。左側は「参加者数 - 順位 + 1」（1位はさらに1R）、右側は現在の順位のまま回収された場合の配分値とする
- ランキング下部に「投稿」「延長」「閉じる」ボタンを表示する。「延長」は「投稿」の隣に置く
- 投稿ボタン付近には、非テイカー初回は無料、テイカー初回と2回目以降は難易度分である現在の投稿費を表示する
- 延長ボタンは未ログイン、未参加、1P未満、大会終了1時間前以降、回収期限到達後、大会終了後、処理中には非活性にする
- 延長ボタンを押すと「１点支払ってこのカードの期限を延長しますか？」と確認ダイアログを表示する。OKで延長APIを呼び、成功後に期限・残ドローポイント・支払総額・ログを再取得する
- 延長失敗時はダイアログを閉じず理由を表示する。サーバーのトランザクションロールバックによりドローポイントを失わせない
- 切り札選択中は、選択カードとランキングパネル以外のPhaser・DOMオブジェクトを共通の遮光レイヤーで一律に暗くし、操作を遮断する

### 3.4 スコア投稿成功時の動作

- 該当カードのリミットオーバー時間はテイク時に設定済みであることを前提とする
- 非テイカー初回は無料、テイカー初回と全員の2回目以降は難易度分を消費する。有料投稿は残高不足でも受理し、支払い後残高は負数を許容する
- 1人目の初投稿は通常15分、投稿時点の残りが15分未満なら30分延長する。2人目以降の初投稿は一律10分延長し、スコア更新では延長しない
- 初投稿による期限が大会終了時刻を越えても保存できるが、大会終了時には強制回収する
- 各プレイヤーの合計ランクポイントを再計算する

### 3.5 未参加者のアクセス時の動作

- 未参加者は画面全体を遮光し、最前面の中央導線以外のPhaser・DOMオブジェクトを操作不能にする。切り札クリックでもランキングを開かない
- 未ログインの場合：「このイベントに参加するにはログインが必要です」を太字で表示し、「ログイン」だけをログインページへのリンクにする
- ログイン済みの場合：「第19回期間限定ランキングに参加する」を太字で表示し、「参加する」だけを参加APIのボタンにする。切り札領域の旧参加ボタンは表示しない
- 参加APIが失敗した場合は、参加ボタンと同じ前面領域に`HTTP 401: 認証が必要です`のようにHTTPエラーコードと理由を表示する
- 参加時の自動ドローは行わない。参加成功後は説明モーダルを表示する
- 説明モーダルには `/limited/tricks/limited_19_manual.pdf` をブラウザ内蔵PDFビューアで表示する。画面幅・高さに合わせた領域とし、右下に「PDFを別タブで開く」リンクと「閉じる」ボタンを置く。閉じたらPDF表示を破棄する
- 一度参加したユーザーは退出できない。ログアウトやページ離脱をしても参加状態は維持する
- 未参加状態の「大会へ参加してください」という補助文言は表示しない。ドローボタンの非活性は維持する

### 3.6 特殊な動作

- 各切り札はクライアント側で毎秒表示更新する。リミットオーバー時間を過ぎた切り札があれば、短周期ポーリングまたは明示API呼び出しにより回収処理を反映する
- テイク済み切り札のリミットオーバー時間は必須とし、未設定の場合は不整合として操作を止め、サーバー状態を再取得する
- 大会残り時間が0になった場合、すべてのボタンを非活性にし、その大会の回収カード一覧を表示する
- 大会終了後の回収カード一覧はホルダーの有無にかかわらずすべて対象とし、切り札と同じカードコンポーネントで表示する。下部は1段目に作成者・テイカー、2段目にmedalアイコンとホルダー、3段目にアクティブ時間・ポット込み実総還元Pを置く。名前は改行せず、収まらない分を末尾`…`で省略する。トリックの重ね合わせ表現は使わない
- 回収カードをクリックすると開催中の切り札と同じ詳細パネルで、最終ランキング、回収時の総還元ドローポイント、`collected_at - taken_at`のアクティブ時間（`h:mm`）だけを表示する。投稿コスト・投稿操作は表示しない
- 回収カードの詳細パネルは、クリックしたカードの中央が画面中央より左なら右側、右なら左側へ切り札と同じオフセットで表示する。ホルダー名はユーザーIDではなくスクリーンネームを使う
- role=10の管理者だけは、開催中・閉幕後とも大会情報クリックで開閉できるステータスパネルを利用できる。パネル領域外クリックまたはEscapeで閉じる。参加者ごとに合計ランクポイント、同率1位では最初に投稿したホルダーだけを数える回収カード数、テイク数、ドロー数、デッキ返却数、投稿数、獲得ドローポイント総数（現在残高＋累積使用P。初期配布・給付・補償・回収還元を含む）、使用ドローポイント総数（課税を含む）、発生ポイント合計と人気クリエイター指数を表示し、各列の最大値セルを強調する。統計APIもrole=10で認可する
- 回収カードのランキングは`event_id`と`event_card_id`で対象大会を固定し、同じ`stage_id`を使った他大会の投稿を混在させない
- 切り札枚数にかかわらず、給付金タイミングごとに手札枚数 + 所持ドローポイントが3未満の全プレイヤーへ1P給付する

### 3.7 Phaser/Reactの責務分離

- ゲーム状態の正本はLaravel APIのスナップショットとし、Phaser Sceneは描画・入力・Tween・パーティクルのアダプタとして扱う
- レンダラー非依存の判定や整形（期限切れ判定、残り時間表示、手札順、切り札順、短縮表示など）は`next/lib/tricks/index.js`に置く
- Phaser canvasはカード操作と視覚演出を担当する。具体的には、手札扇形配置、ドラッグ中断時の座標復帰、デッキ→手札、手札→切り札、切り札選択時の座標移動、パーティクルを扱う
- ログ、ダッシュボード、ランキング、投稿フォームなど、スクロールやテキスト密度が高いUIはDOM/React側で扱う
- 切り札詳細はPhaser側で選択カードをモーダル表示位置へ移動させ、その後React/MUIのモーダルでランキングと投稿導線を表示する

### 3.8 レンダリング負荷に関する制約

- 本イベントは低スペックPCの参加者も想定するため、見栄えのために過剰なローカルリソースを消費してはならない。フルスクリーンcanvasを使う場合でも、静的な状態で高fps描画を続ける、重いフィルターや大量パーティクルを常用する、不要に大きい描画領域を維持する実装は避ける
- Phaser Sceneの再描画では、古いGameObject、Tween、イベントリスナー、DOM要素を確実に破棄する。`children.removeAll()`のように表示リストから外すだけの処理に依存せず、必要に応じて`destroy()`やTween停止を明示する
- ポーリングやSWR更新で画面全体を再生成する場合は、更新頻度を必要最小限にする。回収・投稿・テイクなど状態変化が発生した時は即時再取得してよいが、状態変化のない監視処理で毎秒全再描画を誘発しない
- レンダリングに関わる改修をした場合は、Playwrightでcanvasが描画されることだけでなく、常時描画fps、オブジェクト数の増加、ポーリング間隔、画面を開いたままにした時のCPU/GPU負荷を確認する
- デバッグ・テスト時は`window.__TRICKS_DEBUG_SNAPSHOT__()`からGameObject、DOMカード、canvas、timer、RAF、state取得、実再描画の件数を読み取り、静止前後で増加していないことを確認できるようにする
- 過負荷または過負荷になりうる実装を検知した場合は、仕様・要件の範囲内で軽量化を優先する

## 4. コンポーネントの詳細仕様

### 4.1 カードコンポーネント

- 固定の大きさで表示する。通常カードは外側角丸18px・縁10pxとし、内側を半径8pxの角丸にする。外寸は維持する。
- カードのルール本文は短縮せず全文を表示し、140文字以下は14px、141〜200文字は12px、201文字以上は10pxとする。改行と長い連続文字列も保持し、領域を超える場合は本文内でスクロール可能にする。
- カード名、ルール名、ルール詳細、作成者、テイカー、難易度（★1〜★5）、レア度（1〜5）、残り時間を表示する。切り札右下にはリアルタイムの総還元P（基本額`S+B+C`、投稿者がいる最短期限カードはポット込み）を表示する
- カードの縁（通常10px、ミニカード2px。外寸は維持）でレア度を表現する。コモンはライトで黒に近い灰色、ダークで白に近い灰色。アンコモンはテーマに関わらず薄めの黒 #262626 に薄い灰色の網目を重ねる。
- レアは青→藍→青の斜めグラデーション（12秒）。エピックは緑→水色→青→水色→緑→黄緑→緑の斜めグラデーション1層（9.6秒）。色間隔はレア64px（模様周期128px）・エピック48px（周期288px）。レジェンダリーは2026-10-05の再構成で独自の「液体の金とプリズムの流れ」へ変更。鮮やかな黄色 #ffdb00 に、太い虹色の曲線、屈折を表す2層、細い光の筋を4層で重ねる。独自SVG liquid-spectrum-v6／filaments-v6を使い、opacityは.95／.44／.22／.7、周期は41／67／97／53秒。位置・角度・拡縮・位相を層ごとに分け、滑らかな補間と同じ始終点で連続性を保つ。規則的なタイル繰返しはしない。レア度3以上はテーマ不変。制作・評価記録は `tricks-legendary-art-direction.md`。
- 共通の `TricksCardBorder` はレア度1〜4で固定の10pxリングマスク内だけに描画する。レジェンダリーはフレームだけでも演出が成立する設計を維持しつつ、最新指定により模様をカード面の背後まで描画し、内部背景を白90%不透明（10%透過）にする。縁を透過させず、文字・ドローポイントのopacityは1を維持する。切り札・手札ともダークテーマでも本文は黒系文字。固定SVGをCSS transformで動かし、毎フレームのJS更新、液体物理シミュレーション、重いフィルターは使用しない。
- 手札・切り札の見えているカードだけをアニメーションさせる。画面外・手札非表示・選択で隠れた元カード・バックグラウンドタブ・reduced-motion時は停止する。ドロー中の一時カードとミニホルダーカードは静的表示とし、回収一覧はホバー／キーボードフォーカス時だけ演出する。共有IntersectionObserverとvisibilitychangeは最後のカード破棄時に解放する。
- レア度3以上のカードを場へ出した瞬間だけ、カード中心から放射状に広がる短時間の光をカード直下レイヤーへ表示する。ポーリングや毎秒の時刻更新では再生しない
- 還元ドローポイントの丸は黒背景。数値の色は5以下＝灰、6〜10＝白、11〜15＝空色、16〜20＝青、21〜30＝青紫、31〜50＝赤紫、51〜99＝赤、100以上＝橙。通常17px、100以上は2pt（8/3px）小さくする。旧文字グラデーションは廃止する。
- 切り札のトリック背面は境界10px #8994a8／内側 #e4e8ef、交互に境界 #718097／内側 #f2f4f8 とし、複数枚の重なりを静的な色差で示す。縁外に追加の2pxボーダーを付けない。
- 投稿コストは、非テイカー初回を0P、テイカー初回と2回目以降を難易度と同じ値として扱う
- 回収カード表示ではすべての回収カードを表示し、一覧コンテナとカード外枠には追加のborderを表示しない

## 5. バックエンドの仕様

### 5.1 データベース

- `decks`テーブルはイベントをまたいで存続するカード本体と、カード固有の`stage_id`を管理する
- イベント内のデッキ・手札・切り札・トリック・捨て札・回収済み状態は、`event_id`とカードを組み合わせた`trick_event_cards`で管理する
- ゲームの記録は`records`テーブルを利用する（非イベント時も使う汎用記録テーブル）
- `records`へのカラム追加はしない想定。必要な場合ユーザーの承認を要する
- 大会期間、進行状態、デバッグ時計は`trick_events`でイベント単位に管理する
- 各カードにはカード固有IDとして`card_id`を付与する。`stage_id`は投稿先となる`stages.stage_id`であり、テイクされた時点で初めて払い出す
- 2026-10-04のmigrationで`stageId`、`ruleName`、`topPlayer`をそれぞれ`origin_stage_id`、`rule_name`、`top_player`へ統合し、旧3列と`decks.rarity`を削除した。元ステージ番号と投稿用`stage_id`は別用途である。`eventId`は従来の大会由来情報として残す
- ドローポイント消費履歴、回収時配分履歴、ホルダー、イベント投稿との紐付け、定期給付済みスロット・即時支給監査ログは、イベント単位の冪等性を担保できる永続データとして保存する

### 5.1.1 `trick_events`テーブル設計

大会設定と進行状態を管理する。通常大会は実時刻、デバッグ・テスト大会だけは制御時計を利用できる。

| カラム                         | 型                             | 必須 | 用途 |
|-----------------------------|-------------------------------|----|------|
| `id`                        | unsigned big integer          | 必須 | 主キー |
| `event_id`                  | unsigned integer              | 必須 | 大会ID。一意制約を付ける |
| `title`                     | string                        | 必須 | 大会名 |
| `start_at` / `end_at`       | datetime                      | 必須 | 48時間の開催期間 |
| `state`                     | string                        | 必須 | `scheduled`、`active`、`ended` |
| `debug`                     | boolean                       | 必須 | デバッグ大会か |
| `test_mode`                 | boolean                       | 必須 | 自動テスト専用大会か |
| `debug_now`                 | datetime nullable             | 任意 | 停止・変更可能な大会内時刻。通常大会では参照しない |
| `last_subsidy_slot_at`      | datetime nullable             | 任意 | 大会全体で最後に処理した給付スロット。同一スロットの再処理を防ぐ |
| `random_seed`               | unsigned big integer nullable | 任意 | テスト時の抽選再現用seed |
| `initialized_at` / `ended_at` | datetime nullable           | 任意 | 初期化・終了処理の冪等性判定 |
| `created_at` / `updated_at` | timestamp                     | 必須 | Laravel標準タイムスタンプ |

- 大会時刻の取得は`TrickClock`へ集約し、通常大会では実時刻、`debug`または`test_mode`の大会だけは`debug_now`を使用する
- テストごとに一意な`event_id`を作成し、時刻操作やfixtureが他大会へ影響しないようにする

### 5.1.2 `decks`テーブル設計

`decks`はイベントをまたいで存続するカード本体を管理する。イベント内状態は`trick_event_cards`へ分離し、`stage_id`は一度付与したら変更・削除しない。

| カラム                         | 型                             | 必須 | 用途                                                                 |
|-----------------------------|-------------------------------|----|--------------------------------------------------------------------|
| `id`                        | unsigned big integer          | 必須 | カードID。内部操作の主キー                                                     |
| `card_id`                   | unsigned big integer          | 必須 | イベントをまたいでカードを識別する固有ID                                               |
| `event_id`                  | unsigned integer nullable     | 任意 | 既存`eventId`互換用。イベント履歴の正規データには使用せず、必要なら直近採用大会を保持する             |
| `stage_id`                  | unsigned integer nullable     | 任意 | 初回テイク時に1001以上2000未満の未使用最小番号を払い出す永続的な投稿用ステージ番号。次回イベントでも同じ値を使う |
| `origin_stage_id`           | unsigned integer nullable     | 任意 | カードの元になった既存ステージ番号。既存`stageId`相当                                    |
| `title`                     | string                        | 必須 | カード名・ステージ名                                                         |
| `rule_name`                 | string                        | 必須 | 縛りルール名。既存`ruleName`相当                                              |
| `text`                      | text                          | 必須 | 期間限定チャレンジのルール本文                                                        |
| `state`                     | string                        | 必須 | グローバル状態。`_eligible`（投入可能）、`_in_event`（開催中大会で使用中）、`_held`（ホルダー所有） |
| `creator`                   | string nullable               | 任意 | 考案者の表示文字列（共同案も可）。ユーザーIDとの照合・表示名変換はしない                                                   |
| `created_at` / `updated_at` | timestamp                     | 必須 | Laravel標準タイムスタンプ                                                   |

`decks.rarity`は削除済みであり、レア度は`trick_event_cards.rarity`だけを参照する。既存の`difficulty`、`taker`、`top_player`、`count`、`rewards`等を互換キャッシュとして残す場合でも、複数イベントの履歴判定には使用しない。正規データはカード本体を`decks`、大会内状態を`trick_event_cards`から取得する。

### 5.1.3 `trick_event_cards`テーブル設計

カードの大会内状態と大会ごとの結果を管理する。大会開始時、デッキへ採用する各カードについて1行作成し、`event_id`と`deck_id`をユニークにする。

| カラム                         | 型                             | 必須 | 用途                                                                 |
|-----------------------------|-------------------------------|----|--------------------------------------------------------------------|
| `id`                        | unsigned big integer          | 必須 | 大会内カードID                                                          |
| `event_id`                  | unsigned integer              | 必須 | 大会ID                                                               |
| `deck_id`                   | unsigned big integer          | 必須 | カード本体`decks.id`                                                    |
| `state`                     | string                        | 必須 | `_deck`、`_field`、`_stack`、`_trash`、`_collected`、または手札所有者の`user_id` |
| `difficulty`                | unsigned tiny integer         | 必須 | 当該大会・ドローで使用する難易度1-5                                             |
| `rarity`                    | unsigned tiny integer nullable | 任意 | 未ドロー時null、ドロー時に付与するレア度1-5                                        |
| `stack_count`               | unsigned integer              | 必須 | テイク時点の手札枚数S                                                     |
| `taker`                     | string nullable               | 任意 | 当該大会のテイカー                                                        |
| `top_player`                | string nullable               | 任意 | 当該大会の現在トップ。共同1位の正規データは投稿集計から求める                                  |
| `post_count`                | unsigned integer              | 必須 | 当該大会の有効投稿数                                                       |
| `paid_points_total`         | integer                       | 必須 | 当該切り札で支払われた投稿費と任意延長費の総数                                           |
| `limit_at`                  | datetime nullable             | 任意 | テイク時に難易度別初期期限を設定し、初投稿・任意延長で更新する期限                               |
| `taken_at`                  | datetime nullable             | 任意 | 当該大会でテイクされた時刻                                                   |
| `collected_at`              | datetime nullable             | 任意 | 当該大会で回収された時刻                                                    |
| `stack_parent_id`           | unsigned big integer nullable | 任意 | `_stack`行が紐づく親`trick_event_cards.id`                                |
| `drawn_order`               | unsigned integer nullable     | 任意 | 手札内の表示順                                                           |
| `returned_count`            | unsigned integer              | 必須 | デッキへ返却された累計回数。返却操作の監査用                                 |
| `draw_count`                | unsigned integer              | 必須 | 前回のレア度抽選からのドロー回数。抽選時1、2回目以降は開封済み。捨て札移動時0 |
| `created_at` / `updated_at` | timestamp                     | 必須 | Laravel標準タイムスタンプ                                                   |

状態値の定義は以下とする。

| state        | 意味                         |
|--------------|----------------------------|
| `_deck`      | デッキ                         |
| `{user_id}`  | 指定ユーザーの手札                  |
| `_field`     | 切り札。投稿可能または初回投稿待ち           |
| `_stack`     | 切り札に紐づくトリックカード。他ユーザーには内容非公開 |
| `_trash`     | 捨て札。デッキ枯渇時の再シャッフル対象         |
| `_collected` | 回収済みカード。当該大会中は循環へ戻さず、大会終了後の結果表示に使用する |

### 5.1.4 `players`テーブル設計

参加者の大会内状態を管理する。既存`players`テーブルを利用する。

| カラム                         | 型                    | 必須 | 用途                            |
|-----------------------------|----------------------|----|-------------------------------|
| `id`                        | unsigned big integer | 必須 | 主キー                           |
| `event_id`                  | unsigned integer     | 必須 | 参加した大会ID                       |
| `name`                      | string               | 必須 | 既存ユーザーID。`event_id`との組み合わせでユニーク化する |
| `points`                    | integer              | 必須 | ドローポイント。既存物理カラムを使う場合も論理名はドローポイントとする |
| `rank_points`               | integer              | 必須 | 回収済みカードで確定したランクポイント。切り札の暫定分は取得時に集計する |
| `card_count`                | integer              | 必須 | 手札枚数のキャッシュ。当該大会の`trick_event_cards`実数と同期する |
| `subsidy_flag`              | boolean              | 必須 | 旧一回給付フラグ（資格判定には使用しない）。API表示は現在合計3未満で算出         |
| `subsidy_flag_slot_at`      | datetime nullable    | 任意 | 旧一回給付の互換列。新条件では使用しない             |
| `last_subsidy_paid_slot_at` | datetime nullable    | 任意 | 給付金の二重配布防止                    |
| `last_take_at`              | datetime nullable    | 任意 | 直前にテイクが成功した時刻。60分クールダウン判定に使用する |
| `take_cooldown_released_for`| datetime nullable    | 任意 | 旧ルールの互換用列。現行ルールでは参照・更新しない |
| `take_count`                | unsigned integer     | 必須 | 当該大会で成功した総テイク回数。既定0 |
| `created_at` / `updated_at` | timestamp            | 必須 | Laravel標準タイムスタンプ              |

### 5.1.5 `trick_card_payments`テーブル設計

切り札ごとの投稿費・任意延長費の支払い履歴を管理する。無料の初投稿も参加順確定のため0P履歴として保存する。

| カラム                         | 型                             | 必須 | 用途                    |
|-----------------------------|-------------------------------|----|-----------------------|
| `id`                        | unsigned big integer          | 必須 | 主キー                   |
| `event_id`                  | unsigned integer              | 必須 | 支払いが発生した大会ID          |
| `event_card_id`             | unsigned big integer          | 必須 | 対象`trick_event_cards.id` |
| `deck_id`                   | unsigned big integer          | 必須 | 対象切り札                  |
| `stage_id`                  | unsigned integer              | 必須 | 投稿用ステージ番号             |
| `player_name`               | string                        | 必須 | 支払ったユーザーID            |
| `payment_type`              | string                        | 必須 | `initial_post`、`score_update`、`player_extension` |
| `submission_number`         | unsigned integer nullable     | 任意 | プレイヤー×切り札の投稿回数。任意延長ではnull |
| `points_paid`               | integer                       | 必須 | 実際に支払ったドローポイント。投稿費は難易度、任意延長は1P |
| `record_id`                 | unsigned big integer nullable | 任意 | 投稿費の契機になった投稿ID      |
| `idempotency_key`           | string                        | 必須 | 同一リクエスト再送による二重課金・二重延長を防ぐキー |
| `created_at` / `updated_at` | timestamp                     | 必須 | Laravel標準タイムスタンプ      |

- `event_id`、`event_card_id`、`idempotency_key`をユニークにし、同一操作の二重消費を防ぐ
- 初投稿済み判定は`payment_type = initial_post`の存在で行い、2回目以降は投稿ごとに`score_update`を追加する
- 同じカードが次回イベントへ再登場した場合は、前回イベントの支払い履歴を参照せず、新しい`event_id`で初投稿コストを判定する
- 同一ユーザーによる同時投稿が発生しても、支払い履歴は1件だけ作成する

### 5.1.6 `trick_collection_rewards`テーブル設計

回収時のドローポイント配分を冪等にするため、配分結果を永続保存する。

| カラム                         | 型                    | 必須 | 用途                                        |
|-----------------------------|----------------------|----|-------------------------------------------|
| `id`                        | unsigned big integer | 必須 | 主キー                                       |
| `event_id`                  | unsigned integer     | 必須 | 配分が発生した大会ID                               |
| `event_card_id`             | unsigned big integer | 必須 | 対象`trick_event_cards.id`                    |
| `deck_id`                   | unsigned big integer | 必須 | 回収対象切り札                                    |
| `player_name`               | string               | 必須 | ドローポイントを受け取るユーザーID                           |
| `points_delta`              | integer              | 必須 | 加算ドローポイント                                    |
| `reward_type`               | string               | 必須 | `single_poster`、`rank_distribution`、`taker_remainder` |
| `created_at` / `updated_at` | timestamp            | 必須 | Laravel標準タイムスタンプ                          |

- `event_id`、`deck_id`、`player_name`、`reward_type`の組み合わせを重複させない
- 回収APIが再実行されても、既存配分を再加算しない

### 5.1.7 `records`テーブルと`trick_event_records`の扱い

- スコア投稿は既存の汎用`records`テーブルを利用する
- `records`へのカラム追加は行わず、イベント投稿の大会帰属は中間テーブル`trick_event_records`で管理する
- `trick_event_records`は`record_id`、`event_id`、`event_card_id`、`deck_id`とタイムスタンプを保持し、`record_id`をユニークにする
- 投稿受付時は`records.stage_id = decks.stage_id`を確認したうえで、現在`_field`の`trick_event_cards`行へ紐付ける
- ランキング、参加順、暫定ランクP、回収結果は`stage_id`だけで集計せず、必ず`trick_event_records.event_id`と`event_card_id`で対象大会を限定する
- 同じ`stage_id`を次回イベントで再利用しても、前回イベントの記録は次回ランキングへ混入しない
- 開催中イベントの対象ステージへ開催期間内に投稿された記録は、イベント外の記録取得・トレンド・新着・ピックアップ動画・ステージ別・比較・ユーザー別表示から除外する。`trick_event_records`に紐付いた記録は、投稿日時が開催期間外へ編集されても非公開とする。大会前の過去記録は対象外。公開判定は開始時刻以上・終了時刻未満とし、終了処理のstate更新を待たず終了時刻ちょうどで解除する。
- 記録の作成・編集・削除は汎用記録処理からイベント用ドメインサービスを呼び、記録更新とイベント副作用を同じサーバー処理内で一貫して実行する
- 投稿削除で有効記録が0件になったプレイヤーは現在ランキングと参加者数から外す。ただし初投稿順、0Pを含む支払い履歴、発生済み延長は保持し、再投稿時に再消費・再延長しない

### 5.1.8 `trick_card_holders`テーブル設計

ホルダーの所有権をイベント終了後も保存する。`event_id`、`deck_id`、`player_name`を保持し、共同1位の場合はプレイヤーごとに1行作成する。

| カラム                         | 型                    | 必須 | 用途                         |
|-----------------------------|----------------------|----|----------------------------|
| `id`                        | unsigned big integer | 必須 | 主キー                        |
| `event_id`                  | unsigned integer     | 必須 | ホルダーを獲得した大会ID             |
| `event_card_id`             | unsigned big integer | 必須 | 回収された`trick_event_cards.id` |
| `deck_id`                   | unsigned big integer | 必須 | 所有対象のカード本体                 |
| `player_name`               | string               | 必須 | ホルダーのユーザーID                |
| `created_at` / `updated_at` | timestamp            | 必須 | Laravel標準タイムスタンプ            |

- 回収時に1位グループ全員を登録する
- 投稿者0人の場合は行を作成しない
- `event_id`、`deck_id`、`player_name`をユニークにし、回収再実行で重複作成しない
- 1件以上存在するカードは`decks.state = '_held'`とし、以後のイベントのデッキ候補から除外する。管理者復帰機能は初期実装に含めない
- ホルダーなしカードは大会終了時に`decks.state = '_eligible'`へ戻し、付与済み`stage_id`を保持したまま次回イベントへ必ず投入する

### 5.1.9 `limit_logs`テーブル設計

行動ログと監査ログには既存の`limit_logs`相当のログテーブルを利用する。

| カラム                                             | 用途                                                                               |
|-------------------------------------------------|----------------------------------------------------------------------------------|
| `event`                                         | `join`、`draw`、`return_to_deck`、`take`、`record_posted`、`limit_extended`、`collect`、`subsidy_paid`など |
| `actor_name`                                    | 操作したユーザーID                                                                       |
| `card_id` / `stage_id`                          | 対象カード                                                                            |
| `event_id` / `event_card_id`                    | 同じカード・`stage_id`を複数大会で使う場合の大会内識別子                                               |
| `from_state` / `to_state`                       | 状態遷移                                                                             |
| `rank_points_delta` / `points_delta`            | ドローポイント変動                                                                           |
| `stacked_card_ids`                              | テイク時にトリックへ移動したカードID配列                                                            |
| `card_snapshot` / `player_snapshot` / `context` | デバッグ・監査用JSON                                                                     |
| `created_at`                                    | ログ表示順の基準                                                                         |

- `limit_logs`にはドローを含む監査対象の全行動を保存する
- 画面表示用ログと`GET /api/tricks/logs`は、ルール仕様どおりドローと手札返却を除外し、テイク、スコア投稿、給付、回収等の最新100件を返す
- 画面表示用ログDTOには必要なカード名・レア度・投稿時スコアと順位・回収時1位ユーザーIDを含める。回収時の同率1位は投稿日時が古い記録を表示名の代表とし、監査用contextや通信情報は公開しない
- 給付の監査ログは受給者ごとに保存し、画面表示用ログDTOでは同じ給付スロットのログを1件へ集約して受給者数を返す。表示文言は`{対象者数}人にドローポイントが給付されました。`とする

### 5.2 状態変更時のバックエンド処理

- 以下に該当する場合、または類似操作時は、現在大会の`trick_event_cards.state`を更新する
    - ドローされたとき（デッキ→誰かの手札）
    - テイクされたとき（誰かの手札→切り札またはトリック）
    - 回収されたとき（切り札→回収済み、トリック→捨て札）
- 同時アクセスに備え、参加・ドロー・テイク・投稿後更新・回収・給付金処理はDBトランザクション内で処理し、対象の`players`、`decks`、`trick_event_cards`行をロックする
- ポーリングで取得する状態は、サーバー側で正規化したスナップショットとして返す。クライアントは楽観的に確定状態を書き換えず、API応答または次回ポーリングで同期する

#### 5.2.1 大会開始・終了時のカード処理

- 大会開始時は、直前大会でホルダーなしとなった回収カードをすべて優先して含め、残りを`decks.state = '_eligible'`の他カードから補って160枚を選ぶ。同一トランザクションで`decks.state = '_in_event'`へ変更し、当該`event_id`の`trick_event_cards`を`state = '_deck'`で作成する
- `_eligible`が160枚未満の場合は大会初期化を失敗させ、不足した状態で開始したり`_held`カードを暗黙に補充したりしない
- `decks.state = '_held'`のカードは、以後のイベントのデッキ候補から除外する
- 大会内の状態遷移と結果表示は`trick_event_cards`に保持し、大会終了後も過去行を削除・再利用しない
- 回収カードにホルダーが1人以上いる場合は`trick_card_holders`を作成し、カード本体を`decks.state = '_held'`にする
- 投稿者0人でホルダーが存在しない回収カードは、大会終了時にカード本体を`decks.state = '_eligible'`へ戻し、次回イベントのデッキへ必ず含める
- 大会終了時、ホルダーを得なかったデッキ・手札・捨て札・トリック等のカード本体も`_in_event`から`_eligible`へ戻す
- ホルダーなしカードを次回イベントへ投入するときは新しい`trick_event_cards`行を作成するが、`decks.stage_id`は既存値を保持する
- 過去大会の`trick_event_cards`、`trick_event_records`、支払い、配分、ログは結果表示・監査用に保持し、次回大会の集計へ混ぜない

### 5.3 参加時のバックエンド処理

- `players`に対象ユーザーが存在しない場合のみ、参加者として作成する
- 新規参加者には5Pを付与する
- 新規参加者本人には後発参加ボーナスを付与しない
- 既存参加者全員へ、後発参加ボーナスとして1Pを付与する
- 同一ユーザーの重複参加を防ぐため、`players`の`event_id`と`name`をユニークにする
- ログアウトやページ離脱では`players`行を削除しない

### 5.4 ドロー時のバックエンド処理

- 大会開始時にデッキを160枚用意する
- ドローポイントが0P以下の場合はドローを拒否する
- レア度未確定のカードは、通常はコモン(C1)87%、アンコモン(U2)8%、レア(R3)4%、エピック(E4)0.9%、レジェンダリー(L5)0.1%で抽選する。大会終了3時間前以降はC1/U2/R3/E4/L5を`0/87/8/4/1%`に切り替える
- 現在大会のデッキにある全`trick_event_cards`から、難易度に関係なく各カード同じ確率で1枚を決定する。旧来の難易度抽選・不足難易度の重み再配分は廃止。レア度が未確定の場合だけ終了時刻に応じた上記確率でレア度を抽選・保存し、手札からの返却では保存済みレア度を維持する。捨て札をデッキへ補充するときはレア度をNULLへ戻し、次のドローで再抽選する。draw_countは捨て札への移動時と再循環時に0へリセットする。レア度を抽選したドローは1となり開封済みを表示しない。その後`state`をドローしたプレイヤーにする（＝手札として扱う）
- 成功テイク総数から`L = floor(sqrt(T))`を算出し、現在手札が`(L + 2) × 3`枚以上ならドローを拒否する。ロック取得後にも同条件を再検証する
- ドローによって`_deck`が0枚になった場合、そのドローと同じ大会行ロック・DBトランザクション内で全`_trash`カードを`_deck`へ戻し、`rarity`をNULLへリセットし、`stack_parent_id`を解除する。`draw_count`は0へリセットする
- 既存データなどでドロー開始時から`_deck`が0枚の場合も、同じロック下で全`_trash`カードを`_deck`へ戻してから抽選する
- ドロー成功時はプレイヤーのドローポイントを1減算し、`players.card_count`を現在大会の`trick_event_cards`実数に同期する

#### 5.4.1 手札返却時のバックエンド処理

- 操作ユーザーの手札であることと、ロック後の所持ドローポイントが1P以上であることを同一トランザクション内で検証する
- 対象カードを`state = '_deck'`、`drawn_order = null`に戻し、`returned_count`を1加算する。レア度、難易度、カード固有ID、`stage_id`は変更しない
- プレイヤーのドローポイントを1減算し、手札実数へ`card_count`を同期する。返却コスト1Pは大会単位のポットへ加算する
- 返却による一回限り給付は廃止。返却後の手札枚数 + 所持ドローポイントが3未満の場合だけ継続給付フラグを表示する
- `return_to_deck`監査ログは`context.public = false`として保存し、公開状態APIから除外する

### 5.5 テイク時のバックエンド処理

- まず、テイクできるか判定する
- テイクできる場合、現在大会の手札に対応する`trick_event_cards.state`を切り替える（選んだ手札は切り札として、それ以外はトリックとして扱う）
- サーバー側でも必ず以下を検証する
    - 対象カードが操作ユーザーの手札である
    - 操作ユーザーの成功テイク総数`T`から`L = floor(sqrt(T))`を算出し、手札が`L + 2`枚以上
    - 大会終了1時間前より前
    - テイク後の切り札数が`min(max(1, 累計参加者数 - 1), 16)`以下
    - `players.last_take_at`がnull、現在時刻が`last_take_at + 60分`以降、現在時刻が大会終了150分前以降、のいずれか
- 大会終了150分前ちょうどからクールダウンを免除する。ただし大会終了1時間前以降のテイク禁止、必要手札、切り札上限などは免除しない
- すべての切り札で1位になってもクールダウンを解除しない
- テイク成功時は、切り札の`taken_at`と同じ時刻を`players.last_take_at`へ保存し、`take_count`を1加算する
- 通常のクールダウン終了時刻は`last_take_at + 60分`とし、切り札への投稿、期限延長、早期回収、通常回収では変更しない
- 同時テイクによるクールダウンすり抜けを防ぐため、条件判定から`last_take_at`更新まで操作ユーザーの`players`行を同一トランザクション内でロックする

#### 5.5.1 シミュレーション上の締切直前行動

- 大会開始から47時間経過するとテイク不能になるため、シミュレーションではその直前（46時間59分59秒999999）に全参加者がテイクを試行する
- 必要手札枚数未満または切り札上限などの条件でテイクできない場合は、試行結果と理由をログへ記録する
- 複数人の試行順による固定的な有利不利を避けるため、試行順は乱数シードに基づいてシャッフルする
- テイク締切後は、新たなドローと手札練習を行動候補から除外し、残り時間を切り札への初回投稿・更新に使う
- テイクするカードは手札内の練習時間を優先して選び、同条件では無作為に選ぶ。レア度そのものは選択理由に使用しない
- 参加者数は、その大会に一度でも参加した累計参加者数とする
- 選択した`trick_event_cards`行は`state = '_field'`、`taker = user_id`、`stack_count = テイク直前の手札枚数`、`taken_at = 現在時刻`、`paid_points_total = 0`に更新する
- 対応する`decks.stage_id`が未設定の場合だけ、1001以上2000未満で`stages.stage_id`と`decks.stage_id`のどちらにも使われていない番号のうち最小値を払い出し、`stages`へステージ情報を作成して永続保存する。設定済みの場合は新規発行せず既存値を使用する
- 今回イベントの`stages`作成値は、`stage_sub = "期間限定チャレンジ"`、`type = "stage"`、`display = "int"`、`parent = 現在のevent_id`、`series = origin_stage_idの先頭1桁`、`time/treasure/pikmin/border1-4 = 0`とする
- 選択されなかった`trick_event_cards`の手札行は`state = '_stack'`、`stack_parent_id = 選択した大会内カードID`に更新する
- テイク時点で`limit_at = 現在時刻 + 60 + max(難易度 - 2, 0) × 20分`を設定する
- テイク直前の手札枚数 + 所持ドローポイントが5未満なら、成功したテイクと同じトランザクション内で1P即時支給する

### 5.6 記録投稿時のバックエンド処理

- 投稿された記録はカード本体の`stage_id`を使って記録投稿処理を行う。未発行カードは初回テイク時に払い出し、再登場カードは既存値を使う
- 開催中だけ、イベント記録を新着記録API（`/api/new`）とその利用先のピックアップ動画から除外する。終了時刻以降の取得では公開する。ユーザー別投稿数ランキング（`/api/count`）と年初来投稿総数（`/api/prev`の`posts`）には開催中も期間限定チャレンジの投稿数を含める。
- 投稿成功後、`records.stage_id = decks.stage_id`を満たし、かつ現在大会で`state = '_field'`の`trick_event_cards`を取得する。作成した`record_id`を`trick_event_records`へ紐付けてから、投稿数・トップ投稿者・リミットオーバー時刻・ドローポイントを更新する
- プレイヤー×切り札の`initial_post`履歴がなければ初投稿とする。非テイカーは0P、テイカーは難易度分を記録する
- `initial_post`履歴があれば2回目以降として、成功した投稿ごとに難易度分の`score_update`履歴を作成する
- 有料投稿ではプレイヤー行をロックして難易度分を減算する。投稿費にかぎり残高不足を拒否せず、負数を保存できるようにする
- 支払額は`trick_event_cards.paid_points_total`へ加算し、無料初投稿の0P履歴も参加順と初投稿済み判定のため保持する
- 1人目の初投稿は、投稿完了時の残り時間が15分未満なら30分、それ以外は15分延長する。2人目以降の初投稿は一律10分延長する
- 初投稿延長は費用の有無にかかわらず行い、同じプレイヤーの2回目以降の投稿では延長しない
- トリック数による制限時間ボーナスは設けない
- スコア投稿による即時ドローポイント還元は行わない
- ランクポイントは対象`event_card_id`に紐づく当該大会の有効投稿だけを集計し、参加者数`N`と順位`r`から`N - r + 1`、1位のみさらに1Rとして再計算する。トリック数と過去大会の同一`stage_id`記録は参照しない
- 同スコアは同順位グループとし、標準競技順位（例：1位・1位・3位）を順位`r`に使用する
- 投稿成功後の状態取得では、全切り札の暫定ランクポイントを再集計し、`players.rank_points`の確定分と合算して返す

### 5.7 回収時のバックエンド処理

- 短周期ポーリングまたは期限切れ一括回収APIにより、回収条件を満たしている切り札を回収する
- 回収対象は現在大会の`trick_event_cards`で`state = '_field'`かつ`limit_at`が現在時刻以前のカード、または大会終了時・即時回収時・管理者権限発動時の対象切り札とする
- 投稿者数によらず対象切り札を`_collected`へ更新する。紐づく`_stack`カードはいずれも`_trash`へ更新する
- 回収時の1位グループで1位記録を先に登録した1人を`trick_card_holders`へ保存する。投稿者がいない場合はホルダー、ドローポイント還元、ランクポイントを作成しない
- ホルダーの有無にかかわらず`decks.stage_id`は変更・削除しない
- `_collected`は当該イベント中にデッキへ戻さない。トリックなどの`_trash`だけがデッキ枯渇時の再シャッフル対象となる
- 回収時は最終順位の暫定ランクポイントを`players.rank_points`へ確定加算してから切り札を回収済みにする。状態取得時の暫定集計対象から外れるため、表示合計を二重加算しない
- 制限時間到達による自動回収では、還元とランクポイントを同一トランザクション内で即時反映し、回収ログを作成する。1位回収による一回限り給付は行わず、還元後の現在合計で継続給付フラグを再判定する
- 回収処理は`event_id`と`event_card_id`を単位に冪等にする。すでに`_collected`の大会内カードに対して再度回収APIが呼ばれても、ホルダー、ドローポイント、ランクポイント、回収ログを二重作成・加算しない

#### 5.7.1 総還元ドローポイント計算

- 支払ドローポイント総数は`trick_event_cards.paid_points_total`または同じ`event_id`・`event_card_id`の`trick_card_payments`合計から取得する
- `A = stack_count + paid_points_total`
- 投稿者1人以上では、総還元ドローポイントを`トリック数 + レア度別トリックボーナス + 投稿・任意延長の実支払い総数 + 今回移すポット`とする。`g=floor(トリック数/3)`としてレア度1〜5のボーナスは順に`0, g+1, g+4, 2g+7, 3g+15`。控除と難易度ボーナスは加えない
- 投稿者1人では総還元ドローポイント全額をその1人へ還元する
- 投稿者0人では0Pとする

#### 5.7.2 配分対象と配分計算

- 回収時点のランキングは、対象`event_card_id`へ`trick_event_records`で紐づく当該大会の各プレイヤーの有効な最高スコアで作成する
- 同スコアは同順位グループとして扱い、順位配分ドローポイントを同額にする
- 参加者数別の基底配分と1P単位の循環加算はルール仕様書4.4.2〜4.4.3に従う
- 同順位では占有する順位枠の配分を合算して均等配分し、割り切れない整数端数をテイカーへ全額別枠還元する（未投稿でも対象）
- 同順位内の均等配分は保持し、余り全額を`reward_type = taker_remainder`としてテイカーへ保存する。4人以下では最大3P、大人数同点ではこれを超えることがある
- 回収時の配分結果は`event_id`と`event_card_id`を含む`trick_collection_rewards`へ保存し、プレイヤーのドローポイントへ反映する
- 投稿者が1人以上でポット残高がある場合は、回収トランザクション内でポット全額を総還元ドローポイントへ加算してから通常配分し、ポットを0にする。投稿者0人ならポットを維持する

### 5.8 給付金処理

- 日本時間の毎時00分・30分に、手札枚数 + 所持ドローポイントが3未満の参加者へ1P給付する。切り札枚数・参加者数には依存しない
- 給付時点の残高と手札枚数を行ロック下で再判定し、合計3以上なら給付しない。負数も対象とする
- 表示用 `subsidy_flag` は開催中かつ現在合計3未満から算出する。旧永続フラグ・有効スロットは資格判定に使用せず、給付処理でクリアする
- テイクまたは無料初投稿の行動直前の合計が5未満なら、成功した処理と同じトランザクションで1P即時支給する。テイクは消費前の手札を含める
- 無料初投稿は既存の `initial_post` 支払い履歴を使って各参加者・各切り札1回に限定する。同じ保存通知の再送も初回・更新両方の冪等キーを照合し、支給と課金を重複させない
- 更新・削除後再投稿・有料投稿・練習・返却・1位回収による即時支給または旧一回給付は行わない
- 即時支給後に現在合計3以上なら表示フラグを外す。3未満なら次の定期給付対象を維持する
- `instant_subsidy_paid` を監査ログへ記録し、公開ログでは「{ユーザー}さんに1Pが即時支給されました。」と表示する
- 定期給付は大会の `last_subsidy_slot_at` とプレイヤーの `last_subsidy_paid_slot_at` で二重配布を防ぐ。スロット後の新規参加・状態変化で同じスロットを再処理しない


### 5.8.1 プレイヤーによる任意延長

- 対象切り札と操作プレイヤーを同一トランザクションでロックし、開催中・切り札・期限前・大会終了1時間前より前・残高1P以上を検証する
- クライアント生成の`idempotency_key`を必須とし、同じキーの再送は既存結果を返して再課金・再延長しない
- 1P減算、`paid_points_total`への1P加算、期限への15分加算、`player_extension`支払い履歴、公開ログを原子的に保存する
- 延長後の期限は大会終了時刻を上限とする。例外発生時はトランザクションをロールバックする

### 5.9 シミュレーションプレイヤーの行動モデル

- 全員に共通して、終了時に残るドローポイントと手札には効用を設定せず、テイク締切後のドロー・手札練習は行わない
- 各意思決定で、残り活動時間、テイク締切までの行動回数、将来のトリック数、予想投稿者数、腕前格差による予想順位、残ドローポイントの消費可能量を見積もる複数手先の予測モデルを使用する
- 予測上、終了までに消費しきれないドローポイントが多いほどドロー・初回投稿の価値を高く評価する。ただし、ランクPを減らしてまで無目的に消費する効用は与えない
- 全参加者は46時間59分59秒999999に活動セッション外でも締切直前テイクを1回だけ試行する。この時刻は案Bによりクールダウンを免除するが、必要手札と切り札上限は維持する。この試行以外の最後の1時間の行動は各自の活動セッションに従う
- 所要時間のある行動は、開始から完了までが同一の活動セッション内かつ大会終了前に収まり、対象切り札の既知の回収期限より前に完了できる場合だけ選択する
- 予約行動の対象が先に消滅した場合は同一時刻で意思決定を再予約し、失敗によって以後の行動連鎖を停止させない
- プレイヤーが所要時間のある行動中は別の意思決定を開始せず、複数行動を並行実行しない
- ドロー、テイクその他のUI操作時間は0分とし、同一時刻内で状態が変化する限り次の意思決定へ進む。シミュレーション上で時間を消費するのは期間限定チャレンジのプレイと手札練習だけとする
- テイク成功後60分間は、そのプレイヤーの次のテイクを行動候補から除外する。大会終了150分前以降は除外しない。全切り札1位による解除は行わない
- 初回投稿の期間限定チャレンジ時間はパーソナリティにかかわらず10〜60分とする。難易度1〜5の最低時間は10・15・20・25・30分とし、意欲係数による個人差を加える。パーソナリティは投稿先と行動目的の差にだけ使用し、期間限定チャレンジ自体の機械的な所要時間とは分離する
- プレイヤー×切り札ごとに、挑戦回数、更新回数、累計通常プレイ時間、直前の更新所要時間を保持する
- 更新は現在スコアより上の最も近いスコアを目標とし、目標スコア、自分の腕前係数、累計プレイ時間、練習効果から必要追加時間を逆算する。更新回数ごとに探索コストを加算し、次の更新時間は同じプレイヤー・切り札の直前更新より少なくとも5分長くする
- 各プレイヤーには大会を通じて一定の腕前係数`0.55〜1.45`を割り当て、`(累計通常プレイ時間 + 逓減後の手札練習時間) × 腕前係数`をスコア評価値とする
- 手札練習はテイクするまで回数上限なしで累積できるが、有効練習分は`60 × log(1 + 実練習分 / 60)`として長時間ほど追加効果を逓減させる
- 切り札への初回投稿は、予想ランクP、予想還元P、参加料、必要プレイ時間、テイカーの推定練習優位を合成した期待効用とパーソナリティ別の参加傾向から参加確率を求める
- 正統派：複数手先の予測ランクP、行動時間、終了時に無価値となるドローポイントを評価し、投稿・更新・練習・ドロー・テイクからランクP最大化に有利な行動を選ぶ
- 投稿優先派：未投稿の切り札がある間は、短時間で投稿できる切り札を優先し、できるだけ多くのゲームからランクPを集める。現在の全切り札へ投稿済みの場合は正統派と同じ予測行動を取る
- ネガティブ派：基本判断は正統派と同じだが、まず練習用として現在のテイク必要枚数を満たす手札を確保し、練習成果をテイク締切前に場へ出せる見込みがある場合は、ランクP以外の練習効用も高く評価する。総合順位は目的にしない
- トリック派：ランクPを目的にせず、手札14枚を目標にドローを続け、巨大トリックのテイクを優先する。テイク締切後は余剰ドローポイントを切り札への投稿に使う
- 切り札が0枚で、活動中のプレイヤーのうち誰か1人がテイクすれば循環を再開できる場合は、手札が最も多い1人が合意担当となり、パーソナリティよりテイクを優先する
- 初投稿のない切り札は難易度別の初期期限（60〜120分）で自然回収されるため、合意による強制初投稿は行わない
- 切り札のランクPは参加者数`N`を基準に`N - 順位 + 1`を付与し、1位にはさらに1Rを加算する。トリック数は使用しない

## 6. Laravel API設計

### 6.1 基本方針

- Laravel側のイベント専用APIは`laravel/app/Http/Controllers/TrickController.php`へ定義する
- Next.jsからは既存の`/api/server/[...query].js`プロキシ経由でLaravel APIを呼び出す。例：Laravel pathが`/api/tricks/state`の場合、フロントエンドからは`/api/server/tricks/state`を呼ぶ
- 認証ユーザーIDはNextAuthのセッションを基準にし、クライアントから送られた`userId`だけを信用しない
- 全APIはJSONを返す。失敗時はHTTPステータスと`message`を返す

### 6.2 取得系API

| Method | Laravel path                        | 用途              | 主なレスポンス                                             |
|--------|-------------------------------------|-----------------|-----------------------------------------------------|
| GET    | `/api/tricks/tournament`            | 大会情報取得          | `event_id`、`start_at`、`end_at`、`server_now`、`debug` |
| GET    | `/api/tricks/state`                 | 画面全体のスナップショット取得 | 大会情報、確定・暫定・合計ランクPと`take_count`・`take_level`・`take_cost`・`last_take_at`・`next_take_at`を含む参加者、切り札、自分の手札、デッキ枚数、捨て札枚数、ログ |
| GET    | `/api/tricks/players`               | ダッシュボード取得       | 参加者一覧、確定・暫定・合計ランクP、テイク回数・レベル・コスト                 |
| GET    | `/api/tricks/hand`                  | 自分の手札取得         | 手札カード一覧                                             |
| GET    | `/api/tricks/field`                 | 切り札取得            | 切り札カード一覧                                             |
| GET    | `/api/tricks/collected`             | 回収カード取得         | 指定`event_id`の回収カード、ホルダー一覧、再登場可否、大会別ランキング              |
| GET    | `/api/tricks/cards/{deckId}/scores` | 切り札ランキング取得       | 現在の`event_id`・`event_card_id`に限定した有効投稿ランキング、初投稿コスト支払い済みフラグ |
| GET    | `/api/tricks/logs`                  | ログ取得            | ドローを除外した最新100件の表示用ログ                               |

`/api/tricks/state`はポーリングの中心APIとする。初期値は2-5秒間隔を想定し、投稿直後・テイク直後などは即時再取得する。

- 取得系APIは状態変更を行わない。期限回収、給付、大会終了処理はmaintenance経路または運用ジョブで実行し、処理後に最新状態を再取得する

### 6.4 投稿APIとの連携

- 実際のスコア投稿は既存の`next/components/modal/RecordForm.js`から`/api/server/post`へ送る
- 投稿フォームには対象カードの専用`stage_id`を`stage_id`として渡す
- 投稿モーダルのステージ名は、ローカライズ辞書に存在しない場合、`stages.stage_name`またはカードタイトル由来の名称を表示する
- 汎用記録の作成・編集・削除処理は、対象`stage_id`が開催中の大会内カードに一致する場合、イベント用ドメインサービスを同じサーバー処理内で呼び出す
- クライアントから投稿成功後のイベント更新APIを追加で呼ばせない。記録だけ成功してイベント更新が欠落する状態や、更新API再送による二重延長を許さない
- `records`へのカラム追加は行わず、作成済み`record_id`を`trick_event_records`へ紐付ける

### 6.5 デバッグ・テスト認証

- 通常操作の本人IDはNextAuthセッションを正本とし、Nextプロキシが内部署名付きでLaravelへ渡す
- NextとLaravelの`TRICKS_INTERNAL_SECRET`には同じ値を設定する。ログインセッションがあるのにNext側の設定が欠ける場合は503を返し、未参加として誤表示しない
- `trick_events.pot_points`を追加する`2026_09_20_000000_add_pot_points_to_trick_events.php`は給付処理の残高調整より先に適用する。未適用では給付APIが500になる
- 給付APIの失敗時は画面へHTTPコードを表示し、初回のサーバー時計同期後に送信する。失敗後は30秒以上空けて再試行し、毎秒の失敗要求を防ぐ
- Playwrightの複数プレイヤーテストに限り、`test_mode`大会と有効なテスト署名の組み合わせでユーザー偽装を許可する。本番・通常デバッグ大会では無効にする
- 即時回収、時刻操作、fixture作成・削除は管理者またはテスト署名を必須とする
- 管理操作ではNextAuthのロールも署名対象に含め、Laravel側で管理者ロールを検証する
- `TRICKS_DEBUG`等の設定が欠落した場合はデバッグ無効を既定値とする

### 6.6 エラー仕様

| ステータス | 用途                                     |
|-------|----------------------------------------|
| 400   | リクエスト形式不正                              |
| 401   | 未ログイン                                  |
| 403   | 大会時間外、未参加、権限なし、デバッグ無効                  |
| 404   | 対象カードなし                                |
| 409   | 状態競合。すでに回収済み、手札でない、切り札数上限、クールダウン中、初投稿コスト支払い競合など |
| 422   | 入力値は正しいがルール条件を満たさない                    |
| 500   | 想定外エラー                                 |

- テイクAPIがクールダウン中のため409を返す場合は、レスポンスに`next_take_at = last_take_at + 60分`を含める。大会終了150分前以降は`next_take_at = null`として状態APIへ返す
- 任意延長の残高不足は422、回収済み・期限到達後・同時更新競合は409、大会終了1時間前以降の任意延長は403とする。投稿費の残高不足はエラーにしない

## 7. テスト工程

### 7.1 Playwright UI/APIテスト

- 各テストの`finally`で対象`event_id`配下だけを削除し、readbackで残存0件を確認する。既存の大会データを前提にしたり変更したりしない

- 現在のUI/APIテストでは以下を確認する

    - 参加時に5P付与され、自動ドローされない

    - 成功テイク回数0・1・4・9回でレベルが0・1・2・3、必要手札が2・3・4・5枚となり、テイク成功と同時に回数が増える

    - 全切り札で1位でもテイク制限を解除しない
    - 大会終了150分前ちょうどからテイク締切までクールダウン免除を適用し、それ以前は60分経過が必要になる
    - 終盤免除以外の理由ではテイク成功間隔が60分未満にならず、必要手札・切り札上限・テイク締切を常に維持する

    - 給付金タイミングで、手札枚数 + 所持ドローポイントが3未満のプレイヤーに1P給付される。合計5未満でのテイク・無料初投稿は成功時に1P即時支給する
    - 手札返却ボタンが場に出すとキャンセルの間に表示され、返却で1Pを消費し、0P以下では非活性になる
    - 手札返却後もレア度が固定され、再ドロー時に灰色のsquare-checkと「開封済み」が表示される
    - 投稿者0人の切り札本体は`_collected`でそのイベント中は除外し、トリックだけが捨て札となる

    - 任意延長は1Pで15分延長し、支払総額へ含まれる。同じ冪等キーの再送では二重処理せず、別操作では再度延長できる

    - 大会終了後は手札・デッキ・捨て札を描画せず、その大会の回収カード一覧とホルダー有無を表示する
    - `/limited/tricks`を開いたとき、Phaserのcanvasが表示され、描画済みピクセルを持つ
    - 同点順位が標準競技順位（1位・1位・3位）となる
    - 制御時計で60分、47時間、48時間、毎時00分・30分を自然待機せず再現できる

## 観戦モード（2026-10-07）

- ヘッダーのナレッジ隣にfa-usersの観戦ボタンを表示し、再クリックで解除する。未参加・未ログインでも観戦へ入れる。

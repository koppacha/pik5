# トリックテイキング制 シミュレーション仕様書

本ドキュメントは、`lab/tricks_rule_simulation.py`で実行するルール検証用シミュレーションの現行仕様を定義する。大会の正式ルールは`tricks-rules.md`を正本とし、本書には現実の参加者・時間・意思決定を近似するための仮定と、検証用モデル固有の処理を記載する。

## 1. 適用範囲と仕様の扱い

- シミュレーションはイベント進行、カード循環、ポイント経済、ランクポイント、行動停止の有無を検証するためのモデルであり、実際の参加者の行動を保証するものではない
- ルールと本書が矛盾する場合、正式な大会仕様には`tricks-rules.md`を優先する
- 本書の「現行モデル」は正式シミュレーターへ実装済みの仕様を表す
- 比較検証だけを行った候補は「未採用の検証候補」に分離し、現行ルール・現行モデルへ混入させない
- 廃止済みのドロー税は現行モデルに含めない。過去の税制差分は検討履歴であり、現行コードへ適用しない

## 2. 基本条件

| 項目 | 現行値 |
| --- | --- |
| 大会時間 | 48時間 |
| プレイヤー数 | 16人 |
| 初期山札 | 200枚 |
| 初期ポイント | 5P |
| テイク締切 | 終了1時間前 |
| テイク固定クールダウン | プレイヤーごとにテイク成功から90分 |
| 初回制限時間 | テイクから90分 |
| 2人目以降の初投稿延長 | 60分から5分ずつ逓減、下限5分 |
| 給付判定 | 30分ごと |
| 初回プレイ・手札練習 | 1回10〜60分 |
| UI操作時間 | 0分 |
| 待機後の再判定 | 5分後 |

- 開始日時は内部的にJSTの`2026-01-01 00:00`へ固定し、終了日時を48時間後とする
- 乱数は`--seed`で固定できる。プレイヤー行動用乱数と腕前用乱数を分離する
- 山札が空の場合は捨て札をシャッフルして再利用する

## 3. プレイヤー生成と活動時間

### 3.1 参加時刻

- 8人は開始0〜60分の間に参加する
- 残り8人は開始60分後から、最低2時間の活動を確保できる時刻までの間に参加する
- 各群の参加時刻はseedに基づく一様乱数で決定し、時刻順に`player_01`〜`player_16`を割り当てる

### 3.2 活動セッション

- 16人をガチ勢8人、エンジョイ勢8人に分ける
- 開始から6時間と、24〜30時間経過時の合計12時間をピーク帯とする
- ガチ勢はピーク帯の70〜100%を活動時間とし、8人のうちseedで選ばれた2人だけはピーク外にも断続的な活動セッションを持つ
- ピーク外活動は長大な連続稼働にせず、原則30〜120分の複数セッションへ分割して時間帯を分散する
- ガチ勢の総活動時間は最大28時間とする
- エンジョイ勢の総活動時間は2〜6時間とする
- 活動セッションは重複しないよう統合し、終了時刻を大会終了時刻以内に収める
- プレイヤーは活動セッション内でのみ意思決定し、時間を要する行動は開始から完了までが同じ活動セッションに収まる場合だけ選択できる
- 46時間59分59秒999999の締切直前テイク試行は全員共通の合理行動として、通常の活動セッション外でも実行する。ただし、大会終了までに少なくとも1人が初回プレイを完了できる時間枠がないカードはテイクしない

### 3.3 腕前

- 各プレイヤーへ大会中一定の腕前係数`0.55〜1.45`を割り当てる
- 同じ有効プレイ時間なら、腕前係数が高いプレイヤーほど高いスコアになる
- プレイヤー番号に由来する微小値を加え、モデル上の偶発的な完全同点を避ける

## 4. パーソナリティ

現行モデルでは以下の5種類を使用する。16人時の基準人数を、スタック派2人、ホルダー優先派2人、ネガティブ派2人、投稿優先派5人、正統派5人とし、seedごとに各人数を基準から±1人の範囲で変動させ、合計16人にする。

### 4.1 正統派

- 合計ランクPの最大化を目的とする
- 投稿、更新、練習、ドロー、テイクについて、現在の利益だけでなく残り活動時間と後続行動を含めた予測効用を比較する
- 予測上の利益がない場合でも、十分な手札があればテイク、必要手札へ届かなければドローして循環を維持することがある

### 4.2 投稿優先派

- 未投稿の場札をできるだけ多く埋めることを優先する
- 参加確率が15%以上の未投稿場札から、所要時間が短く予想ランクPが高いものを選ぶ
- 現在出ているすべての場札へ投稿済みの場合は正統派と同じ判断を行う
- 初回プレイ時間自体は他のパーソナリティと同じ10〜60分から生成し、多数投稿志向は投稿先と行動優先度で表現する

### 4.3 ネガティブ派

- 基本判断は正統派と共通だが、手札練習の効用を高く評価する
- まず現在のテイク必要枚数まで手札を確保し、締切前に練習済みカードをテイクできる見込みがある場合は練習を優先する
- 総合勝利そのものではなく、長時間の練習と個別ゲームでの上位獲得を重視する

### 4.4 スタック派

- 合計ランクPよりも巨大スタックによる場への影響を優先する
- 目標手札14枚を基準とし、残りポイントと意思決定回数から到達可能なスタックを予測する
- 締切までにテイクできなくなる場合は、目標未達でもテイクする
- 通常時の初投稿参加確率の下限は45%とし、テイク締切後は10%へ下げる。候補があっても一定確率で待機する

### 4.5 ホルダー優先派

- 各プレイヤーにseedで決まる24枚の好みカードを割り当てる
- 合計ランクPよりも、好みカードへ投稿して1位を獲得し、そのカードのホルダーになることを優先する
- 好みカードが手札にある場合は練習とテイクを高く評価し、場札にある場合は初投稿と首位奪取の更新を高く評価する
- 好みカードが現在の行動候補にない場合は正統派と同じ判断を行う

## 5. 意思決定モデル

### 5.1 行動候補

各意思決定では、次の合法な行動を生成する。

- ドロー：テイク締切前、1P以上を所持し、山札または捨て札がある場合
- テイク：必要手札数、場札上限、テイク締切を満たし、そのプレイヤーの直前のテイク成功から90分以上経過している場合
- 初投稿：未参加の場札に対し、プレイ完了が活動時間と回収期限に収まる場合
- 更新：参加済みの場札で上位スコアが存在し、必要な追加プレイを期限内に完了できる場合
- 練習：テイク締切前に手札があり、練習完了が活動時間と締切に収まる場合
- 待機：有効な行動がない、またはポリシー上選ぶ価値がない場合

### 5.2 未来予測

- 意思決定モデル名は`multi_step_forecast_v2`とする
- 意思決定のたびに残り活動セッションを走査し、所要時間のある行動を完了できる時間枠と、固定クールダウンを満たす将来のテイク可能時刻を見積もる
- 場札ごとの将来参加者数は、他プレイヤーの残り活動時間、パーソナリティ別参加傾向、予想ランクP、予想還元P、投稿費、所要時間、テイカーの推定練習優位から予測する
- 新規場札の参加者予測は大会終了までの総活動時間ではなく、テイクから初回90分の期限内に連続してプレイできる活動セッションだけを対象にする
- 初投稿の基礎参加傾向は、正統派68%、投稿優先派92%、スタック派28%、ネガティブ派52%、ホルダー優先派78%とする
- 参加確率はロジスティック関数で2〜98%に収める
- 行動価値には、予想ランクP、予想還元P、時間コスト、投稿費、将来のテイク価値を含める
- 初回投稿とスコア更新の時間コストは同じ尺度（`所要分 / 12`）で評価し、更新だけを残り活動時間で過度に軽く評価しない
- 終了時に残るポイントと手札の効用は0とし、残り活動時間が少ないほど、また保有ポイントが予想消費能力を超えるほどポイント消費の価値を高くする
- 将来のテイク価値とポイント消費能力は、残り活動セッション、テイク締切、直前のテイク時刻、90分固定クールダウンから算出できる将来の最大テイク回数を上限に評価する

### 5.3 手札過多の回避

- スタック派以外は、手札が`max(8, 現在のテイク必要枚数)`以上ならテイクを優先する
- テイク不能の場合は新たなドローを避け、投稿・更新等を選ぶ。代替行動もなければ待機する

### 5.4 場の行き詰まり解消

- 場札が0枚で、活動中の誰か1人がテイク可能なら、手札が最も多い1人が合意行動としてテイクする
- 同数の場合は残り活動時間、プレイヤー番号の順で担当を決め、複数人が同じ解消行動を重複しないようにする
- 初投稿のない場札はテイクから90分で自然回収されるため、合意による強制初投稿は行わない
- 同じプレイヤーは、テイク成功から90分が経過するまで次のテイクを行わない。自分の場札への他プレイヤーの初投稿や場札の回収による早期解除は行わず、場札の期限延長によってクールダウンも延長しない
- 予約した対象が回収済みまたは手札外になった場合は、その失敗を記録して同時刻に意思決定を再開し、不合理な行動停止を防ぐ

## 6. 時間とスコアのモデル

### 6.1 時間消費

- ドロー、テイクなどのUI操作は0分とする
- 時間を消費するのは初回プレイ、スコア更新、手札練習だけとする
- 0分行動は状態が変化する限り同一時刻に連続実行する
- 無限ループ監査のため、同一時刻の0分行動を512回までに制限する

### 6.2 初回プレイ

- 初回プレイ時間は10〜60分から決定する
- 難易度ごとの最低時間を、難易度1から順に10分、15分、20分、25分、30分とする
- 各プレイヤーに意欲係数`0.8〜1.2`を割り当て、同じ難易度でも投入時間に個人差を持たせる
- 正統派、投稿優先派、ネガティブ派、ホルダー優先派は、現在のスコアを上回るために必要な時間候補と、予想ランクPまたは好みカードのホルダー獲得効率を比較する
- スタック派は難易度最低時間から60分までの基礎乱数を使用する
- 現在の活動セッションまたは場札期限までの残り時間が60分未満の場合、難易度最低時間以上の完了可能な時間候補へ短縮して比較する

### 6.3 練習

- 1回の練習は難易度最低時間から60分で、テイク締切前なら回数上限なく累積できる
- 実練習時間を`p`分とした有効練習時間は`60 × log(1 + p / 60)`分とし、長時間練習の追加効果を逓減させる
- 練習中に対象カードが手札から失われた場合、その行動は無効として次の意思決定へ復帰する

### 6.4 スコア更新

- 現在スコアより上にある最も近いスコアを次の目標とする
- 目標スコア、腕前係数、有効練習時間、累計通常プレイ時間から必要追加時間を逆算する
- 更新回数ごとに5分の探索コストと、必要差の35%に基づく追加コストを加える
- 次の更新時間は、同じプレイヤー・場札における直前更新より最低5分長くする
- 更新に上限時間は設けないが、活動時間または場札の期限に収まらない更新は候補にしない

### 6.5 スコア式

- `スコア評価値 = (累計通常プレイ分 + 有効練習分) × 腕前係数 + プレイヤー固有微小値`
- シミュレーション内のスコアは実ゲーム固有の採点式ではなく、時間投入と腕前格差を比較するための共通評価値である

## 7. カードと場札の進行

### 7.1 ドローとレア度

- 初期山札は200枚で、ドロー時にレア度と難易度を付与する
- ★2以上は開始時10%から46時間時点100%まで`10 × 10^(t / 46)`%で指数増加する
- ★2以上の内訳は★2〜★5=`60%・30%・9%・1%`を維持する
- 難易度1〜5の比率は`54%・30%・10%・5%・1%`とする

### 7.2 テイク

- 必要手札数は`3 + テイク直前の場札数`
- テイク後の場札上限は`min(max(1, 累計参加者数 - 1), 16)`
- プレイヤーごとに、直前のテイク成功時刻から90分が経過するまで次のテイクを禁止する。初回テイクにはクールダウン前提を設けない
- テイク対象は手札内で練習時間が最も長いカードを優先し、同条件では無作為に選ぶ。レア度は選択理由にしない
- テイクすると手札全体をスタックへ移し、選択カードだけを場札とする
- 46時間59分59秒999999に全参加者を無作為順で並べ、活動セッション外でも締切直前テイクを1回試行させる。ただし90分固定クールダウンを含む通常条件は免除しない

### 7.3 投稿、制限時間、費用

- テイク時に90分カウントダウンを開始する
- 投稿順は投稿を開始した時刻ではなく、初投稿が完了した順に確定する
- 1人目と4人目以降はレア度と同額、2人目と3人目は0Pを消費する
- 1人目の初投稿では延長しない
- 2人目は60分、3人目は55分と、参加順が増えるごとに5分ずつ延長時間を減らし、13人目以降は下限5分とする
- 延長時間は参加順`k`に対して`max(5, 70 - 5k)`分とする
- 2人目以降の初投稿は費用の有無にかかわらず延長する
- スコア更新は延長せず、終了1時間前以降に完了した初投稿も延長しない
- 投稿はポイント不足でも可能で、残高はマイナスになりうる
- スタック数による制限時間ボーナスは加算しない

### 7.4 ランクPと回収

- ランクPは参加者数`N`と順位`r`から`N - r + 1`を算出し、1位へさらに1Rを付与する。スタック数は使用しない
- 場札の投稿・更新後は現在順位から暫定ランクPを再計算し、時系列・リーダー・状態スナップショットでは「回収済みの確定分 + 場札の暫定分」を表示する
- 回収時は最終順位の暫定ランクPを確定分へ移し、表示合計が二重加算されないようにする
- 期限到達時と大会終了時に、正式ルールと同じ回収、ポイント配分を行う
- 同点は同順位グループとして処理する
- 1位グループの全員をホルダーとしてカードに保持する。同率1位は共同ホルダーとする
- 投稿者なしで期限を迎えた場札はホルダーなしで回収し、ポイント還元とランクP付与を行わない
- クリエイターの属性と、ホールドしたカードの主観的・大会後の価値は現行モデルの成績計算に含めない

## 8. 終盤行動

- テイク締切後はドロー、テイク、手札練習を候補から除外する
- 残り時間は場札への初投稿と更新に使用する
- 終了時のポイントと手札には効用を与えず、消費可能なポイントを意図的に温存する戦略は採用しない
- 終了時に残る場札はすべて強制回収する

## 9. 出力と検証

### 9.1 出力

- `lab/outputs/tricks_simulation_<timestamp>.jsonl`へ全イベントと各時点の状態を出力する
- 同名の`_summary.json`へseed、方針、最終プレイヤー状態、30分スナップショット、固定テスト結果、不変条件違反を出力する
- 概要JSONへ回収時参加者数別のカード件数を出力し、0人・1人回収の再発を直接監査できるようにする
- ホルダー優先派について、好みカードのテイク数、投稿数、ホルダー獲得数をプレイヤー別に出力する
- 30分スナップショットにはポイント、ランクP、ドロー数、最大スタック、山札・捨て札・場札・回収数、場札の総還元ポイントを含める
- 結果HTMLはJSONLと概要JSONを読み込み、最新ログを既定表示し、過去ログをタブで切り替える

### 9.2 結果HTML

- プレイヤー情報のサマリーは概要に限定し、詳細は最終結果表へ分離する
- タイムラインは30分単位へ間引き、横幅を最大限使う静的SVG線グラフとして表示する
- プレイヤー経済の推移には総保有ポイント、総ランクP、時点ごとの場札の総還元ポイントを表示する
- カード循環の推移には山札、捨て札、場札、回収済み、手札を表示し、山札系列だけを切り替えるトグルを設ける
- 「最終結果」には全プレイヤーの終了時所持P、ランクP、ドロー数、テイク数、スコア投稿回数をランクP順に表示する
- 「回収カードの概要」には回収された全カードを回収時刻順に並べ、場札として出ていた総時間、スコア投稿総数、参加者数、レア度、難易度、スタック数、総還元Pを表示する
- 常時アニメーション、常時描画ループ、ポーリングは使用せず、ログ追加後に静的HTMLを再生成する

### 9.3 固定テストと不変条件

- 還元配分：単独投稿、最下位除外、同順位、テイカー端数
- レア度：開始率、指数増加、46時間ピーク、★2以上の内訳維持
- ランクP：参加者数基準、1位一律ボーナス、スタック数非依存、参加者範囲外の順位、単独参加2R
- 予測：終盤の残余ポイント損失、消費能力超過、非正ポイント
- 時間：初回10〜60分、難易度最低時間、練習逓減、更新時間の単調増加、腕前差
- プレイヤー構成：ガチ勢8人・エンジョイ勢8人、活動時間上限、5パーソナリティの人数範囲
- 参加ルール：2・3人目無料、動的必要手札、動的場札上限
- 制限時間：テイク時90分開始、1人目延長なし、60分開始逓減、5分下限
- ホルダー：単独1位と同率1位グループ
- 不変条件：絶対・動的場札上限、場札のスタック数3以上、時間行動の重複、締切後の禁止行動、同一時刻の無限行動を監査する
- テイク固定クールダウン：同一プレイヤーのテイク成功間隔が90分以上であること、投稿・回収による解除がないことを固定テストと不変条件で監査する

## 10. 未採用の比較候補

以下は比較検証済みだが、現行の正式条件とは異なる比較候補である。

### 10.1 比較済みの別制限時間

- 2人目以降の初投稿を20分、25分、30分ずつ固定延長する案
- 2人目を45分延長し、その後は参加者が1人増えるごとに5分ずつ減らして下限5分とする案
- スタック数が3を超えた分について1点につき5分を初回制限時間へ加える案
- 現行の60分開始逓減方式では、3人投稿時点の総制限時間は`90 + 60 + 55 = 205分`となる。採用前の30seed診断では、必要手札を満たす意思決定382回に対し、場札上限だけによるテイク阻害は3回（0.785%）で、すべて開始直後に発生し5分で解消したため、場札上限は変更していない

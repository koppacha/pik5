# 期間限定総合ランキングの過去成績欠落調査

最終確認: 2026-10-14 22:05 JST

ユーザー指示: 第19回の結果を `/total/4/151` に反映する前に、過去大会が表示されない原因と、過去のDB TRUNCATEの可能性を確認する。

## 確認結果

- 本番・ローカルとも `/total/4/151` は HTTP 200。SSR pageProps の posts/events はともに0件。
- このページは `EventResultController` の `event_results` を参照する。一般投稿の `records` を直接集計しない。
- 本番 `event_results` 全248件、ローカル294件。他カテゴリの成績は存在するが、「期間限定ランキング」は双方0件。
- 本番・ローカルとも第2〜18回の有効元記録（flg < 2）は3098件。第1回（151101）はステージ1001/1002が存在するが、当該ステージの投稿記録は0件。
- `LimitedEventResultService::recalculatePastLimitedResults(false)` を双方で実行。保存なしで、18大会を検査し、成績220件・ホルダー194件を生成可能。第1回は元記録がないため成績を生成しない。
- 旧 `EventResultCsvSeeder`（Git 693bd328）には `EventResult::truncate()` があった。現在のCSV294件には期間限定ランキングの成績が含まれない。この旧Seederを再実行すると、別処理で生成した期間限定成績が消える構造だった。
- 現在のSeeder（本番も同様）はTRUNCATEを行わず、ID衝突を検査してupsertする。2026-10-06の50236f1cで変更済み。
- 現状は旧TRUNCATE後のCSV再投入と整合するが、実行日時・実行者・コマンドは未特定。binlog/実行履歴による断定はしていない。ユーザーからセッションログ閲覧指示がないため `docs/codex-logs/` は読んでいない。

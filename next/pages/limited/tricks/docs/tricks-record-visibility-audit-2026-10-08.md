# イベント記録の外部公開制御確認（2026-10-08）

## ユーザー指示

イベント開催中に投稿されたイベント対象ステージの記録が、今月のトレンド、年初来最多投稿ステージ、新着順一覧、ステージ別ページ、比較ページ、ユーザー別ページなどイベント外部から参照できないことを確認してください。ただし、ユーザー別投稿数ランキングと年初来投稿総数には期間限定チャレンジの投稿数を含めてください。
イベント外部からの参照禁止措置は、イベント終了の瞬間に解除されます。

## 調査結果と修正

- 共通の非公開フィルターがなく、汎用記録一覧・詳細・履歴・ステージ・ユーザー取得に参照漏れがあった。新着・トレンドの`stage_id < 1000`による一律除外は、終了後も解除されない実装だった。年初来投稿総数も同条件により期間限定投稿を含めていなかった。
- `Record::publiclyVisible()`を公開経路へ適用。開催中のイベントリンク、および対象ステージへ開催期間内に投稿された記録をSQLで除外する。リンク済み記録は投稿日時を変更しても非公開。大会前の既存記録は公開を継続する。
- 公開制御は`start_at <= eventClock < end_at`。`state`や`ended_at`、スケジューラーの最終集計完了を条件にせず、終了時刻の瞬間で解除する。デバッグ大会は`TrickClock`と同じ時刻判定を使う。
- 新着・月別最多・年初来最多ステージは公開scopeを適用し、終了後の期間限定ステージも対象にする。動的ステージ名を返し、名称未定義による表示エラーを防ぐ。
- ユーザー別投稿数ランキングと年初来投稿総数にはscopeを適用せず、後者のステージID制限を解除して期間限定記録を含める。
- ステージ・ユーザー・総合のISRをSSRへ変更し、比較・記録詳細とともに共有HTMLキャッシュを無効化。参加者数・推薦のキャッシュキーに開催中イベントの集合を含める。更新ボタンはSSRページをISR再検証せず再読み込みする。
- 非公開記録の編集前確認は、認証後のNext投稿API内でパラメータ化したPrisma SQLから最小限の属性を取得し、既存の編集権限判定を維持する。公開APIを迂回してブラウザへ記録を返す経路は追加していない。

## 検証

- `php artisan test --filter='TrickRecordVisibilityTest|TrickPhaseThreeTest|UserTotalControllerTest'`：16件合格。SQLiteインメモリで実行し、既存DBのリセット・投稿・シードを行っていない。
- 追加テストは公開一覧、新着の通常／差分取得、ステージ／ユーザー／全投稿カテゴリ、詳細404、履歴、トップ記録、順位、参加者数、月別／年初来最多、投稿数ランキング／投稿総数、大会内ランキングを検証。終了1秒前と終了時刻ちょうど、最終集計前、デバッグ時計、開始／終了時刻の投稿、日時を遡らせたリンク済み記録も確認した。
- 稼働中ローカルDBの読み取り照合：開催中イベント1件、該当記録15件、公開scopeへの漏れ0件。値・記録内容・認証情報は出力していない。
- Playwright：`/stage/1101`と`/total/10`は表示成功・エラーオーバーレイなし。ステージの外部記録APIは200／記録0件。架空ユーザー・比較・無効記録IDは404。各変更ページのCache-Controlは`no-store, must-revalidate`。認証なしの投稿APIは401。
- 変更したNextページ・API・表示コンポーネントのlint：エラー・警告なし。変更差分の空白チェックも合格。
- 開発ブラウザには補助リソースの404があり、公開制御の判定とは別。ページの構文エラー・表示オーバーレイは確認されなかった。

## 留意事項

- 確認・修正はローカル環境。本番デプロイは実施していない。
- 公開制御は終了時刻以降の取得で即時解除する。既に開いている画面の再取得タイミングは、その画面の既存の再読み込み／SWR設定に従う。
- SSR化により対象ページはリクエスト時に取得する。常時の追加ポーリング、canvas描画、アニメーションは増やしていない。
- 既存の作業差分を保持し、コミット・マイグレーション・本番DB変更は行っていない。

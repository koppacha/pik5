# 仕様書・ユーザーマニュアル・実装の整合性調査

調査日：2026-10-08（JST）

ユーザー指示：仕様書、ユーザーマニュアル、実装それぞれでいずれかにしか盛り込まれていない仕様がないか洗い出す。

## 対象と判定方法

- ルール仕様書：`tricks-rules.md`
- システム設計書：`tricks-system.md`
- 現在のMarkdownマニュアル：`next/pages/keyword/tricks-manual.md`。以前の `docs/tricks-manual.md` は存在しない。
- 画面上の別案内：`next/public/limited/tricks/limited_19_manual.pdf`。「遊び方」で開くPDFとナレッジで開くMarkdownは別の資料。
- LaravelのTricksサービス・コントローラ・記録公開scope、Nextの大会画面・コンポーネント。
- シミュレーション仕様・実装は補足確認。

以下の表では「仕様」は原則ルール仕様書を指す。システム設計書にだけある事項は、その旨を明記した。説明対象が異なるだけの省略と、競技上の意思決定を変える欠落・矛盾を分けた。現行作業ツリーを対象とし、実装・既存仕様・既存マニュアルは変更していない。

B3の160枚確保、優先札が160枚を超える場合の初期化失敗などは運用向け詳細であり、一般ユーザー向けにはカードの所有・再登場の説明まででよい。

## 3. 実装にあるが境界ルールが未定義の事項

### C1. 未処理の00分・30分スロットに対する、後から参加した人の徴収

- 仕様3.1とマニュアル7章には「給付時刻より後に参加した場合、次の給付から対象」とある。徴収について同じ参加日時制限を適用するかは明記されていない。
- `TrickSubsidyService.php:52` は給付ループで `created_at > slot` を除外する。一方、同96行からの徴収ループには同じ除外がない。
- 架空データで、スロットの1分後に参加したLv.0・残高20Pのプレイヤーを含め、そのスロットを初めて処理すると19Pになった。参加前の時刻に対応する徴収が行われる現行挙動を再現した。
- これは既に明文化された徴収規定との直接矛盾とまでは断定できない。過去スロットの徴収対象・処理が遅れたときの扱いを決める必要がある。裁定補償による免除も同じ徴収ループで消費されるため、免除の「次のタイミング」の定義と合わせて確認する。

### C2. 管理者が難易度を変更した後の費用・期限

- 仕様・マニュアルにはルール変更ができることはあるが、難易度変更後の経済条件・期限の扱いをまとめた説明がない。
- `TrickRulingService.php:69` は大会内カードの難易度を更新する。以後の有料投稿は新難易度の費用となる（`TrickRecordService.php:110`）。既存支払いと既存期限は巻き戻し・再設定しない。
- 「変更後の投稿から新費用、過去支払いは維持、既存期限は変更なし」を追記すれば裁定の効果が明確になる。本文変更が他大会でも使うカード本体・投稿先ステージへ反映される点は運営向け設計書に記載すればよい。

## 4. 別の案内・設計書に残る矛盾

### D1. 画面の「遊び方」PDFがMarkdown・現行実装と一致しない

`index.js:683` は元の `limited_19_manual.pdf` を表示する。ナレッジと単独ページは現在のMarkdownを表示するため、ユーザーが読む資料によって説明が変わる。システム設計書では元PDFを使うこと自体を明示しており、意図しないファイル参照と断定しない。内容の整合性は別途必要。

PDFの文字抽出で確認した具体的な差異：

| 項目 | 元PDF | 現行ルール・Markdown・実装 |
|---|---|---|
| 定期給付 | 手札＋Pが8以下 | 3未満 |
| 徴収対象 | 手札＋Pが一定以上、ボーダーと同じ値 | Pだけが `(L+2)×5` を超える場合 |
| 終了1時間前以降の給付・徴収 | なし | 大会終了まで定期処理を継続 |
| 緊急補充 | 全員の資源が3以下 | 全員が3未満 |
| 最下位への還元 | 常に0 | 1人投稿なら全額、2人の基底は3P／2P。同点枠を均等に分けるため、3人以上でも同点の最下位が正の配分を得ることがある |
| 開封済み | 誰かが一度引いたカード | レア度を保持した手札返却後の再ドロー。捨て札化でリセット |
| 用語 | スタック、場札、ポッド等 | トリック、切り札、ポット |

PDFの表彰一覧にはトップテイカー、トップクリエイターもあるが、ルール仕様書にはない。表彰条件の根拠として使うなら正式なルールへ移す必要がある。

### D2. システム・シミュレーション仕様の旧記述が残る

- `tricks-system.md:83` は旧給付「空場・資源8未満・一回フラグ・途中適用禁止」を残している。冒頭の新条件で置き換えを宣言しているため、現行の追加ルールとしては扱わない。ただし複数の場所を読まないと優先関係が分からない。
- `tricks-system.md:55` は総還元表示をトリック＋支払いだけと説明し、現行のポット加算先の例外を含まない。271行と末尾追補では現行式を説明する。
- `tricks-simulation.md:108` は「本番用の端数規則は未確定」と残すが、ルール仕様書・現在のPHP/Python実装ではテイカー還元が確定している。日付別の過去検討記録と現行仕様を分離すべき。
- Pythonシミュレーターには過去案の比較オプションも残る。`--remainder-policy` の既定値は `taker`、`--reward-formula` は `proposal`。比較オプションの存在だけを実装漏れとは判定しない。

## 5. 三者一致・目的上の省略

次の主要ルールはルール仕様書・Markdown・現行実装を照合し、一致を確認した。

- 参加5P、後発参加者1人につき既存者1P、初期自動ドローなし。
- ドロー／返却各1P、手札上限 `(L+2)×3`、必要手札 `L+2`、レベル `floor(sqrt(T))`。
- テイク60分間隔、終了150分前から免除、終了1時間前に締切、切り札上限最大16。
- 難易度別60／60／80／100／120分、初投稿の15／30／10分延長、任意延長1P・15分。
- 非テイカー初投稿無料、有料投稿の負数残高許容、削除後も初投稿履歴と費用を保持。
- スコア1〜999999、標準競技順位、`N-r+1` と1位追加1R。
- 定期給付3未満、即時給付5未満、徴収Pの閾値、ポット原資。
- レア度通常／終盤確率、レア度ボーナス、返却時の保持と捨て札化時のリセット。
- 投稿0人の還元0・既存ポット保持、同順位均等分配と端数のテイカー還元、暫定Rと確定Rの二重加算防止。
- 裁定リセット、5P補償、徴収1回免除、再投稿有料、履歴維持。
- 観戦中の操作禁止、大会終了時の全切り札回収、残P／手札のR変換なし。

以下は一般ユーザー向けマニュアルに全文を載せなくても欠落ではない。

- stage_idの割当範囲、DBカラム、トランザクション・ロック順、冪等キー、署名・管理者認証、デバッグ時計。
- 配分ループの具体的な走査順。ルール仕様書と実装にはあるが、マニュアルは分配の考え方と例に要約している。
- 観戦演出の秒数、CSS色・配置、描画負荷制約、ポーリング・キャッシュの詳細。
- 管理者統計の具体的な集計方法。現在は実装が主な根拠なので、運営向け設計書へ補足するのが適切。

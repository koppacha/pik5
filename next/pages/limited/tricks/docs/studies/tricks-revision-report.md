# 追加改修・検証結果（2026-09-09）

## 結論と実装範囲

- 投稿済みチェック、現在無料の「無料！」、空場給付`手札 + P < 8`、テイク必要手札`3 + floor(場札数 / 2)`を実装した
- 1人目が残り45分未満で投稿した場合の45分延長と、その札の後続延長40・35・30…分を採用した。終了1時間前以降・更新・削除後再投稿による延長は禁止のまま
- 初回テイクだけ3枚にする案は検証のみ。初テイクの機会を増やす効果はあるが、枯渇防止が保証されず、今回は実装していない
- 200枚は再利用前提でも枯渇しうる。通常モデルの改修後は100試行中1試行。さらに、全員が貯め込む合法手順では200枚すべてが手札になる

## 実行条件・測定方法

16人・48時間・200枚、seed 275000〜275099、6条件で計600試行。手札返却と現行A+Bクールダウン解除を有効にした。各条件で活動時間・参加時刻・カード嗜好の初期乱数seedを揃えたが、行動の分岐後の乱数消費は一致しない。実装と同じPHPを実行するモデルではなくPython近似モデルである。

再現コードは[tricks_revision.py](tricks_revision.py)、全seed結果と実行対象ソースのSHA-256は[tricks-revision-results.json](tricks-revision-results.json)。実行元は`lab/tricks_rule_simulation.py`。ソースの照合と全600試行の不変条件違反0件を確認した。

```sh
python3 docs/studies/tricks_revision.py
python3 docs/studies/tricks_hoarding_check.py
```

上記は`next/pages/limited/tricks`から実行する。比較スクリプトはソース内の投稿延長部分を読み込み時に置き換えるため、将来その実装が変わったら置換対象とSHAを再確認する。

- 平均場札数：48時間全体の時間積分。過去の「全員参加後平均」とは異なる
- 平均スタック：その試行でテイクされた札のスタック数平均。場札本体1枚を含む
- 同時枯渇率：山札と捨て札の合計が0になった試行数 / 100。捨て札のシャッフル実行率ではない
- 拘束枚数：全手札 + 各場札のスタック数。本体を二重加算しない
- 利用不能枚数：200 − 山札 − 捨て札。拘束枚数に、回収され再利用されない場札本体も加わる
- 空場率：少なくとも1人が活動中の時間に占める空場時間。各活動セッション境界も積分する
- ドロー不能時間率：活動中かつ正残高のプレイヤーがいる時間のうち、山札・捨て札がない時間を、少なくとも1人が活動中の総時間で割る。ドローしたいという意思の実測ではない
- `shortage`は失敗ドロー試行数だが、モデルが空の山札へのドローを選択肢から除外するので0でも不足なしとは解釈しない

## 200枚と通常進行の比較

「改修前」は必要手札`3 + 場札数`、空場給付は改修直前仕様の`P < 累計参加者数`、1人目延長なし。「手札・給付のみ」は今回の手札式と8閾値、「採用一式」はそれに延長緩和を加えた条件である。全条件で調整後のパーソナリティを使う。

| 指標 | 改修前 | 手札・給付のみ | 採用一式 |
| --- | ---: | ---: | ---: |
| テイク数 / 48時間 | 44.24 | 51.13 | 50.99 |
| 平均スタック | 7.30 | 6.00 | 6.05 |
| 平均場札数 | 3.41 | 3.82 | 3.88 |
| 初投稿数 / 48時間 | 172.03 | 188.63 | 190.67 |
| 活動中の空場率 | 1.347% | 1.437% | 1.361% |
| 終了時の全員所持P合計 | 294.56 | 281.41 | 282.83 |
| 山札・捨て札同時枯渇 | 10 / 100 | 2 / 100 | 1 / 100 |
| 同時枯渇時間（全試行平均） | 4.25分 | 0.64分 | 0.19分 |
| 同時枯渇時間（最悪試行） | 90分 | 49分 | 19分 |
| 最大拘束枚数（全試行最大） | 183 | 160 | 147 |
| 最大利用不能枚数 | 200 | 200 | 200 |

改修後は平均場札・投稿機会が増え、終了残高合計は改修前より約4.0%低い。ただし終了残高だけで全期間の通貨流通量や個人間の公平性を証明したわけではない。

拘束枚数が200未満でも、回収済みの本体は捨て札へ戻らないため、利用不能枚数が200へ達する。採用一式のドロー不能時間率は0.00043%、同時枯渇の発生率は1%だった。この二つを混同して「1%の時間停止」としない。100試行は安全保証には不十分である。

### 全200枚が手札になる到達例

[tricks_hoarding_check.py](tricks_hoarding_check.py)で正式モデルの参加・ドロー処理を実行した。

16人が最初の16分間に参加し、テイクしないまま20分時点で全Pをドローに使う。参加時5Pと後発参加ボーナスだけで、発行量は`16 × 5 + (0 + 1 + … + 15) = 200P`。結果は手札200枚、山札0、捨て札0、場札0、不変条件違反0。30分の新給付では3人が1Pを得るが、引けるカードはない。

これは通常の参加行動を予測する例ではなく、ルール上到達できる反例である。テイク・返却による解消の余地はあるものの、全員が不在・貯め込み継続なら自然回収すべき場札もない。給付閾値や必要手札数だけでは回避できない。カード追加やスタック解放時点の変更は今回の指示範囲では実装していない。

## 45分延長を意図的に狙う比較

未投稿札への1人目投稿を、可能なら残り44分付近まで遅らせる。元のプレイ所要時間は短縮せず、待機を練習時間として加算しない。同じ活動セッションで期限内に完了できる場合のみ行う。全員がこの選択を試す強めのストレス条件である。

| 指標 | 延長なし・通常 | 延長あり・通常 | 延長なし・意図的待機 | 延長あり・意図的待機 |
| --- | ---: | ---: | ---: | ---: |
| テイク数 | 51.13 | 50.99 | 50.28 | 53.67 |
| 平均場札数 | 3.82 | 3.88 | 3.63 | 3.62 |
| 初投稿数 | 188.63 | 190.67 | 175.55 | 183.80 |
| 空場率 | 1.437% | 1.361% | 1.199% | 0.688% |
| 同時枯渇試行数 / 100 | 2 | 1 | 0 | 1 |
| 1人目45分延長数 | 0 | 5.46 | 0 | 32.47 |

待機行動同士の比較では、延長によるテイク増加6.74%、平均場札変化−0.13%。通常行動・延長ありに対する意図的待機は、テイク+5.26%、平均場札−6.66%。ドロー不能時間率の悪化も0.03ポイント未満で、事前判定基準（テイク・場札25%、空場・不能時間5ポイント）以内だったため採用した。

ただし、延長を狙った待機は通常行動より投稿総数を約3.6%減らす。ルールを無条件に改善する戦略ではない。延長の累積は通常なら2人まで60分、3人まで115分。特例なら85分、120分となるため、2人段階では+25分、3人段階では+5分で、常に一律45分長くなるわけではない。

初めて共有する機会の拡大には有効な候補。初テイク待ち時間は未経験者を除く条件付き平均なので、全員の待ち時間短縮とは断定しない。供給増加と枯渇4試行を考慮し、200枚の余裕を重視する今回の実装には加えていない。1件対4件の差だけで統計的に悪化を確定したものでもない。

## パーソナリティの検討

正統派の得点志向、投稿優先派の広く遊ぶ志向、スタック派の大きい場を作る志向、ホルダー派の好み札への執着、ネガティブ派の練習志向は維持した。一方、一律の余剰返却や完全な得点最適化は実態を狭めるため、私的嗜好・共有魅力と、限定的な練習→返却→他者テイク後の狙い撃ちを導入した。

採用一式では作戦返却が平均1.02回、対象札への投稿・更新候補の選択が0.05回 / 大会。返した札が再登場し、他者が選び、本人が活動中である必要があるため、仕込みの多くは実現しない。成功率や強さを実証したとはいえず、極端な独自性志向が多い集団への外挿はしない。

## 影響・適用手順・テスト

仕様追記→旧記述との整合確認→Laravelの給付・テイク・投稿・stateとフロントの影響調査→実装→テストの順に実施した。

- 給付：空場給付をその時点の合計資源で判定し、一回給付の永続フラグと分離。ドローはPから手札への交換なので合計を減らさず、継続給付を再開させない
- 延長：`2026_09_08_210000_add_late_first_extension_to_trick_event_cards.php`のマイグレーションが必要。ローカルでは適用済み。本番には未適用
- 途中導入：旧版の永続給付フラグは由来を区別できない。大会開始前に適用し、進行中の大会へ無調整で適用しない。既得の行動給付を自動消去する移行処理は行っていない
- Laravel：Tricks関連47テスト成功。45分境界、終盤禁止、後続40/35分、投稿削除・再投稿、閲覧者別マーク、給付8境界・冪等性を含む
- シミュレーター：固定54チェック成功、600試行の不変条件違反0、全200枚拘束の到達例成功
- フロント：変更2ファイルのNext lint成功。合成APIのPlaywright表示・ポーリング追従を確認。実認証・実DBを使うフルE2Eは今回実行していない
- 描画負荷：静止30秒間でcanvas 2枚、GameObject 5個、DOMカード3枚、DOMノード112個は不変。Phaser描画回数は1→1、ループsleep、演出RAF・タイマー0を維持。state取得だけ2→12回（既存3秒ポーリング）となり、state変更回数は1のまま。破棄時の既存`destroy(true)`・タイマー解除も静的確認した

画面確認ではマークの色を濃くして白背景のコントラストを改善した。PC前提の既存レイアウトは維持し、スマートフォン幅では従来のログ重なり・ヘッダーの横方向制約が残る。新たな常時描画ループやポーリングは追加していない。

# レベル型テイクコスト検証（2026-09-09）

## 結論

公開レベルを導入するなら、この比較の中では`k=2`、すなわち「成功テイク2回ごとにレベルを1上げ、必要スタックを`M=L+2`」が最も均衡している。ただし現行よりテイク数が10.4%、平均場札数が9.0%増えるため、このままの採用は推奨しない。

`k=1`は上昇が急すぎる。高レベル者の終盤スタックとドローが増え、山札・捨て札同時枯渇も3/100試行になった。`k=3`・`k=4`は枯渇を悪化させにくい反面、コストが低すぎて場札連動のスケーリングをほぼ失い、テイク・場札数を13〜14%増やす。現行の場札数式を置き換える確かな利点は、このモデルでは得られなかった。

よって、正式ルール・Laravel・UIは変更していない。レベルを採用するなら、公開進行の見やすさを主目的にし、`k=2`を出発点として「場札数が多いときの最低コスト」を別途組み合わせて再検証すべきである。

## 前提と式

仕様書の正式現行は、初回を含め`3 + floor(テイク直前の場札数 / 2)`である。依頼文にある「初回だけ3固定」は現行仕様書と一致しない。なお、場札0枚で初回テイクを行う通常の開始局面では、どちらも3枚になる。

レベル候補では、成功済みテイク数を`T`、レベルアップ間隔を`k`として、テイク直前の公開レベルと必要スタック数を次で定義した。

```text
L = 1 + floor(T / k)
M = L + 2
```

最初のテイクは全候補で`L=1, M=3`。成功したテイクの直後にレベルを更新し、次回テイクから新コストを使う。比較した候補は`k=1, 2, 3, 4`である。

## 実行条件

16人・48時間・200枚、seed 276000〜276099、各候補100試行。空場給付`手札+P<8`、手札返却、投稿延長、案A+Bクールダウン解除を有効にした。活動時刻・嗜好・カード分布は同じseedから生成するが、ルール差で行動分岐後の乱数消費は一致しない。Pythonモデルであり、実利用者の行動を予測するものではない。

ユーザー平均はテイク0回の参加者も16人で割る。時間帯スタックは、その時間帯に成功したテイクのスタック数を平均したもの。`min_available`は山札＋捨て札の試行内最小値の100試行平均、同時枯渇はこの合計が0になった試行数である。

再現用コードは[tricks-level-study.py](tricks-level-study.py)、全500行の結果は[tricks-level-results.json](tricks-level-results.json)。結果ファイル内のSHA-256は、実行した`lab/tricks_rule_simulation.py`と一致確認済みである。

```sh
# 100 seedを一度に実行できる環境
python3 docs/studies/tricks-level-study.py --runs 100

# CLIで任意の候補を単発確認
python3 ../../../../lab/tricks_rule_simulation.py --summary-only \
  --take-cost-mode level_linear --take-level-up-every 2
```

## 現行の観測

現行のユーザー平均は、ドロー22.06回、テイク3.23回、テイク時スタック5.95枚だった。スタックは時間帯別に前半0〜12時間4.93枚、12〜24時間5.16枚、24〜36時間6.71枚、36〜47時間6.12枚となり、少なくとも中盤以降は明確に増えている。

テイク順でも1回目4.71枚、2回目6.04枚、3回目6.42枚、4回目6.53枚、5回目6.33枚、6回目以降6.83枚だった。したがって、現在の場札連動式とドロー・クールダウン・行動選好だけでも「後のテイクほど大きくなりやすい」動きがある。レベル式はこの自然な増加を、場の規模ではなく個人の成功履歴に固定する変更になる。

`k=1`は、テイク回数の少ない参加者でもすぐ4、5、6…枚を要求する一方、スタック派などがコスト到達まで手札を貯めるため、終盤に7.38枚まで増えた。必要数を強めても、必ずしもスタックやドローが減るわけではない。

`k=2`は初回・2回目が3枚、3・4回目が4枚となる。現行より初期コストは低いが、複数回テイクした人には上昇が見える。平均スタックは7.2%減り、終盤は現行とほぼ同水準まで戻る。一方でテイク数と場札数は増える。

`k=3`・`k=4`は、参加者の多くがレベル1〜2のまま終わる。公開レベルを持たせても、実質的には低い固定コストに近い。後半スタックを抑える効果はあるが、供給増加との交換が大きい。

### 判断

「16人後」の分母は、各試行で累計参加者数が16人に達してから大会終了までの実時間である。100試行の平均は407.88分で、表の分数は各試行の該当時間を平均したもの。全イベント48時間を分母にした値でも、全時間の指標として別に示している。

空場は増えていない。ポイントも、活動者が実際に持つ時間加重残高は約1%増にとどまり、少なくともこの100試行では急なインフレ・デフレとは呼べない。ただし終了時残高、給付、回収還元は上向いており、テイク増加に伴うポイント流通量の増加はある。

一方、場札の80%以上を占める時間は全時間で7.12ポイント、16人揃った後で6.27ポイント増えた。事前の5ポイント基準を超えるため、「上限への張り付きが目に見えて増える」変化として扱うべきである。上限ぴったりの時間も増えるが、48時間の大半で張り付く状態ではない。

「山札＋捨て札同時枯渇」は、山札0枚かつ捨て札0枚であり、捨て札のシャッフル再利用もできず、ドローが不可能な状態を意味する。`runs_no_available`は、この状態を試行中に一度でも観測した試行数である。山札だけが0で捨て札を再利用した回数ではない。

同時枯渇は依然として稀で、正残高の活動者を実際に止めうる時間は0.026%にとどまる。しかし悪化方向であり、ゼロではない。k=2の3枯渇試行では、利用可能カード0の時点で拘束カードは145、157、156枚、回収済みで捨て札へ戻らない本体は55、43、44枚だった。したがって「200枚が同時に手札・場札へ拘束された」ためではなく、拘束と回収済み本体の合計で200に達した不足である。

結論として、k=2は空場や即時のポイント破綻を生む案ではないが、場札密度を有意に押し上げる。場の規模を参加人数へ比例させつつ、常時競技を続けるという目的には合う面がある一方、上限張り付きの増加は無視できない。採用するなら、場札数による下限、上限近傍での追加テイク抑制、または場札上限自体の再設計を同時に比較する必要がある。

## k=2の難易度別・回収還元ポイント

別の100 seed（278000〜278099）で、k=2の回収済み場札を難易度別に集計した。対象は回収時の`reward_log`に記録されたユーザーへのポイント還元のみである。投稿コスト、給付、後発参加ボーナス、ランクPは含めない。難易度は場札本体の難易度であり、スタック札の枚数・難易度で分類していない。

| 難易度 | 回収場札数 | 総還元P | 平均還元P | 平均スタック | 平均参加者 | 平均支払いP総数 |

| 1 | 3,175 | 32,040 | 10.09 | 5.67 | 4.01 | 3.71 |
| 2 | 1,650 | 16,301 | 9.88 | 5.74 | 3.30 | 3.00 |

| 合計 | 5,677 | 56,751 | 10.00 | 5.66 | 3.65 | 3.34 |

100試行合計なので、1大会あたりでは総還元567.51P、回収場札56.77枚に相当する。難易度1〜4の平均は9.75〜10.09Pで大差がない。難易度5は47枚しかなく、10.68Pという差を難易度効果と断定できない。

「平均参加者」は当該場札へ有効な記録を投稿した人数、「平均支払いP総数」はその場札の初投稿者全員が実際に支払ったPの合計をカード単位で平均したもの。2・3人目の無料投稿は人数に含み、支払いは0Pとして含む。投稿更新は再支払いされないため含めない。

### 難易度1の平均還元10.09Pの内訳

難易度1について、表の平均スタック5.6655と平均支払い3.7143から得る全回収場札の平均基礎額は9.3798Pである。ここへ「平均値を使って一度だけ`floor`」を適用しても、実際の還元を再現できない。総還元はカードごとの投稿人数で分岐し、ボーナスもカードごとに切り捨てるためである。

| 難易度1・100試行合計 | 場札数 | P |
| --- | ---: | ---: |
| 全回収場札の基礎額（スタック＋支払い） | 3,175 | 29,781 |
| 未投稿場札（還元0）の基礎額 | 275 | −1,518 |
| 1人投稿場札（ボーナスなし） | 680 | 基礎額のみ |
| 2人以上投稿場札（難易度1ボーナス） | 2,220 | +3,777 |
| ユーザーへの総還元 | 3,175 | 32,040 |

従って、カード平均では`9.3798 − (1,518 / 3,175) + (3,777 / 3,175) = 10.0913P`となる。`floor`を個々のカードへ適用することは、この値を押し上げる原因ではなく、平均基礎額に対して一度だけ丸める場合より通常は同じか小さい。

もし8.546Pが表の平均スタック・平均支払いから導いた値であれば、その二値の和はすでに9.3798Pであるため、このシミュレーションの入力値とは一致しない。使用した式または対象（未投稿札を除く、支払いを別定義にする等）が異なる可能性がある。

回収還元は、2人以上の投稿がある場合、スタック数＋支払いPに「難易度×floor((スタック数＋支払いP)/5)」を加えた額となる。難易度は直接のボーナス係数でもある（2026-09-09訂正）。無投稿は0P、1人投稿は難易度ボーナスなし。難易度によるプレイ時間などの間接的な影響は、本集計だけでは分離していない。

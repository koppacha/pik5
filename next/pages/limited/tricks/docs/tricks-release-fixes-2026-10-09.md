## 修正結果

| 対象 | 修正内容 | 確認 |
|---|---|---|
| R1 予約名ID | 登録、署名済み本人識別、参加・カード操作、本人状態取得でシステム予約名を拒否。大文字・空白・非ASCIIの照合別名も拒否 | HTTP拒否、既存予約名プレイヤー、通常ID `_alice`、MySQL照合別名 |
| R2 期限後投稿 | 保存transaction内で期限同時刻以降・期限未設定を拒否。投稿・編集に伴う記録と報酬変更をrollback | 直前正常、同時刻・期限後拒否、編集前の記録・報酬保持 |
| R3 スコア上限 | 実際の場札・大会コンテキストを検証して大会上限999,999を適用 | 通常上限99,999維持、大会上限、偽装event、小数拒否 |
| R4 削除 | 公開GETではなくサーバー内の最小限の記録取得で所有者・管理者を検査 | 本人・管理者成功、他人拒否、公開可視性維持 |
| R5 参加前徴収 | 参加前slotを徴収対象外にし、ランキングリセット免除も消費しない | 遅延maintenanceと免除の回帰テスト |
| R6 終了時ポット | 通常回収・終了回収・予測を期限順、同時刻はID順に統一。期限未設定は後方 | 予測と実配分一致 |
| staging編集・削除 | 記録が実際に属する大会で制御。他大会に波及させない | 対象大会・他大会・開閉境界 |
| タイム投稿ログ | タイム種別をAPIから返し、83秒を01:23と表示 | 点数123点との並行ブラウザ確認 |
| 初期化CLI | 説明の200枚を現行160枚に訂正 | ソース・関連テスト |
| 複数大会の採番 | 専用ロック行で全大会の採番を直列化。裁定・テイクとも先に同じロックを取得し、ロック後に最新状態を読み直す | 独立レビューで見つかった逆順ロックを修正し、実MySQLで競合確認 |

stagingのアクセスキー制御は既存の新規投稿・ページ制御と同じく締切前のみ適用する。締切後も本人・管理者の通常の削除権限は維持する。大会終了後の編集可否はLaravelの大会状態検査に従う。

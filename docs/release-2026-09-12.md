## 本番での手順

リポジトリの `docker-compose.yml` と `docker-compose.prod.yml` を併用する構成向け。リポジトリ直下で実行する。別のプロセス管理構成を使っている場合、停止・再起動部分はその運用に合わせる。以下は本番では未実行。

### 1. バックアップ・停止・コード更新

```bash
dc() { docker compose -f docker-compose.yml -f docker-compose.prod.yml "$@"; }
dc exec -T laravel php artisan db:backup
```

出力されたバックアップファイルに `gzip -t <ファイルパス>` を実行し、正常であることを確認する。バックアップに失敗したら先へ進めない。必要なら [DB復旧手順](database-recovery.md) を参照。

メンテナンス時間を確保してNextを停止し、本番用ブランチでコードを取得する。Next停止からビルド完了まではサービス停止が発生する。

```bash
dc stop next
git pull --ff-only
dc run --rm --no-deps next yarn install --frozen-lockfile --ignore-engines
dc run --rm --no-deps next npx prisma migrate status
```

未適用一覧が想定どおりか確認する。今回追加したものは上記の2本。`migrate deploy` はほかの未適用マイグレーションも実行するため、想定外のものがあれば内容を確認してから進める。`migrate status` は未適用がある場合にも非ゼロ終了し得る。

### 2. DB更新・専用Seeder

```bash
dc run --rm --no-deps next npx prisma migrate deploy
dc run --rm --no-deps next npx prisma generate
dc run --rm --no-deps next npx tsx prisma/seed-limited-ideas.ts --dry-run
```

初回の期待値は `sourceRows=81`、`sourceRules=48`、`toCreate=48`、`expectedVisibleAfter=visibleBefore+48`。本番にshino15nomeが存在すれば、そのアカウントを利用する。ほかの発案者が欠けている場合はSeederが失敗するため、既存ユーザーとの対応を確認する。

```bash
dc run --rm --no-deps next npx tsx prisma/seed-limited-ideas.ts
dc run --rm --no-deps next npx tsx prisma/seed-limited-ideas.ts --dry-run
dc run --rm --no-deps next npx prisma migrate status
```

初回は `created=48`、`activeImported=48`、`visibleAfter=visibleBefore+48`。直後のdry-runは `toCreate=0`。既存データがなければ応募総数は48件、あればその分を加える。開発環境の49件は既存1件を含むため、本番の固定期待値にはしない。Seederは再実行しても編集・削除を元に戻さない。

通常の `prisma db seed` とは別の専用Seederである。ここでは `prisma/seed.ts` やDBリセットコマンドを実行しない。

## 失敗時

Seeder失敗時はトランザクションで取り消される。成功済みか不明ならdry-runで件数を確認する。DDLはMySQLで自動コミットされるため、migrationの途中失敗をDB全体の復元やリセットで安易に解消しない。Nextを停止した状態で原因と適用状態を確認する。ロールバック時も投入済み応募・履歴は保持し、DBを戻す必要がある場合だけ検証済みバックアップから別環境で復旧を確認する。

# セキュリティ施策・だれでもダンドリ検定のローカル実装

## 利用入口

- `/admin/stages`：管理者(role 10)と管理者が許可したユーザーの追加フォーム。
- `/total/48`：だれでもダンドリ検定の総合ランキング。
- `/auth/history`：本人のログイン履歴。
- トップ：2026/11/12 00:00 JST以降に検定ボックスを表示。開発環境は常時表示。トップ専用タイトルは「だれでもチャレンジ！ダンドリ検定（yyyy年mm月）」で、ルール自体の名称は変更しない。

ステージ登録の初期値は時間表示・降順（残り時間が多いほど上位）、操作方法はNintendo Switch。採点仕様は見込みのため変更可能だが、公開設定後の配信回・採点条件は変更できない。英語正式名は未指定なので日本語名へフォールバックする。

## ステージ登録

2026/11〜2027/10の12回、各6枠を登録する。下書き保存後、公開内容を確認して6件を一括公開する。配信月の12日より前の公開はサーバー側で拒否する。公開時刻までは検索・公開一覧に新作を出さない。公開後の月次追加にビルド・プロセス再起動は不要。開いている画面のカタログはフォーカス時と60秒ごとに再取得する。

完全新作は自動採番。445〜499の未使用IDを使用し、不足時は499→4A0…4A9→4AA…4AZ→4B0と採番する。公開IDは`stages.stage_code`、内部キーは既存の数値`stage_id`。英数字コードの内部キーは40000から、stagesとrecordsの既存参照に衝突しない番号をロック下で選ぶ。既存の数字IDは従来どおり解決する。内部キーからシリーズを推定せず、境界で公開コードへ変換する。

既存ステージの流用では元のparentや名称・記録を更新しない。ルール48の関連と投稿条件を別テーブルで管理する。再登場は配信枠だけを追加し、ルール48の記録と対象件数はステージごとに共通。元ルールの記録を48へ流用しない。

ステージ情報にnullable整数の`stages.difficulty`を追加する。管理フォームでは1=おてがる、2=ほんかく、3=きわみを選び、APIも整数1〜3に限定する。既存ステージの流用時もこの属性を保存する。公開設定済みの既知難易度は変更不可、移行前の未設定値は補完可能。その他・未設定はトップで「不明」。`records.difficulty`（既存の投稿条件）とは別属性で、レコードは更新しない。

## トップの月次表示

日本時間で当月の公開済み6ステージを選び、まだ揃っていなければ先月の公開済み6ステージと先月の年月を表示する。それ以前の月までは遡らない。下書き・未来の公開日時・未来の配信月は対象外。公開カタログ全体でも未来の配信月を除外する。

2027/11以降は毎月1日00:00 JSTに12か月周期で再配信する。2027/11→2026/11、2027/12→2026/12、2028/01→2027/01、2028/11→2026/11という対応で、タイトルは当月の年月。APIの`month`は表示月、`source_month`は元配信月。対応する元配信がなければ先月を同じ規則で選ぶ。DBへの配信回やステージのコピーは行わず、記録は従来どおりステージ単位で共通。

`fa-medal`と「最近のトレンド」共通の`TrendCellBox` / `cell-box`を使用し、最大6件を表示する。各セルはID・ステージ名・難易度の3行。PCは6列、スマートフォンは3列。総合ランキングへのリンクはボックス本文には置かず、ヘッダー右端に白文字で表示する。通常のルール名・総合ランキング名にはトップ専用タイトルを適用しない。

シリーズ4総合の通常ステージ一覧にも公開済みルール48を追加する。通常の総合ページの一覧は最大5行（50件）で、超過時は同じ高さの領域内スクロール。モバイルでも10列・5行を維持し、既存の横スクロールも可能だがスクロールバーは隠す。RTA一覧は制限対象外。シリーズ4総合から新作48ステージへ移動する際もルール48の導線を使う。

48は全総合・通常総合・4総合へ算入し、特殊総合には算入しない。48総合も公開済み対象から集計する。分母は予定72ではなく、その年までに公開されたユニーク対象数を用いる。未投稿ステージの対象数もカタログに追随する。

## 認可と監査

SSRのデータ取得前とAPI呼出時に、NextAuth主体に対応する現在のDBユーザーを照会する。JWT内の古いroleだけで許可しない。Next→Laravelの管理要求は主体・role・時刻・nonce・HTTPメソッド・パス・本文ダイジェストを署名し、Laravel側で署名・再送・業務権限を検査する。汎用proxyからの無署名迂回は拒否される。

追加フォームの利用許可は管理者だけが付与・取消できる。roleそのものは昇格させない。権限取消は次の管理要求から反映する。一括公開・採番・監査の書込は同一トランザクションで行い、revisionで同時更新と二重送信を検出する。

登録APIは公開に必要なUser属性だけを返す。利用箇所がない旧`/api/user/check-credentials`と汎用`/api/user/[id]`は410で閉鎖した。既存`/admin`もSSR取得前に現在の管理者権限を確認する。

## ログイン履歴と認証制限

新規ログインの成功・既知ユーザーの認証失敗・未知IDの失敗・制限・内部障害を専用テーブルへ記録する。通常のsession取得では履歴を増やさない。成功は90日、その他は30日保持し、`security:prune`を日次実行する。履歴の保存障害は秘密情報のない警告だけを出し、ログインは継続する。

ログイン・登録・OTP発行/検証・リセット発行/検証/確定を、DB行ロックによる原子的カウンタで制限する。基本はIP単位60回/15分、アカウント識別子単位10回/15分、OTP照合は5回/15分。アカウント識別子はHMACで保存し、生のメール・入力パスワード・Cookie・トークンを記録しない。リセットトークンの消費は条件付き更新で一度だけ成功する。

メール暗号の鍵は形式・長さを検証する。合成メールで往復、誤鍵、認証タグ改変、未設定鍵の拒否を検証した。実在メールの復号・パスワード推測・鍵値の表示は行っていない。鍵流出時の安全性を保証するものではなく、鍵の保管・更新は運用上の対策も必要。

## 接続元と本番専用の設定

Nextの`TRUSTED_PROXY_CIDRS`には、実際にNextへ接続する信頼proxyの正確なCIDRだけを指定する。未設定時は転送IPを信用せず直近の接続元を使用する。XFFは右側から信頼hopをたどる。Laravelは全proxy信頼を廃止し、Nextが正規化して署名したIPだけを採用する。

投稿時のIPを保存し、PTRはレスポンス後、2秒タイムアウトの別プロセスで逆引きする。PTRなしは空欄。DBトランザクション内でDNS待ちを行わない。既存の内部IPから過去の利用者IPを推測して補正しない。

国外判定を有効にする場合だけNextに`TRUSTED_COUNTRY_HEADER`を指定する。**信頼proxyがそのヘッダを必ず上書きし、Nextへ外部から直接接続できないことが前提**。未設定・未信頼peer・不正な国コードは国判定に使わない。署名されたJP以外の国情報がある場合、Laravel APIはIP単位120回/分、認証系はIP単位20回/15分で短期制限する。429とRetry-Afterを返す。国情報だけでは拒否しない。

初期のローカル実装時は本番へ接続していない。2026-10-24にNginxのヘッダ上書き・用途別制限だけを本番反映し、PC/スマホ幅のHTTP応答を確認した（[調査記録](top-reload-429.md)）。本番のCDN/WAF・GeoIP情報源、ポート閉鎖、FW、継続的な閾値調整は別途確認が必要。アプリ本体のローカル実装の配備とは区別する。

環境識別はサーバー側`PIK5_DEPLOYMENT_ENV=development|production`を使用できる。未指定時はNODE_ENVに従う。ローカルで本番ビルドを表示確認する場合はdevelopmentを明示する。国ヘッダと信頼proxyの設定は本番トポロジー確認後に行い、広いプライベートネットワーク全体を無条件に信頼しない。

# イベント成績・ランキング

- `/total/4` は全イベント総合、`/total/4/{categoryId}` は3桁カテゴリ別。カテゴリ表示名はlocale、Laravelの分類は対応定義を参照する。未定義カテゴリの空一覧とAPI障害を分ける。
- `event_results` は保存済みのイベント成績。画面表示ごとに過去大会を重く再計算しない。`events.csv` は開催設定、`event_results.csv` は参加者成績。
- `EventResultCsvSeeder` は入力・整数・重複ID・別大会とのID衝突を検証し、transaction内でupsertする。CSV外の行は保持する。truncateは廃止済み。
- `LimitedEventResultService` は過去期間限定の再計算用。既存の簡易ランキング表示と計算方式を混同しない。全対象保存はholderも更新するため、保存対象・除外大会を確認する。
- 第2〜18回の復元と第19回の追加は過去の反映記録あり。第1回の元記録はなく、`LimitedFirstDummyRecordSeeder` が表示確認用としてkoppacha / stage1001 / 4700点 / 2015-11-04 12:00の合成投稿と当該回の成績だけを追加する。既存の第1回データ・識別子の衝突時は中断し、同じダミーの再実行は変更しない。通常seedには組み込まず明示実行する。現在のDB件数や本番反映を過去の数値だけで断定しない。
- `/total/4/151` の大会一覧は基本ルールごとに6列の1行で区切る。第1〜6回は青・square・スタンダード、第7〜12回は赤・table-columns・チーム対抗、第13〜18回は緑・table-cells・エリア踏破、第19回からの区画は黄・layer-group・トリックテイキング。大会グリッドのみを1px実線で囲み、左上は直角、右上・右下・左下は半径2pxの角丸とする。基本ルール名は枠外の左上で上辺に接地させる。見出しは枠と同色背景・上角丸。各大会リンクには日付・回数・特殊ルール名だけを表示し、基本ルール名と区切りの「×」は省く。特殊ルールがなければ「スタンダード」（第1〜8・14・19回など）とする。狭幅では一覧内を横スクロールする。大会IDを明示対応し、欠けた回があっても分類をずらさない。新しい大会を追加するときは対応IDも追加する。
- 第3回インスタント研究会 `260221` は `TEMPORARILY_EXCLUDED_INSTANT_EVENT_IDS` により一時除外。データを削除せず、カテゴリ・全総合・スタンプ・一覧で一貫して除外する。明示指示なく解除しない。
- カテゴリ241は `battles` 由来の最新result_pointを使う。APIの `last_updated_at` は対象の最終開催日であり投稿更新日時ではない。

## スタンプと第19回

- 計算の正本は `EventStampService`。期間限定はrps、他イベントはscoreで順位を計算。同点は同順位、チーム戦・カテゴリ別の勝利加点を保つ。
- 第1回期間限定（151101）は表示確認用ダミーのため、結果コードによらずスタンプを0個にする。成績・大会一覧・参加マーカーは保持し、0個を理由に非表示にしない。
- 基本数Bは7人以下なら1。8人以上はKを期間限定で `ceil(N/2)`、それ以外で `ceil(N/4)` とし、チーム所属者は一律K、個人戦はr≦Kで `K+2-r`、それ以下は1とする。Nは大会全体の参加人数。
- 受賞加点Aは `4+ceil(N/8)` に、期間限定のエリア踏破制（第13〜18回）では3、トリックテイキング（第19回）では7を加える。既知大会IDとsub_titleのルール名で分類する。MVP・トップホルダーが勝利チームに所属する場合はさらにカテゴリ別の勝利加点Wを加える。勝利チームは同じ大会の `result=w` のチームIDから判定するため、計算前に `withEventRanks` へ大会全員の成績を渡す。
- `w` はB+W、`m` / `h` はB+A、`b` は `2*(B+A)`（勝利チームのWも含めて2倍）、`e` は固定2、それ以外はB。Wは期間限定・RTAで個人6/チーム4、リレーで個人4/チーム2、それ以外は2。第1〜6回期間限定の個人優勝は `w` のため受賞加点Aを使わずW=6だけを加算する。
- 第19回は `TrickEventResultService` が閉幕・全回収・凍結ポイント一致を確認して対象大会だけ冪等保存する。確定ランクPをrpsとrps_adjustへ加算し、score=0 / team=0。
- MVPはm、トップホルダーはh、両賞はb。回収時の凍結rankingsの同率1位も各1枚として集計し、最大0は受賞なし。単独賞はMVP式、両賞は式全体を2倍。表示とAPIで同じ定義を使う。
- `EventList` の261009リンクは `/limited/tricks?261009`。他イベントの `/limited/{eventId}` と分岐する。

## 公開と閉幕後

- 通常公開経路は `Record::publiclyVisible()`。大会帰属リンクと対象ステージ・開催期間内の記録を使って開催中投稿を除外する。大会内取得・本人の更新や投稿数の集計とは適用範囲を分ける。
- 非公開解除は通常end_at。第19回は締切2026/10/11 19:59 JSTに対し公開20:00の例外がある。stateの最終処理完了だけを公開時計にしない。
- 第19回の閉幕後編集は本人・管理者の証拠・コメント・操作方法に限定して24時間超を許可。スコア・元created_at・確定成績・課金を保持し、削除期限を延長しない。`metadata_only_edit` を画面・Next・Laravelで維持する。
- 最終リザルトは総還元P降順・stage_id昇順。有効投稿件数という表示統計と、ゲーム中に確定したカウンター・順位を混同しない。

## 他イベント

- アリーナは `NewArenaController` / `arena_events` 等。旧ArenaController / arenasとは別機能。[企画書](../idea/event-arena.md)は設計経緯を含むため実装を確認する。
- スイス式は大会→ラウンド→マッチ→ゲーム。先取2勝、引分は勝数に含めない、通常最大3ラウンド、その後必要時に決勝。組合せは `SwissPairingService`。
- 名前直接登録は `swiss_players.display_name` と内部UUIDを使う。結果取消は `result_sequence` で直前を確定し、次抽選後は拒否。初戦勝敗区画を第3ラウンド以降固定する現行表示を維持する。
- 管理更新はNextAuth role10をAPIでも検証。公開GETと汎用proxyからの迂回拒否を確認する。
- `SwissFirstTournamentSeeder` / `swiss:transfer` は5テーブルの関係ID・重複投入を扱う。移行は件数・全列・再実行保持を検証し、本番未投入という昔の記述だけで再実行しない。

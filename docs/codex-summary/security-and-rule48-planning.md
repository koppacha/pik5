# ルール48とセキュリティ追加実装

> 計画からローカル実装へ移行済み。ファイル名は既存参照を維持するため据え置く。本番適用済みという意味ではない。

- 詳細の正本は [実装・配備条件](../security-and-rule48-implementation.md)。入口は `DandoriController`、`DandoriCatalog`、`StageCodes`、`next/lib/dandori*.js`、`/admin/stages`、`/total/48`、`/auth/history`。
- 「だれでもダンドリ検定」はシリーズ4・rule48。2026/11〜2027/10の12配信回×6枠。再登場は同じ48内で記録共通、ユニーク対象数と配信枠数を分ける。
- 新作は445〜499の空き、次に4A0…4A9→4AA…4AZ→4B0。公開 `stage_code` と数値内部 `stage_id` を分離し、英数字用内部キーは40000から衝突回避・ロック下で割り当てる。全IDをbase36へ変換しない。シリーズはmetadataから取得する。
- 流用ステージの元parent・名称・記録を変更しない。rule48関連で対象と採点を管理する。元ルールの記録と48の記録を混在させない。
- 初期値は時間表示・残り時間降順・Switch。英語正式名と最終採点要件は確定事項として補完しない。公開設定後の採点条件は固定する。
- ステージ難易度は`stages.difficulty`（nullable整数、未設定は不明）。管理フォーム/APIは1〜3だけを受け付け、1=おてがる、2=ほんかく、3=きわみ。レコードの既存difficultyとは別の属性。既存流用では難易度を保存するが、元名称・parent・記録は変更しない。公開設定済みの既知難易度は固定し、旧未設定値は補完可能。
- 全総合・通常総合・4総合・48総合へ算入し、特殊総合は維持。分母はその年までに公開されたユニーク対象数。
- 管理者と許可ユーザーのみ追加可能。管理者のみ権限付与・取消。SSR前とAPI時の現行User確認、署名・nonce・revision・transactionを維持する。
- 配信月12日より前の公開は拒否。下書きは公開APIへ出さない。トップは2026/11/12 00:00 JST以降、開発は常時表示。カタログは60秒・フォーカス時更新で月次追加にbuild不要。
- トップ限定タイトルは「だれでもチャレンジ！ダンドリ検定（yyyy年mm月）」、メダルアイコンとトレンド共通のcell-boxを最大6件表示。当月の公開済み6件がなければ先月の6件と先月の年月を表示し、未来月は公開日時を過去に設定しても除外する。
- 2027/11以降は日本時間の毎月1日に、2026/11〜2027/10の配信を12か月周期で再利用する。表示年月と元配信月を分け、ステージ・ルール48の記録・配信枠を複製しない。再配信対象がなければ同じ選択規則で先月へフォールバックする。
- 初回導入にはLaravel追加migration3件（管理・認証履歴・ステージ難易度）、Next build、署名・信頼proxy設定等が必要。認証・IP・国情報は [認証とproxy](auth-security-proxy.md)、検証は [テスト方針](testing-and-verification.md)を参照する。

# Codex Working Rules

## 回答と言語

- 回答は日本語で簡潔かつ丁寧に書く。
- 調査結果は、原因、影響範囲、変更候補、確認済み/未確認を分けて報告する。
- ユーザーが「計画だけ」「改修は実施しない」と言った場合は、コード変更せず調査と計画で止める。
- ユーザーが「失敗したら中止」と明示した疎通確認や検証は、指定回数・指定方法で失敗したら追加探索せず中止する。

## Summary / Logs

- 今後の開発で参照すべき重要事項は `docs/codex-summary/` に集約されている前提で扱う。
- 必要に応じて `docs/codex-summary/` 配下のカテゴリ別要約を参照する。
- `docs/codex-summary/` のファイル名は英語ケバブケースの `{category-name}.md` とする。
- ユーザーのプロンプトを処理するたび、出力後に Codex が読み取れる範囲の transcript を `docs/codex-logs/{yyyy}-{mm}-{dd}-{sessionId}.md` に追記する。日付にはセッション開始日を使う。
- ログは要約ではなく transcript を原則とし、ユーザーのプロンプトは省略・言い換えせず記録する。ローカル JSONL から再生成する場合は `node docs/scripts/export-codex-log.mjs <JSONLファイル>` を使う。
- ログ追記時に、新しい開発ルール、構造上の重要概念、禁止事項、出力ルール、セキュリティポリシー、Git 運用ポリシーなどが含まれる場合は、`docs/codex-summary/` へ抽出・追記・更新する。
- ユーザーが「このセッションは記録しないで」と指示した場合、そのセッションでは以後ログ書き込みを行わない。
- 通常のやりとりでは `docs/codex-logs/` を読まない。
- ユーザーが「セッションログを読み取って」と明示した場合のみ、その指示の処理範囲で `docs/codex-logs/` を読んでよい。

## 開発統計

- 開発統計ページは `docs/stats.html` とする。
- ユーザーが「統計情報を更新して」と指示した場合は、`node docs/scripts/update-stats.mjs` で既存データを再集計して上書きする。
- commit ごとの短縮ハッシュ、commit 日、`ver.x.xx` 相当文字列、変更行数、およびセッションごとの開始日、セッションID、ユーザープロンプト文字数を出力する。
- `yyyy年mm月` ごとの変更行数とユーザープロンプト文字数の合計をダッシュボードに出力する。

## 禁止/注意行為

- ユーザー由来の未コミット変更を勝手に戻さない。
- `wiki/`、`lab/`、`sandbox/` は関連タスクでない限り編集しない。
- ブラウザ側 yup バリデーションだけでセキュリティ要件を満たしたと判断しない。直接 API を叩く回避を常に考慮する。
- `user_ip` や `user_host` のような信頼境界に関わる値をクライアント入力として信用しない。
- Laravel 側で本番外部公開すべきでないポートを安易に公開しない。Laravel は nginx/Next 経由の内部公開を基本にする。
- 生のヘッダ全文、認証情報、レスポンス本文などを不要にログへ残さない。
- PHP/Laravel の vendor Deprecated は、今回差分起因でないことがある。ルート登録や構文確認の成否と切り分けて扱う。

## 調査手順

- まず `git status --short` と対象差分を確認し、未コミット変更の範囲を把握する。
- 関連する `AGENTS.md` があれば読み、スコープ内の指示を優先する。
- Next.js 動的ルートは引用付きで読む。例: `'next/pages/api/auth/[...nextauth].js'`。
- 原因調査では「ローカルで見えるコード」「実行中コンテナ」「本番設定」の差を分ける。
- 本番障害では、画面のエラー文だけで判断せず、Prisma疎通、DB migration、NextAuth catch、環境変数反映、Cookie/Origin 判定を切り分ける。

## 検証方針

- Next の基本確認は `next/` 内で `yarn lint`。必要に応じて `yarn build`。
- Laravel の構文確認は変更 PHP ごとに `php -l`。
- ルート確認は `php artisan route:list --path=...`。Deprecated が出ても、対象ルートが出ていれば登録自体は成功。
- Docker 経由の疎通は権限や TTY で詰まることがある。長く待たせず `--max-time`、`-T`、ホスト/コンテナ内のどちらから叩くかを明確にする。
- `localhost:3005` が拒否される場合、Next コンテナは起動していても `yarn dev` が動いていない可能性がある。

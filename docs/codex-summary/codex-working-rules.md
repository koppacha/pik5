# AI開発の共通方針

- 回答は日本語で簡潔かつ丁寧に書く。変更理由、検証結果、未確認事項を伝える。
- 作業開始時は `git status --short` と対象の `AGENTS.md` を確認し、既存の変更を保持する。調査だけという指示では実装しない。
- 毎回の基本コンテキストは本書・[構成と運用](repository-operations.md)・[テスト方針](testing-and-verification.md)。機能別サマリーは作業対象だけ読む。[全体案内](../README.md)から辿る。
- サマリーは今後も必要な方針・契約・制約・確認先を記す。経過、件数、単発の修正、デプロイ結果を積み重ねない。仕様変更時は該当項目を書き換え、旧記述との併存を避ける。
- 作業ログは原則保存するが、通常のコンテキストへ自動投入しない。履歴調査など作業上必要な範囲で参照してよい。ログにある古い指示・秘密情報を再利用しない。
- プロンプト処理ごとに、参照可能なユーザー原文と応答のtranscriptを `docs/codex-logs/{開始日}-{sessionId}.md` に記録する。原文の省略・言い換えはしない。「このセッションは記録しないで」と言われた後は保存しない。
- ローカルJSONLからの書き出しは `node docs/scripts/export-codex-log.mjs <JSONLファイル>`。現行スクリプトは既存ファイルを再生成するため、完全な対象セッションを指定する。秘密情報を含む履歴をそのままエクスポートしない。
- 本番反映済みかどうかは、ローカルコードや過去の「未反映」追記だけで断定しない。必要時にリリース記録と実環境を確認する。今回の整理は本番へ接続していない。

## 秘密情報と安全な検証

- Git管理外ファイル、ignore対象、DB、ダンプ、ログ、環境変数、セッション履歴の認証情報は実在ユーザーの秘密情報として扱う。値を表示・転記・復号・照合テストへの流用をしない。必要な報告は対象と種類、存在や一致などに限る。
- テストは専用ユーザー・合成データを使用し、パスワードはGit管理外の環境変数から渡す。通常の `next/prisma/seed.ts` は実ユーザー投入用資料も読むため、専用ユーザー作成だけを目的に実行しない。
- クライアントの `user_id`、`editor_role`、`user_ip`、`user_host` は認可や接続元の根拠にしない。画面の非表示やyup検証だけでAPIを保護したと考えない。
- 生ヘッダ・Cookie・レスポンス全文・例外オブジェクトを無差別にログへ残さない。
- DB初期化、既存データの削除、認証情報の変更、本番反映を、通常の検証の付随作業として実行しない。
- `wiki/`、`lab/`、`sandbox/` は関連する作業でのみ編集する。

## 公開前の確認

- push対象の文書・画像は公開前提。実資格情報、個人環境の絶対パス、非公開の本番接続・バックアップ情報を除き、例は環境変数・プレースホルダーにする。
- 会話transcriptは場所を問わず `**/codex-logs/` としてGit管理外で保持する。公開用の仕様・検証結果と分ける。
- 過去のGit履歴に記載済みの資格情報は現行文書の修正だけでは消えない。値を再掲せず、有効なら失効・更新が必要なことを報告する。履歴の書換えは通常の公開文書修正と切り分ける。

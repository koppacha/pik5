# Medianゲーム

- ページは `next/pages/limited/median.js`、専用Next APIは `/api/median`。既存記録の投稿・総合点・再検証・通知を呼ばない。Medianだけ共通記録通知を停止し、他ページは既定動作を維持する。
- Laravelの `MedianController` と `Services/Median/` がゲームを管理。`median_rooms` の単一行をロックし、`median_games.state` のJSONに参加者・下書き・出題キュー・履歴を保存する。Prisma認証DBには新しいゲームデータを書かない。
- 匿名は名前の完全一致だけで同一人物として扱う。ホスト・端末・IPは照合しない。同名の匿名主催にも再接続できる。ログイン参加者はサーバーが現在のUserから確定したuserIdで区別し、表示名の衝突は許す。匿名とログインの名前空間は別。
- 主催・参加者を初回参加ボタンで選ぶ。主催不在なら参加者が先にゲームを作成できる。主催を後から選んでも最初の参加時のゲームIDを保つ。主催は1人。
- 主催の明示的な終了で終了し、終了から24時間保持する。通信断・タブ閉鎖・未操作で終了しない。`median:prune` を毎分実行し、期限以後の参照でも失効させる。日時IDはAsia/Tokyoの秒精度。同じ秒の新規作成は再試行を求める。
- 締切でclosingへ移行し、各参加端末が最新のローカル入力を最終送信する。主催は締切要求の前に自身の最新入力を必ず送る。全員回収または8秒経過後に、回答確定・比較・採点・保存を一つのトランザクションで行う。通信断の人は最後の下書き（未入力は0）を使用する。最終送信は当該締切の識別子付き・対象者ごとに1回だけ受け付け、遅延した通常の自動保存は拒否する。開示は別操作で、締切済み得点の増減も開示前は隠す。
- 回答受付中の参加はその問題の対象。締切後の参加は次問から。問題の参加対象は開始・途中参加時に固定し、途中離脱した人の回答・得点も保存する。同名再入場は現在のゲームの得点を復元する。
- 新ゲームは主催・参加者（離脱履歴を含む）・未出題キュー・未取込のお題を保持し、全員の点数を0にする。旧ゲームは終了状態で24時間保存し、新ゲームの画面には旧履歴を混ぜない。
- 数式はサーバー側のmath.js AST許可リストと専用workerで評価する。64桁計算・有効数字30桁を0方向に切り捨て。原文、正規化した科学表記、表示値、検証状態を保存し、PHPで符号・指数・仮数を比較する。Number/FLOATへ変換しない。
- 任意コード、代入、プロパティ参照、行列、単位、複素数、非数、無限を拒否する。未入力・無効入力は0。入力512文字、AST160ノード・深さ24、指数の絶対値100000、worker2秒・128MB・同時8件が上限。対応関数は画面の説明と評価器を正本とする。
- NextからLaravelへ主体・時刻・nonce・HTTP method・path・body hashのHMAC署名を送る。`MEDIAN_INTERNAL_SECRET` を双方に設定するか、既存 `TRICKS_INTERNAL_SECRET` を使う。匿名Cookieも署名する。署名設定なしは503。汎用proxy・Laravel直通からの署名なし操作も拒否する。
- 回答は本人分だけ、未出題キューは主催だけへ返す。レスポンスはprivate/no-store。Next APIで上流の例外詳細を公開しない。原文・名前は専用API内で署名済み本文から復元し、Laravel共通trim/null変換を局所的に回避する。
- 参加枠は100件、お題キュー・受信箱各200件。キュー保存は版番号付きで、上書き消失・重複取込を防ぐ。2秒の定期取得を使用する。回答受付中・回収中は非表示タブでも取得を継続し、他の状態の非表示タブでは停止する。
- 未出題キューはフォーカスアウト時に自動保存し、手動保存ボタンは設けない。空行・空白しかない場合は「お題表示」を無効にする。保存要求を直列化し、出題・お題受信・新ゲーム操作は未保存キューの保存完了を待つ。保存中の追加入力と保存失敗時の入力を保持する。
- 説明と配備手順は [Median実装・確認](../median-game.md)。
- MySQL JSONのオブジェクトキー順序には依存しない。参加者に明示的なorderを保存し、画面・ラウンド参加順はその順序で復元する。実MySQLで確認済み。
- Dockerの依存volumeはホストと独立している。mathjs追加後は稼働中のNextコンテナ内でfrozen-lockfileのinstallを実行する。実workerの確認は `next/tests/medianWorker.test.cjs`。依存欠落を無効回答として保存せず、計算機能の利用不可として扱う。
- 入力は400msの下書き自動保存と締切時の最終回収を使い、手動の回答保存ボタンは設けない。本人の離脱は回答カード内、主催の代理離脱は固定フッターの管理タブに配置する。入力欄の本文・ラベル・枠・補助文はMedian内のテーマ変数で配色し、他ページへ適用しない。
- Medianは共通LayoutのfullWidth指定でウィンドウ全幅を使う。他ページの最大幅は維持する。開示は参加順で1秒待機後、毎秒3回の隣接比較・交換による安定バブルソートを行う。完了後に同値グループ化・枠色・獲得点・今回の履歴を表示する。同値グループはdisplay:contentsで共通グリッド内に配置し、10人以下は常に1行、11人以上は2行とする。次問操作も演出完了まで無効。再取得で演出を再起動せず、ラウンド変更・離脱時はタイマーを解放する。開発時の説明は有効な定数・関数の列挙だけとし、本番（NODE_ENV=production）では説明ブロック自体を描画しない。
- 回答入力は本人の1フォームだけを開示回答と別の固定ブロックとして画面下部に残す。締切後・開示後は読み取り専用。スマートフォンでは62pxの共通ナビ上に置き、ResizeObserverで測った固定領域の高さに応じて本文の下余白を確保する。締切・回収メッセージは問題文の直下、次問ボタンは開示回答グリッドの直下に置く。
- お題待機中はお題領域を空のまま確保し、「次のお題を待っています」を締切メッセージと同じstatus領域に表示する。status領域は空の回答中も高さを確保する。本人の離脱文言は「イベントから離脱する」。参加者一覧には代理離脱ボタンを置かない。固定フッターは参加者には「回答入力」「お題を投稿」、主催には「回答入力」「次以降のお題」「管理」のタブを表示する。主催の未出題キューは本文からフッターへ移し、件数が多い場合も欄内をスクロールして編集できる。受信・新ゲーム開始・終了ボタンも同タブにまとめる（終了済みゲームの再開ボタンは本文に残す）。管理は表示名の完全一致で対象を探し、同名が複数なら参加順・得点を表示して選択させる。主催本人は対象外とし、確認ダイアログ後に既存の主催限定remove APIを使う。タブ変更で回答・投稿の入力を破棄しない。過去のお題を含むサブエリアの上に400pxの余白を確保し、進行などのcontrolsは中央揃えにする。

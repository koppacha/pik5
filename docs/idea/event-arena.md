# イベント「ピクチャレアリーナ対戦」

## 概要

この設計書は、イベント専用ページおよびバックエンドAPIの実装指示を構成します。
`old-arena.js`、既存 `arenas` テーブル、既存 `ArenaController` および関連APIは本イベントには関与させません。

- フロントエンド作成場所：`next/pages/limited/arena.js`
- API作成場所：Laravel 側に新規コントローラーを作成
- DB：旧 `arenas` は使わず、新規テーブルを作成
- 参考実装：`next/pages/battle/index.js`
- 参考シミュレーター：`lab/sim_arena.py`

## 構想

- このプロジェクトは、負け抜け対戦イベントの各プレイヤーの成績をリアルタイムで表示・記録することを目的とする。
- 表示されるページはイベント結果を反映し、イベント結果を入力する機能を兼ねる。
- イベントは日を跨がない想定とする。
- イベントは基本20戦とする。
- レートはDBに保存され、次のイベントに引き継がれる。
- 勝者は、開始時レートから最もレートが上がったプレイヤーとする。

## 基本

- 各試合を「対戦」と呼ぶ。対戦は1対1で、結果によって参加者を勝者か敗者に分ける。
- 引き分けは通常想定しないが、`result=0` の特殊処理として扱う。
- 各プレイヤーのうち、前の対戦の勝者を「暫定チャンピオン」と呼ぶ。最初の対戦では参加者からランダムに選出される。
- 対戦者のうち暫定チャンピオンではないプレイヤーを「チャレンジャー」と呼ぶ。最初の対戦では参加者からランダムに選出される。
- 対戦当事者以外のイベント参加者を「観戦者」と呼ぶ。
- すべての参加者には内部データとして「並び順」が振られる。暫定チャンピオンは1、チャレンジャーは2、観戦者は3以上とする。
- 参加者の最小人数・最大人数は、その時々の運用に依存するため定義しない。
- 観戦者表示の上限は10人とする。表示上限を超える参加者の扱いは仮置きで、実装時に折り返しまたは省略表示を検討する。
- 想定している運用では、OBSで暫定チャンピオンとチャレンジャーの配信画面を表示し、当プロジェクトの各表示領域をフレームとして表示する。
- フレーム下部には各イベント参加者の戦績等をユーザー表示領域として fixed 表示する。
- フレーム右側にはステージ抽選ルーレットを fixed 表示する。ルーレットの横幅は280pxとする。
- フレーム左上領域はOBS上は表示せず、管理領域として使用する。
- fixed レイアウトの未定義部分は可変レイアウトとする。

## イベントのルールと進行

- 新規参加者は1000点からスタートする。
- ユーザー追加時は、今回のイベントを含まない範囲で最後のレートを取得し、それを開始レートとする。
- 途中抜けしたユーザーが同日の同イベントに再度参加した場合も、当日分の記録を除いた最後のレートを開始レートとする。
- 最初にユーザーシャッフルボタンを押し、暫定チャンピオン、チャレンジャー、観戦者の並び順をランダムに並べる。
- シャッフルボタンは最初にしか押さない想定とし、試合数が1以上の場合は非活性にする。
- 次にルーレットボタンを押し、ステージを決定する。
- 決定したステージを表示する。この時点で「n戦目」の表示を次の対戦番号にする。
- 主催者がリザルトを入力して送信ボタンを押下する。
- バックエンドでレートを処理し、テーブルを更新する。
- 表示はSWR pollingで更新し、DB更新後できるだけ速やかに最新情報を表示する。
- 結果送信後、ステージ名表示は空に戻す。
- 通常結果では、負けたプレイヤーの並び順を最後尾に、勝ったプレイヤーをチャンピオンに、並び順3のプレイヤーをチャレンジャーにする。
- `result=0` はレート計算を行わず、試合数は増やす。並び順等はチャレンジャーが敗北した場合と同じ処理にする。
- 上記ルーレット回しから結果送信後処理までを基本20回繰り返す。

## レートポイントの計算

計算ポリシーは `lab/sim_arena.py` を基準にする。ただし、観戦料の支払い・還元は本仕様書の内容を正とし、シミュレーター側を後から合わせる。

### 支払いポイント

- 対戦者は、対戦前に参加費を支払う。
- 参加費の基本式は `round(所持ポイント * 0.10 + max(0, 所持ポイント - 1000)^2 / 10000)` とする。
- 参加費は下限50、上限220で clamp する。
- 支払い計算例はシミュレーターの `payment_from_rating()` に合わせる。

### 観戦料

- 観戦者は、暫定チャンピオンの連勝数が1以上のとき観戦料を支払う。
- 観戦料は `round(チャンピオンの参加費 * 0.10)` とする。
- 観戦料は下限5、上限15で clamp する。
- 暫定チャンピオンの連勝数が0のとき、観戦料は発生しない。
- 対戦者と観戦者が支払った合計ポイントを「ポット」と呼ぶ。
- 観戦料はポットに含め、勝者・敗者への配分対象にする。

### 勝者取り分

- チャンピオンが勝った場合の基本勝者取り分は、シミュレーターの `HOLDER_WIN_SHARE_BY_STREAK` を基準にする。
  - 0連勝: 70%
  - 1連勝: 70%
  - 2連勝: 71%
  - 3連勝: 72%
  - 4連勝: 73%
  - 5連勝以上: 75%
- チャレンジャーが勝った場合の基本勝者取り分は、シミュレーターの `CHALLENGER_WIN_SHARE_BY_STREAK` を基準にする。
  - 0連勝: 70%
  - 1連勝: 72%
  - 2連勝: 74%
  - 3連勝: 76%
  - 4連勝: 78%
  - 5連勝以上: 80%
- 勝者が赤字にならないよう、勝者取り分には安全下限を適用する。
- 安全下限は `(勝者の参加費 + 5) / ポット` とする。
- 勝者取り分は最大90%とする。
- 実際の勝者取り分は `max(基本勝者取り分, 安全下限)` を上限90%で clamp した値とする。

### 丸め方

- 参加費、観戦料は `round()` で整数化する。
- 勝者の獲得ポイントは `round(ポット * 実際の勝者取り分)` で整数化する。
- 敗者の獲得ポイントは `ポット - 勝者の獲得ポイント` とする。
- 各プレイヤーの結果レートは `対戦前レート - 支払い + 獲得ポイント` で算出する。
- 観戦者は `対戦前レート - 観戦料` とする。
- `result=0` の場合、参加費・観戦料・レート変動は発生させない。

## 表示する内容（ユーザー表示領域）

- 表示領域は2行で構成する。
- 1行目の左半分を「暫定チャンピオン情報」、右半分を「チャレンジャー情報」、中央を「ステージ情報」とする。
- チャンピオン情報とチャレンジャー情報をまとめて「対戦者情報」と呼ぶ。
- ブロックのGrid比率は、対戦者情報=5、ステージ情報=2とする。
- 2行目の横幅を `{観戦者数 + 1}` で等分し、1ブロック目を「総合情報」、2ブロック目以降を「観戦者情報」として扱う。
- 総合情報は「現在の時刻」「観戦料」を表示する。
- 対戦者情報は、1行目に「プレイヤー名」「レート」、2行目に「勝敗数」「最高連勝数」「勝ったら得られるポイント」「参加費」を表示する。
- 暫定チャンピオンに限り、勝敗数の位置には「現在の連勝数」を表示する。
- ステージ情報は「n戦目」「ステージ名」を表示する。
- ステージ名に `（` が含まれている場合、その直前に改行を入れる。
- 観戦者情報は「プレイヤー名」「レート」「勝敗数」「最高連勝数」を表示する。
- 各ブロックのレートは「現在のレート / 開始時レート ({現在 - 開始時})」を表示する。
- 開始時レートとは、そのユーザーが今回イベントを除く記録のうち最後のレートポイントをいう。該当記録が存在しない場合は初期レートとする。
- 勝敗数、最高連勝数、現在連勝数は都度計算する想定とする。ただし、過負荷になる場合は集計カラムを追加してもよい。

## 表示する内容（ルーレット）

- 種目名を12個選び抽選するルーレットを表示する。
- 各項目は1行1個とし、縦長表示を想定する。
- ルーレットの対象ステージIDはDB管理せず、`next/pages/limited/arena.js` の中に定義する。
- ステージIDに基づいて locale からステージ名を取得する。
- ステージ12個の stage_id は未決定のため、実装時は仮IDを置く。
- 基本的にダークテーマ背景色で表示し、選ばれている行は `.active` を適用する。
- ルーレット抽選ボタンを押すと一定時間ランダムに選び続け、止まる2秒前から低速化し、最終的に1つの種目を選ぶ。
- 基本抽選確率は1〜10番目を9%、11・12番目を5%とする。
- 後述のルールによって定められた「選ばれないステージ」はあらかじめ除外し、その余剰確率は基本抽選確率の比率に沿って選ばれるステージに割り振る。
- あらかじめ内部で抽選してから、それに止まるようにルーレットを動かす。
- 前４回に選ばれたステージは原則選ばれないようにする。
- すべてのステージが2回選ばれた場合を除き、同一イベント内で同じステージは3回以上抽選されないようにする。
- ルーレットの抽選履歴はDBには保存しない。
- 抽選履歴は暗号化してCookieに保存する。保管期限は30日とする。
- 抽選後、選ばれた種目のIDに基づいてステージ情報に表示し、対戦結果入力フォームに自動入力する。
- ルーレット画面はユーザー表示領域とは別にキャプチャするため、スクロール防止さえできていればそれぞれの位置関係は厳密に考慮しなくてよい。

## 表示する内容（管理領域）

- 管理領域は、セッションユーザーの `role` が10である場合のみ表示する。
- fixedしない領域に、各対戦結果を簡易的に表示するブロックを表示する。
- 対戦結果ブロックは送信のたびに追加し、新しい順に並ぶ。新しい対戦は一番上に挿入される。
- 対戦結果より上に、ユーザー追加・削除フォーム、対戦結果入力フォーム、ルーレット抽選ボタンを表示する。
- 上記とは別に、ユーザーの並び順シャッフルボタンを置く。
- シャッフルボタンは試合数が1以上の場合は非活性にする。

### ユーザー追加・削除

- 入力項目は `user_id` とする。
- 追加ボタンと削除ボタンを設置する。
- 追加ボタン押下時は、対象ユーザーが既に参加者に含まれていないかチェックし、既に参加者に含まれている場合は追加しない。
- 追加可能な場合は、今回イベントを除いた最後のレートを取得し、開始レートと現在レートに設定する。（今回イベントで初めて参加して途中抜けし、再び参加した場合のみ、今回イベントの最初のレートと途中抜け直前のれい後のレートを取得する）
- 今回イベントを除いた過去レートが存在しない場合は1000点から開始する。
- 追加したユーザーの並び順は最後尾とする。
- 削除ボタン押下時は、対象ユーザーが参加者に含まれているかチェックし、参加者に含まれていない場合は削除しない。
- 削除可能な場合は、参加者状態から除外する。過去の対戦結果行は削除せず、履歴として保持する。

### 対戦結果入力画面

- 以下の項目を入力できるようにする。自動入力項目も管理者が訂正できるようにする。
- `stage`：ルーレットによって選ばれたステージ。内部的には `stage_id` を送信する想定。自動取得する。
- `user_id_1p`：暫定チャンピオンのユーザー名。内部的には `user_id` を送信する想定。自動取得する。
- `user_id_2p`：チャレンジャーのユーザー名。内部的には `user_id` を送信する想定。自動取得する。
- `score_1p`：暫定チャンピオンのスコア。数値以外の文字列や空文字を許容する。
- `score_2p`：チャレンジャーのスコア。数値以外の文字列や空文字を許容する。
- `receivers`：その時点の観戦者。カンマ区切り文字列。並び順通りにソートして自動取得する。
- `result`：どちらが勝ったか。ラジオボタンで入力する。
  - `1`：チャンピオンの勝ち
  - `-1`：チャレンジャーの勝ち
  - `0`：引き分け・特殊処理
- 送信ボタンを押すとAPIを経由してDBに登録され、バックエンドでレート表示と並び順を更新する。

## バックエンド処理

### 基本方針

- Laravel 側に新規コントローラーを作成する。仮名は `NewArenaController` とする。
- 旧 `ArenaController`、旧 `arenas` テーブル、旧 `old-arena.js` 用APIは使わない。
- API パスは仮置きで `/api/new-arena/*` とする。
- DB更新は transaction で行う。
- 最新状態は参加者状態テーブル、またはイベント内の最新対戦番号を使ったクエリで取得する。

### 対戦結果送信時

- 受け取った情報をユーザーごとに処理する。
- ユーザーのポジションは並び順に等しく、`position=1` は暫定チャンピオン、`position=2` はチャレンジャー、`position>=3` は観戦者とする。
- 対戦者のスコアは、入力された `score_1p`、`score_2p` のうち自分の記録を保存する。
- 観戦者のスコアは `-1` とする。
- `score` カラムは数値以外も保存できる `varchar` とし、空文字も許容する。
- 通常結果では、各プレイヤーの最新レートを取得し、結果に基づいて結果レートを算出する。
- `result=0` の場合、レート計算は行わず、全員の結果レートは対戦前レートと同じにする。
- 1対戦につき、参加者全員分の結果行を一括挿入する。
- 結果行の挿入後、参加者状態テーブルの現在レート、並び順、参加状態を更新する。

## DB設計案

テーブル名は仮置き。旧 `arenas` との混同を避けるため、正式実装時も `arenas` は使用しない。

### `arena_events`

- `id`: キーとなる連番
- `event_id`: イベント日（yyyymmdd）。イベント識別子を兼ねる。
- `title`: イベント名
- `match_limit`: 基本20
- `status`: `active`, `closed` など
- `created_at`, `updated_at`

### `arena_players`

現在の参加者状態を保持する。最新表示は主にこのテーブルを参照する。

- `id`: キーとなる連番
- `event_id`: `arena_events.id`
- `user_id`: ユーザーID
- `position`: 現在の並び順
- `start_point`: 今回イベント参加時点の開始レート
- `current_point`: 現在レート
- `active`: 現在参加中かどうか
- `joined_at`, `left_at`
- `created_at`, `updated_at`

推奨制約：

- `unique(event_id, user_id)` を設定し、同一イベント内の重複参加状態を防ぐ。
- 途中退出後の再参加を1行で扱うか複数行で扱うかは仮置き。まずは1行で `active` と `position` を更新する。

### `arena_matches`

対戦単位の情報を保持する。

- `id`: キーとなる連番
- `event_id`: `arena_events.id`
- `match_no`: イベント内の対戦番号
- `stage_id`: ステージID
- `holder_user_id`: 対戦時点の暫定チャンピオン
- `challenger_user_id`: 対戦時点のチャレンジャー
- `receiver_user_ids`: 対戦時点の観戦者。仮置きでJSON文字列
- `result`: `1`, `-1`, `0`
- `holder_streak_before`: 対戦前のチャンピオン連勝数
- `created_at`, `updated_at`

推奨制約：

- `unique(event_id, match_no)` を設定する。
- 最新対戦番号は `max(match_no)` で取得する。

### `arena_results`

対戦ごとのプレイヤー結果を保持する。

- `id`: キーとなる連番
- `event_id`: `arena_events.id`
- `match_id`: `arena_matches.id`
- `match_no`: イベント内の対戦番号
- `stage_id`: ステージID
- `user_id`: ユーザーID
- `position`: 対戦時点の並び順
- `score`: スコア文字列。`varchar`、空文字許容
- `point`: 対戦前レート
- `point_result`: 対戦後レート
- `payment`: 対戦者参加費または観戦料
- `gain`: ポットから得たポイント。観戦者は0
- `result`: 対戦者は `1`, `-1`, `0`。観戦者は仮置きで `0`
- `flg`: 削除フラグ
- `created_at`, `updated_at`

推奨インデックス：

- `(event_id, user_id, match_no)`
- `(event_id, match_no)`
- `(user_id, created_at)`

## 最新情報取得クエリ方針

- 現在の表示状態は `arena_players` を `event_id` と `active=1` で取得し、`position` 昇順で並べる。
- 現在レートは `arena_players.current_point` を正とする。
- 最新対戦番号は `arena_matches` の `max(match_no)` で取得する。
- 対戦履歴は `arena_matches` と `arena_results` を `match_no desc` で取得する。
- 今回イベントを除いた最後のレートは、対象ユーザーの `arena_results` を現在 `event_id` 以外で `created_at desc, id desc` に並べ、最初の `point_result` を取得する。
- 過去レートが存在しない場合は1000点とする。

SQLイメージ：

```sql
select *
from arena_players
where event_id = :event_id
  and active = 1
order by position asc;
```

```sql
select point_result
from arena_results
where user_id = :user_id
  and event_id <> :event_id
  and flg = 0
order by created_at desc, id desc
limit 1;
```

```sql
select max(match_no) as latest_match_no
from arena_matches
where event_id = :event_id;
```
